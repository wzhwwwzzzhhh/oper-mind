# 10 项目迭代待办清单

对比行业参考项目（智能 OnCall Agent），梳理当前项目缺失或薄弱的部分，作为后续迭代的 roadmap。

---

## 一、检索增强（RAG + 向量数据库）

**当前状态：** 长期记忆用 JSON 文件 + 关键词匹配，属于最原始的实现。

**需要补齐的：**

- [ ] 引入向量数据库（推荐 Chroma，轻量、无需独立部署、跟项目一个进程）
- [ ] 引入 Embedding 模型（可用 sentence-transformers 或在线 API）
- [ ] 文档分片策略（固定长度分片 / 按段落分片 / 重叠分片）
- [ ] 向量存储 + 检索流程（文本 → embedding → 存向量库 → 检索 → 重排序）
- [ ] 检索结果注入 LLM 上下文（现在 format_context 已做，但向量化了效果会好很多）

**价值：** 面试必问 RAG。当前关键词匹配面试官一眼看穿，向量检索才是工业级方案。

---

## 二、多 Agent 架构

**当前状态：** 单 Agent，既管对话又管诊断又管知识检索。

**需要补齐的：**

- [ ] 拆分为多个职责单一的 Agent
  - 对话 Agent：处理用户交互、上下文管理
  - 诊断 Agent：DB 诊断逻辑（当前的主要功能）
  - 知识库 Agent：检索知识文档辅助回答
- [ ] Router Agent：根据用户意图将请求分发到对应 Agent
- [ ] Agent 间通信机制（Agent A 调用 Agent B 的结果）

**价值：** 展示系统设计能力。"单 Agent 职责过重，复杂场景需要分工协作"是标准答案。

---

## 三、Plan-Execute-Replan Agent 模式

**当前状态：** 只有 ReAct 模式（思考 → 行动 → 观察 → 重复）。

**需要补齐的：**

- [ ] Plan 节点：LLM 先生成执行计划（多步骤）
- [ ] Execute 节点：按计划逐步执行
- [ ] Replan 节点：执行过程中根据中间结果动态调整计划
- [ ] 与现有 ReAct 模式共存：简单场景走 ReAct，复杂场景走 Plan-Execute

**价值：** ReAct 是基础，Plan-Execute 是进阶。面试中主动提两种模式的适用场景是加分项。

---

## 四、SSE 流式输出

**当前状态：** Agent 完整跑完才返回结果，用户需要等待。

**需要补齐的：**

- [ ] FastAPI 的 StreamingResponse 包装
- [ ] Agent run 方法改为 generator，逐步 yield 中间结果
- [ ] 前端逐字展示 LLM 输出

**价值：** 用户体验差异。没有流式输出的 API 在工程上是不完整的。

---

## 五、前端界面

**当前状态：** 只有 CLI 和 curl。

**需要补齐的：**

- [ ] 最简单的聊天 UI（HTML + JS，单个文件也不嫌少）
- [ ] 对话输入框 + 消息展示区
- [ ] 流式输出展示（配合 SSE）
- [ ] （可选）Markdown 渲染 / SQL 高亮

**价值：** 面试 demo 时展示 CLI 远不如展示一个能交互的页面。用 AI 写前端代码量很小。

---

## 六、MCP（Model Context Protocol）

**当前状态：** 未涉及。

**需要补齐的：**

- [ ] 理解 MCP 是什么（工具、资源、提示词的标准协议）
- [ ] 将现有的 Tool 系统适配到 MCP 协议
- [ ] 或简单理解概念，面试时能说清楚

**价值：** 2025-2026 年新兴标准，部分面试已经开始问。投资回报比不高，了解概念即可。

---

## 七、工程化完善

**当前状态：** 项目能跑，但离生产还有差距。

**需要补齐的：**

- [ ] Docker / Docker Compose 一键部署
- [ ] GitHub Actions CI（跑测试 + lint）
- [ ] .env / config 的环境隔离完善
- [ ] 日志系统（logging 替换 print）
- [ ] 错误处理（LLM 超时重试、幂等性）

**价值：** 简历上写"该项目已容器化部署，CI 通过率 100%"是硬指标。

---

## 优先级建议

```
第一梯队（面试高频，投入产出比最高）
  ├── RAG + 向量数据库（Chroma）
  └── 多 Agent 架构

第二梯队（加分项，体现深度）
  ├── Plan-Execute-Replan
  ├── SSE 流式输出
  └── Docker 部署

第三梯队（锦上添花）
  ├── 前端界面
  ├── CI/CD
  ├── MCP 概念
  └── 日志系统
```
