# OperMind 前端开发路线图 — 阶段一 M7 / report 历史基线

> 创建日期：2026-07-18　|　历史基线标记：2026-07-25
>
> 本文件记录阶段一 M7 的研发、实验和 Trace 可观察性前端路线与交付，**不再是主产品开发入口**。当前产品进度见 `docs/开发/_A-Plan-总览.md`，阶段二前端计划见 `docs/开发/_B-V1产品化开发计划.md`。

## 1. 当前职责边界

项目保留两个前端，服务不同用户与任务：

| 目录 | 用户与目标 | 默认体验 |
|---|---|---|
| `frontend/` | 运维工程师、SRE、系统管理员的 V1 主产品 | 结果优先：根因、证据、影响、置信度、建议、风险与审批；完整过程按需展开 |
| `report/` | 研发、调试、实验、答辩 | Trace、Replay、路由、Agent 协作、Debate、Reflection、实验指标 |

主产品不把完整 Trace 作为视觉中心。需要查看完整编排过程、回放或实验指标时，主产品提供跳转 `report/` 的高级分析入口。`report/` 不是 `frontend/` 的替代品，也不得删除。

## 2. M7 已完成范围

M7 已在 `report/` 固化以下历史可观察性能力：

1. 工程地基、健康检查与后端代理。
2. 同步诊断闭环、错误态和报告展示。
3. direct / chain / parallel 的 Trace 回放与拓扑表达。
4. SSE 实时增量、同步降级和过程状态更新。
5. M5 对比实验的 ECharts 指标看板。

这些能力继续用于研发验收、实验解释和演示支撑。历史实现、日志与验收记录保留在 `docs/开发/M7-前端可视化/`，不应被重写为阶段二的产品任务。

## 3. 已知接口历史基线

阶段一后端当前提供 `GET /health`、`POST /diagnose`、`GET /diagnose/stream` 等接口，契约位于 `backend/src/api/`。它们是 M7/report 的可观察性接口基线，不等同于阶段二产品 API。

阶段二将定义 `/api/v1` 的会话、运行、事件和结构化 `DiagnosisResult` 契约。`frontend/` 必须消费该产品契约，不能长期依赖 Markdown 解析或仅以 M7 的临时诊断接口构建产品流程。

## 4. 维护规则

- `report/` 的修复只限研发/实验/Trace 可观察性职责，不借机扩张为主产品工作台。
- 主产品前端初始化、信息架构、结果优先交互和与 `report/` 的跳转关系，按 P0–P7 执行。
- API/SSE 变更时，同步更新 `AGENTS.md`、`CLAUDE.md`、`docs/开发规范.md` 和对应阶段日志。
- 旧 M7.5 与 M8 的“下一步”描述已由 P6/P7 吸收；不得据此文件将其重新列为当前主线。
