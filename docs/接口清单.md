### 已知缺陷（不是缺接口，是契约本身的问题）

- **`POST /approval` 没有审批人身份。** 当前无登录体系（`产品定义.md` §7），谁都能批，「人工审批」在安全叙事上是空的。这不是补一个字段能解决的，前置是身份模型。
- **可被审批执行的动作只有 1 个**：受控靶场固定联合索引重建（`approval/P5-controlled-action-real.md`）。接口是通用的，白名单是单条。

### 注册能力开工前必须先定的三件事

服务注册涉及新增公开 API + 凭据处理，按 `CLAUDE.md` 必须 PRD → Design → 用户确认。方案收敛前需要用户答：

1. **DSN 存哪。** 现在不落库。加 UI 注册就必须落库，否则刷新即失。可照搬模型 Provider 的成熟方案（AES-256-GCM 加密落库、主密钥走环境变量、接口只回 `has_api_key` + 掩码尾号，见 `model/P6-model-provider-key-management.md`）；或保持环境变量、UI 只声明服务 ID，凭据仍由运维注入。
2. **注册时是否立刻探连接。** 失败是拒绝创建，还是允许存为「未验证」态？后者更实用，但页面得多一个诚实的未验证状态。
3. **允许注册哪些类型。** PostgreSQL / Redis 有真 Connector；MySQL 没有。按 §5.6，未启用能力可以出现在下拉里但必须如实标注。
