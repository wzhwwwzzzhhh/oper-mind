> 状态：**已与用户确认的北极星。** 每阶段进入前仍须完成半页小设计 → Review → 用户确认。
> 更新：2026-08-09（路径段按 P0–P7 实际交付结果标注状态；待决点按已确认决策收敛）
> 配套事实源：`产品定义.md`、`路线图.md`、`开发规范.md`。本文取代 `归档/正式产品架构设计-v1.md` 草案。

## 一个视角：这是一台"受控事实机器"

OperMind 的心不是聊天、也不是多 Agent，而是底下这台机器：把"人的运维问题"变成**有出处、脱敏、被治理的事实**，并在拿到许可后变成**被治理的动作**。聊天和多 Agent 是它友好的脸，**工具网关是它的良心**。

判定跑偏的唯一标准：**凡不是"往这台机器上插的一个插件"的东西，都是跑题。**

## 一条主脊（产品宪法）

```
消息 → Run → 大脑(协调→领域Agent→质检→Report) → 工具网关 → Connector → 证据 → 结果 → Trace →(高风险)提案→审批→执行→验证 → 留痕
```

继承 Java 参考项目的**产品模块形状**（会话 / 服务连接 / 监控 / 自愈审批 / 模型设置 / 知识库），但全部挂在这一条脊上——不为每种服务复制一套 Controller/Dashboard。

## 两条硬规则（结构性防漂移）

1. **一条主脊，能力即插件**：新能力 = 新 Tool + Connector 绑定 + 注册。禁止新端点、新流程、新"模式"、新独立脚本/页面。
2. **每阶段必须在前端摸得到**：能打开浏览器亲手做一件新事、看到真实结果，才算完成。后端做一堆而前端零变化 = 未完成。

## 不可妥协的边界

- **工具网关是必须最先做对的接缝**：模型/Agent 永不直接碰 DB/Shell/网络；网关校验权限+schema+限时+脱敏，Agent 只拿到"允许的工具菜单"。MCP 将来只是网关下受同样策略约束的适配器。
- **智能与权力分离**：读只读顺网关流动；动作绝不由 LLM 执行，LLM 只能从白名单模板**提议**，由确定性策略引擎 + 人工审批 + 白名单执行 + 独立验证完成。
- **能力即诚实锁**：服务按"真正接通的能力"渲染，未接通显示"未启用"，且 Agent 那里根本没有对应工具。
- **大脑薄且对基础设施无知**：Agent 只收 AgentTask（目标 + 允许工具 + 绑定服务 + 已有证据），回 findings + 证据引用 + 安全摘要；Debate/Reflection 仅在跨域证据冲突时触发。
- **凭据永不落库/日志/Trace**；**Trace 只是 Run 事件的安全只读投影**，不含 CoT/Prompt/原始数据。

## 开发节奏

每阶段：半页小设计 → 用户确认 → 实现 → 用户在浏览器验证 → Test/Review → 单独提交（可回滚）。短循环，用户在环里。

## 大致路径（P0–P7 已交付，当前在完善阶段）

- **P0 · 清理** ✅ 评测语义 + demo 靶场清除。
- **P1 · 大脑上线，前端能聊** ✅ 会话→Run→内核唯一执行链；每 Run 状态隔离；接真 LLM；根路由落工作台。
- **P2 · 工具网关 + 第一个真事实（基石）** ✅ 网关（权限/schema/限时/脱敏）+ Connector 接口 + 只读真工具；慢查询降级为"第一个工具"。
- **P3 · 前端重构 + 服务中心变真** ✅ 窄图标导航/双模式壳、服务中心与详情页、自绘 CSS 替代 antd；ManagedService + 能力驱动渲染。
- **P4 · 当前监控快照 + 多服务实例** ✅ ServiceSnapshot + 经网关的只读健康/指标工具；多服务实例接入与服务上下文贯通。
- **P5 · 受控动作闭环变真** ✅ 审批骨架接第一个真动作模板（固定联合索引重建）+ 监控历史趋势。
- **P6 · 沿主脊横向长** ✅ Redis 接入、日志真实源、主机指标、知识检索、模型 Provider/Key 管理、跨服务联合调查。
- **P7 · 页面与诊断深化** ✅ 文档知识库页、服务监控概览页、DB 锁与连接池只读诊断。
- **当前 · 体验驱动完善**：不新增能力，只修跑不通的链路和误导用户的占位。

## 已由 P0–P7 确认的原待决点

| 原待决点 | 已确认结论 |
|---|---|
| 凭据存储方案 | 服务 DSN 走环境变量不落库；模型 API Key 走 AES-256-GCM 加密落库，主密钥在环境变量。 |
| 一个 Run 是否跨多服务 | **不跨**。会话承载多服务，每服务一个 Run，前端按服务分组聚合（P6 跨服务联合调查）。 |

## 仍待单独设计、不擅自决定

- MCP 接入时机与产品边界；
- 除固定联合索引重建外，每种高风险动作的白名单/审批/验证规则；
- 高危 SQL 审批是否接入 ToolGateway 执行链（当前 `core/approval.py` 的 CLI 审批路径不可达，见 `完善清单.md` P0-5）；
- 长期记忆的存储与检索方案（当前 v1 链路默认关闭）；
- 身份、租户、角色与审批人模型（当前无登录体系）。
