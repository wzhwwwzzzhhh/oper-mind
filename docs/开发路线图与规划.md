## 一、项目定位

基于多智能体协作的**运维故障诊断系统**（毕业设计）。核心研究贡献是**多 Agent 协作机制**——相较已有的单模型 Java/Spring AI 版本，论证协作带来的价值。

技术栈：Python 3.10+ · LangGraph · OpenAI SDK · FastAPI · React + TypeScript（未建）。

## 二、当前状态（已验证）

### 四层架构（mock 模式下基本闭环）

- **编排层**（`core/graph.py` + `coordinator.py`）：`CoordinatorAgent.route()` 驱动编译好的 LangGraph：
  ```
  START → route(LLM 决定 strategy+target)
        → direct（单 Agent） | chain（Server→DB→Log 串行，每层带上游线索） | parallel（ThreadPoolExecutor 并发）
        → conflict_check →(冲突)→ debate → report → reflection →(有反馈, 最多 2 轮)→ report → END
  ```
  debate/冲突检测**只在 parallel 路径**触发；direct/chain 直接进 report。全程 `trace` 供前端可视化。
- **领域 Agent 层**（`agents/`）：ServerAgent / DBAgent / LogAgent 继承 `BaseAgent`（手写 ReAct 循环）。ReportAgent 非真 agent——纯字符串模板。
- **工具 + 记忆层**：工具返回**纯文本字符串**。Server 工具真实 psutil（mock fallback）；DB/Log 工具全 mock。短期记忆=内存对话窗口（近 5 轮）；长期记忆=`data/memory.json`，关键词加权检索（向量检索的 MVP 占位）。
- **质量层**：Debate=单次 LLM 裁决（`evidence` 参数未用，无多轮）；Reflection=通用 reviewer prompt（非领域化），靠字符串匹配「通过」判定。

### 已知短板 / stub 清单

| 模块 | 问题 |
|---|---|
| `debate.py` | 单 judge，`evidence` 参数未用，无多轮论证/投票（「简化实现」） |
| `reflection.py` | reviewer 对象未真正使用，所有评审同一通用 prompt；pass/fail 靠 `"通过" in text` |
| `approval.py` | `request_approval` 用阻塞 `input()`（FastAPI/并行会挂死）；prod webhook 是 TODO；`ApprovalRequired` 异常定义了但从未使用 |
| DBAgent | 用 mock EXPLAIN，无真实 MySQL 连接 |
| `llm.py` | 死代码 `_mock_response`；无重试/流式；硬编码 model `qwen2.5:7b`、timeout=60 |
| `tool_registry` | 安全门 SQL 硬编码；非 SQL 高危操作全走 `kill_query` 分支 |
| API | `/memory/stats`、`/memory/clear` 是 stub |
| 工程 | `build_system()` 在 app.py 与 main.py **逐字重复** |
| 依赖 | `requirements.txt` 缺 pyyaml、fpdf |
| **安全** | `config/config.local.yaml` 提交了**真实 DeepSeek key**，已在 git 历史；.gitignore 虽列了它但因先前已提交仍被跟踪 |
| 前端 | `src/frontend/` **空目录**，完全未建 |

### 关键路径 = 实验基础设施（最长的杆，最先启动，三项可并行）

- **M1 评测数据集**：7 条 → **80–100 条**，重点补**跨领域复合故障**（`requires_collaboration`）+ 高危操作类；schema 增 `symptom / domain / root_cause / gold_route / risk_level`；双人标注报 **Cohen's κ**；留 20% held-out。→ `data/eval_dataset.json`
- **M2 评测 Harness**：`scripts/run_eval.py` 配置矩阵驱动，逐条跑全链路捕获 trace + 指标（准确率 / 工具正确率 / 延迟 / token / 修订数 / 共识质量）；`src/eval/metrics.py` 含 **LLM-as-judge** 口径。此处嵌入**轻量结构化输出**改造（仅供采集，非全链路重写）。
- **M3 复现性**：固定种子；主实验跑 **mock 模式**（确定性）；`src/eval/stats.py`（均值/标准差/95%CI/Wilcoxon/Friedman）；锁依赖版本；温度设 0。

### 演示轨（与实验轨并行，互不阻塞）

- **M2' API 补全**：`GET /diagnose/stream`（**SSE**，trace 事件逐条推送让诊断链动起来，最高杠杆）；`GET /scenarios`；真实 `GET /health`（mock/live 徽章）；完善 `/memory/stats`。
- **M3' 前端脚手架**：空目录 → Vite + React-TS + AntD5 + ECharts + Zustand + TanStack Query；vite proxy 到 uvicorn；调通 `/health`。
- **M4' 前端 MVP**：查询/场景选择 → **诊断链可视化**（direct/chain/parallel 视觉差异是核心看点）→ 思考面板 → 报告渲染，消费 SSE 实时点亮。

### 🟣 核心实验（机制已实现，主要是「跑批 + 出图」）

- **M4 实验 A（不可省）**：建**同模型同工具的 Python 单 Agent 基线** vs 多 Agent。⚠️ 别直接跨语言比 Java 版（混淆变量，评委必问）。重点看复合故障子集差距 + case study 对照。
- **M4 实验 B（全消融）**：路由策略对比 + reflection 消融 + debate 消融 + 记忆消融。加 LLM-as-judge + 人工抽检校准。

### 🟠 M6 — 机制增强（冲高分主战场，一等公民）

- 领域化 reflection（结构化 pass/fail，弃字符串匹配）

### ⚫ M5 — 打磨 + 答辩就绪

## 六、三条务必守住的答辩红线

1. **样本量与统计**：7 条不够，先扩数据集；任何结论带 n、标准差、显著性检验。
2. **基线公平性**：主对比用同模型同工具的 Python 单 Agent，而非跨语言比 Java 版。
3. **准确率评判口径**：LLM-as-judge 用独立模型 + 固定 prompt + 人工抽检校准，论文中交代。
