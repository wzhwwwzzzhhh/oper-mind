# 开发文档索引与执行入口

> 更新时间：2026-07-29　|　维护状态：生效
> **总进度与当前唯一下一步：`_A-Plan-总览.md`。** 本索引不复制进度状态，只解决“该读哪份文档、旧文档能否执行”的问题。

## 1. 当前恢复顺序

1. `git status --short` 与最近提交；
2. `_A-Plan-总览.md`：确认唯一下一步和实施授权边界；
3. 本文件：识别当前文档层级；
4. `治理-个人AI运维助手产品重定位/README.md` 与该目录 `HANDOFF.md`：理解当前 P3 产品体验设计和当前交接；
5. 当前实现需要继承的契约或技术事实，再读取 P0 API 契约、P2/P3 对应日志、测试和源码。

当交接记录、计划、提交或工作区不一致时，停止猜测：先以 A-Plan、最新提交和未提交 diff 复核，再修正文档。

## 5. 维护规则

- 只允许 A-Plan 使用“当前唯一下一步”作为项目级命令；B-Plan、设计日志和历史 review 只能记录其当时状态或显式指向 A-Plan。
- 新增活文档前先判断归属：产品体验/跨阶段决策放 `治理-*`，P 阶段实现放 `P*-*`，规则改动放 `开发规范.md`，进度改动放 A-Plan。
- 每份完成的 `HANDOFF.md` 都必须回填最终状态、注明关闭日期和新的恢复入口；不可把“待提交”“待用户审阅”等旧阻塞留作当前指令。
- 文档目录、权威边界或产品流程变更时，同步本索引、顶层 `docs/README.md`、`AGENTS.md`、`CLAUDE.md` 与 `docs/开发规范.md`。
