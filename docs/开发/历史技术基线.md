# 历史技术基线（保留事实，不保留旧路线）

> 更新：2026-07-30。本文替代已删除的 M0–M8、P0–P3、旧治理目录和教程式开发日志，避免历史路线干扰当前产品判断；删除记录仍可在 Git 历史中追溯。

## 必须继承的代码事实

1. **API 与持久化**：`backend/src/api/v1/`、`backend/src/application/`、`backend/src/domain/`、`backend/src/infrastructure/persistence/` 已形成 Session、Message、Run、RunEvent、Result 的基础闭环；现行 API 契约以 FastAPI 路由、Pydantic schema 与测试为准。
2. **流式与前端**：`frontend/src/features/workbench/` 已有会话、Run 状态、SSE 和结构化 Result 的读取/展示基础。它是新会话式工作台的可复用底座，不代表旧产品文案仍有效。
3. **Agent 技术资产**：`backend/src/agents/`、`backend/src/core/`、`backend/src/tools/`、`backend/src/memory/` 保留 ReAct、LangGraph、Debate、Reflection、Trace 与记忆实验能力。真实靶场不能直接把开放式模型 Tool 调用作为安全边界。
4. **评测与演示资产**：`report/`、`experiments/`、`data/` 与相关脚本保留，用于毕业设计、回归和研发验证；它们不是主产品前端，也不定义当前路线。
5. **P4 靶场**：`demo/orders-slow-query/` 和 `backend/scripts/demo_orders_env.py` 已真实验证 PostgreSQL 订单慢查询场景。操作只限授权的 `opermind_demo` 靶场；详情见当前 P4 文档。

## 不再继承的路线

- 已删除的旧会话体验、发送恢复与实验优先级路线不再作为产品目标；其中已落地代码可按当前工作包择优复用。
- M0–M8 的评测优先级、P0–P3 的阶段顺序、旧前端体验文案，以及教程式步骤编号，不再定义需求或“下一步”。
- 旧文档已从工作树删除，**不是**要求删除相应代码、测试、迁移或 Git 历史。

## 使用方式

开发当前能力时，先读 `_A-Plan-总览.md`、当前产品蓝图和对应 P4 工作包。需要确认历史实现时，优先读代码和测试；只有确有追溯必要时再查 Git 历史，而不是恢复旧文档作为活跃规范。
