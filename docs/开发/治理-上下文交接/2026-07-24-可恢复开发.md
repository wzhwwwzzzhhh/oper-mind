# 上下文交接与恢复开发规则

> 日期：2026-07-24　|　状态：✅ 已生效　|　关联：M7.2 Trace 回放收口

## Design

长任务的真实进度不能只依赖对话上下文：上下文中断会使“已完成、待修复、禁止提交项和验证边界”丢失或模糊。目标是在不增加无效日志的前提下，让任意后续工作上下文可从仓库确定恢复。

## Step

1. 保持一个 step 可在一次上下文内完成；预计超出时继续拆分并独立提交。
2. 在跨上下文、改动已涉及 3–5 文件、出现 P1/P2、长联调或上下文接近上限前，更新当前 step 的 `HANDOFF.md`。
3. 恢复时固定核对 Git 状态、最近提交、A-Plan、交接记录、设计文档和未提交 diff。
4. 交接记录与工作区不一致时先核对，禁止猜测、跳过验证或直接提交；step 完成后回填或移除交接文件。

## Code

- `docs/开发规范.md`：新增“上下文交接与恢复”规则和提交前检查项。
- `AGENTS.md`、`CLAUDE.md`：同步精简硬约束，确保不同协作入口的行为一致。
- `docs/开发/M7-前端可视化/HANDOFF.md`：作为本次 M7.2 的首个恢复交接点，记录基线、审查问题、验证和提交边界。

## Test

- `git diff --check` 在提交前复验。
