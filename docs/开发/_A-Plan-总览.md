## 1. 产品方向

OperMind 从“多 Agent 运维诊断 Demo”演进为面向**个人用户日常轻量使用**的独立 AI 运维助手。它以长期、多轮的个人会话作为用户主线；用户可主动提问，后续也可从真实监控发现或已接入告警进入同一会话上下文。

产品主流程：

```text
主动提问 / 真实监控发现 / 已接入告警
→ 创建或进入个人长期会话
→ AI 解释当前判断，按需发起 Agent 调查
→ 会话内呈现结论、证据、影响、不确定性与安全建议
→ 用户持续追问；未来经明确授权后才可处理并验证
```

两个前端职责明确分离：

- `frontend/`：V1 主产品前端，默认以个人会话和可理解的调查摘要为中心；Run、SSE、Agent 细节按需展开。
- `report/`：阶段一 M7 产物，面向研发、实验、答辩与调试，展示 Trace、Replay、Debate、Reflection 和实验指标。

产品体验的当前设计真相源为 `docs/开发/治理-个人AI运维助手产品重定位/`。`P0` 原型和 `P3-主前端工作台` 中的 Run/Result 工作台布局、旧导航与旧“唯一下一步”保留为历史及技术证据，**不得再直接作为新的产品体验需求来源**；已发布 `/api/v1` 契约与 P2/P3 测试事实仍必须继承。

## 5. 执行与降级原则

```text
P0/P1/P2/P3.4c 技术基线
→ R1 个人 AI 运维助手产品重定位
→ P3.5 会话主体验与 API 差距 Design
→ P3.6 会话优先最小切片（需单独授权）
→ P4 独立监控、环境、数据源与知识
→ P5 提醒/告警进入会话与受控处理
→ P6 个人产品收口
→ P7 测试、部署与生产加固
```

- 采用纵向切片：产品流程 → 数据模型 → API → Agent 接入 → 前端 → 最小验证 → Review → Commit。
- Agent Core 不推倒重来。产品会话、持久化、事务、权限和审计放在 Application Service / Repository 边界，Agent 节点专注诊断推理。
- 产品 API 向 `/api/v1` 统一演进；`backend/src/api/` 是当前 HTTP/SSE 契约边界。
- 真实数据库、数据源与前后端联调必须先共同确认目标、权限、数据、契约、回退和验收场景；`api_key="mock"` 与确定性 mock fallback 始终可用。
- 历史路线图 `docs/开发路线图与规划.md`、历史开发日志和 `docs/初始开发/` 不删除；它们不定义当前下一步。
