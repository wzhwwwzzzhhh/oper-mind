# P4.1 Review — 会话触发的订单慢查询只读调查

> 日期：2026-07-30　|　结论：**通过；mock/API/UI 回归和 target 真实 smoke 均已完成**

## 已审查结论

- [x] P4.1 是会话式产品的第一条可见切片，而不是脱离 UI 的 Agent 实验；复用 Session/Run/Result/SSE 与 Workbench，不另造产品壳。
- [x] 只支持一个慢查询问题；不支持的提问必须明示范围，不能把普通问答伪装成真实调查。
- [x] DB/Log/Server 角色由确定性只读 Collector 实现；未复用旧的开放 SQL Tool 或将模型参数作为真实数据库访问边界。
- [x] `target` 仅允许固定靶场，应用元数据和诊断库隔离；不可用时 fail-closed，不会探测 `gongkar` 或其他资源。
- [x] 只读接口不调用 `diagnostic-probe`，避免调查本身写日志或改变性能窗口。
- [x] 结果根因依赖 DB 的直接事实和 Log/Server 的交叉支持；部分失败保留不确定性，全部失败不伪造成功。
- [x] UI 只显示角色状态、摘要与可引用证据，不显示 CoT、Prompt、原始 SQL/日志/HTTP body、路径、异常详情或凭证。
- [x] `recommendations=[]`、`requires_approval=false`；审批、执行、Verify 仍归 P4.2。
- [x] P4.1 不引入文件上传、RAG、模型 Key、Redis/MySQL 或公开 API/迁移变更。

## 必守停止条件

若实现发现 P2 Result/API 无法承载所需证据、需要新增表/endpoint，或需要让模型产生真实查询参数，必须停止 P4.1，另行完成 Design → Review → 用户授权；不得以实现便利性绕过该审查门。

**Review 决定：**在用户明确同意产品蓝图与 P4.1 实施后，可以按此设计开始代码工作。
