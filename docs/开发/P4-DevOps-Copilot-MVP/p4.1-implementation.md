# P4.1 实施记录 — 订单慢查询只读证据调查

>

## 本工作包交付

- 新增 `domain/evidence.py`：`EvidenceFact`、`RootCauseFact`、`RiskFact`、`AgentInvestigationSummary`、`EvidenceInvestigationResult` 均为严格 Pydantic 数据边界。
- 新增 `infrastructure/diagnosis/demo_orders/`：固定 target settings、PostgreSQL `pg_indexes`/参数化 `EXPLAIN (FORMAT JSON)` reader、固定 JSONL 聚合 reader、固定 `/health` 与 `/internal/diagnostic/metrics` reader、并行 Collector、确定性 executor 与 ResultAssembler。
- 新增 `OPERMIND_DEMO_ORDERS_EVIDENCE_MODE`：默认 `disabled` 保持旧装配；`mock` 使用确定性 fixture；`target` 只允许 `127.0.0.1:5433/opermind_demo`、固定 service URL 和固定日志文件，并拒绝应用元数据复用。
- P4.1 模式下只有明确“订单 + 慢查询/性能 + 查询/SQL”等意图会读取三类证据；其他输入返回“当前 MVP 只支持订单慢查询”的已保存范围说明，不再回退为旧 Agent 实验式回答。
- 复用 P2 `Session → Run → Result → Message → RunEvent/SSE`；没有新增 endpoint、迁移、表或公开 schema。
- 事件持久化改为最小安全字段白名单：仅节点、摘要、角色、状态、耗时与 mode；原始 SQL、计划 JSON、日志、HTTP body、绝对路径、异常详情和凭据均不进入事件或 Result。
- Workbench 增加可重放的最小过程视图及展开的角色摘要/风险/证据；UI 不显示 CoT、Prompt 或原始读取。
- 新增 `backend/scripts/smoke_p4_orders_evidence.py`，供具备当前 shell target 凭据时执行 `start → inject → API 调查 → repair → clean`。

## 固定结果边界

- 只有“目标索引不存在 + 固定订单查询 `Seq Scan` + 日志和服务均支持异常”才输出 `high / 0.95` 根因。
- DB 证据满足、交叉证据不足时，保留 `high / 0.70` 高风险线索和不确定性。
- DB 不满足或不可用时不得生成“缺失索引”根因；所有源不可用、target 配置非法时安全失败。
- `recommendations=[]`、`requires_approval=false` 固定；没有 DDL/DML、没有审批、没有执行、没有 Verify 产品动作。
