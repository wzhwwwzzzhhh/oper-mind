# P4.3 Implementation — 服务中心、有限快照与调查入口

> 实施完成：2026-07-31　|　状态：**完成并已验证（target smoke 因当前进程未提供靶场凭据而 fail-closed）**

> 设计与审查：`p4.3-服务中心监控调查入口-design.md` / `p4.3-服务中心监控调查入口-review.md`

## 1. 已实现的产品路径

P4.3 没有另造实验控制台，而是将既有的单问题诊断与修复闭环接入产品的服务入口：

```text
服务中心
→ 订单服务靶场的有限当前快照
→ 创建带 service_id 的会话
→ 用户点击既有“开始调查”
→ P4.1 只读证据与根因
→ P4.2 Proposal / 人工审批 / 固定执行 / Verify
→ 服务页读取安全活动摘要
```

唯一已注册服务是代码内不可编辑的 `order-service`（展示名“订单服务靶场”）。它只暴露固定“调查订单慢查询”入口；没有用户可写服务配置、连接串、凭据、第二服务、第二故障、服务级 SSE、后台监控任务或告警系统。

## 2. 关键实现与边界

- **静态注册与受控 Connector**：新增 `ServiceRegistry` 与唯一 `PostgresOrdersSlowQueryConnector`。`disabled` 不执行外部读取；`mock` 返回明确的确定性模拟；`target` 只复用 P4.1 已批准的 health、metrics、当前库确认、固定索引和固定计划读取。两类来源的失败只收敛为安全 unavailable/insufficient 状态，绝不回退 mock。
- **当前事实而非伪监控**：服务详情只展示一次请求的有限快照：可用性、P50/P95、窗口大小、慢查询/超时计数和数据库高层信号。它不读取日志、diagnostic probe、故障注入、P4.1 调查 executor 或 P4.2 action executor，也不执行 DDL/DML。
- **会话关联与兼容**：显式 Alembic migration `20260731_03_p4_service_center` 为 `sessions` 增加可空 `service_id`、只接受 `NULL` 或 `order-service` 的检查约束，以及 `(service_id, updated_at, id)` 索引。普通 `POST /sessions` 不接受 `service_id`；只有服务专属 endpoint 经静态注册表校验后写入固定值。
- **不自动调查**：`POST /api/v1/services/order-service/sessions` 仅写入一个 active Session。不会创建 Message、Run、Result、Proposal，也不会触发 target 读取。Workbench 跳转后显示服务标签和预填问题，仍需用户主动点击既有“开始调查”。
- **安全活动留痕**：服务活动只限定查询 `service_id=order-service` 的会话，按 Run 的稳定 cursor 排序，只返回 Session/Run 状态、诊断摘要、严重性/置信度、Proposal 状态与 Verify 状态；不返回证据、原始异常、SQL、日志、连接信息、action digest、内部 request ID 或凭据。
- **产品页面**：新增服务中心列表/详情路由。详情页仅在页面可见时每 15 秒刷新，支持手动刷新；活动列表可回到关联 Workbench 会话。没有将历史 Verify 伪装为当前服务健康。
