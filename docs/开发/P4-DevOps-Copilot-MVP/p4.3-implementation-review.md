# P4.3 Implementation Review — 服务中心、有限快照与调查入口

> 审查日期：2026-07-31　|　结论：**✅ 代码、迁移、API、UI、回归与真实 target smoke 均通过**
>
> 设计基线：`p4.3-服务中心监控调查入口-design.md`
>
> 实施记录：`p4.3-implementation.md`

## 1. 产品路径与范围

- [x] P4.3 将既有 P4.1/P4.2 接入“服务中心 → 有限快照 → 服务上下文会话 → 用户确认调查 → 审批执行 → Verify 留痕”的主产品路径；没有新增 Agent 实验台或第二套 Run 生命周期。
- [x] 服务注册表是代码内唯一 `order-service`；未知 ID 统一拒绝，普通 Session API、URL、查询参数和前端都不能伪造或动态创建服务关联。
- [x] 服务入口只创建 `service_id=order-service` 的 active Session；API 和前端回归均确认用户点击开始前没有 Message、Run、Result 或 Proposal。
- [x] 未扩大到第二服务、MySQL、Redis、Kubernetes、用户可写连接、用户凭据、MCP、知识库、文件上传或模型 Key。

## 2. 读取、数据和写入边界

- [x] Connector 只复用 P4.1 的固定 health/metrics 读取和固定 PostgreSQL 当前库、索引、计划只读读取；服务页不直接连接外部资源。
- [x] `disabled` 为零外部读取，`mock` 为显式确定性模拟，`target` 失败为安全 unavailable/insufficient，不回退 mock；相关边界有独立测试。
- [x] 快照不调用日志 reader、diagnostic probe、故障注入、P4.1 investigation executor、P4.2 action executor，且不含 DDL/DML。
- [x] 迁移仅改变应用元数据的 `sessions`：可空 `service_id`、`NULL/order-service` 检查约束、服务活动查询索引；没有快照、时序、告警或服务配置表。
- [x] 目标边界仍只允许授权靶场；代码没有 `gongkar`、其他数据库、schema、端口或任意 SQL/Shell 的访问/回退路径。

## 3. 公开契约与信息暴露

- [x] 新增服务列表、详情、活动列表、服务专属 Session 创建 API；Pydantic/OpenAPI/TypeScript 客户端已同步生成并通过类型检查。
- [x] 公开快照只包含状态和有限指标；活动只包含安全语义摘要及 Run/Proposal/Verify 状态。
- [x] 公开资源、错误路径和页面不显示原始 SQL、日志、HTTP body、路径、内部 request ID、连接信息、action digest、凭据或模型 CoT。
- [x] 前端详情页只有可见时 15 秒轮询和手动刷新；没有服务级 SSE、WebSocket、后台巡检或把历史 Verify 伪装为实时健康。

P4.3 的代码实现符合 Design 中的产品入口、静态注册、有限只读快照、会话不自动调查、审计留痕与信息脱敏边界，并已完成真实 target smoke，可正式收口。
