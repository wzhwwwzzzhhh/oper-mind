# P4.3 HANDOFF — 已注册服务中心、有限监控与调查入口

> 更新：2026-07-30　|　状态：**Design/Review 已完成，等待用户实施授权**

## 当前产品基线

- P4.0、P4.1、P4.2 均已完成；现有产品已经可以在唯一受控订单慢查询靶场中完成会话调查、固定 Proposal、`local_operator` 审批、白名单执行、独立 Verify 与审计展示。
- P4.3 只补“服务中心 → 有限快照 → 带服务上下文的调查会话 → 既有闭环”的产品入口；不增加第二故障、第二服务或通用连接能力。
- 唯一已注册服务固定为 `order-service`（订单服务靶场）；静态注册表而非用户可写服务配置。
- 唯一真实 target 仍是专用 `opermind_demo` 靶场；绝不探测、读取、写入或清理 `gongkar`。

## 已完成的设计与审查

- Design：`p4.3-服务中心监控调查入口-design.md`
- Review：`p4.3-服务中心监控调查入口-review.md`
- 设计已明确：
  - `sessions.service_id` 是唯一新增会话关联字段，历史会话保持 `NULL`；不借用 `environment_id` / `incident_id`；
  - `GET /api/v1/services`、服务详情、活动列表和服务专属 Session 创建是拟定公开契约；尚未实现；
  - 监控只读取 P4.1 已批准的 health、metrics、固定 DB 索引/计划；不调用 probe、日志读取、故障注入、执行器或 DDL/DML；
  - 当前快照、历史 Verify、`disabled`、`mock`、`target unavailable` 各自有明确且不互相伪造的语义；
  - 服务入口仅创建并预填会话；用户点击既有“开始调查”前，不创建 Message/Run/Result/Proposal，也不发起 target 读取。

## 实施前禁止事项

在用户明确确认下列授权前，不得修改运行时代码、Alembic 迁移、`/api/v1` 契约、前端路由、真实连接或 smoke：

> 按 `p4.3-服务中心监控调查入口-design.md` 实施 P4.3。

不得借 P4.3 扩展 MySQL、Redis、Kubernetes、第二服务、用户服务配置/凭据、MCP、告警平台、时序监控、RAG/知识库、文件上传、模型 Key 或任何通用 SQL/Shell/action。
