# P4.0 Review — 受控靶场与单问题产品路线

> 日期：2026-07-30　|　结论：**通过；Work 1 已提交，P4.1 等待实施授权**

## 靶场与安全

- [x] 靶场有唯一数据库、schema、表、索引和本机服务目标，且正常/故障/修复/恢复/清理均可真实复现。
- [x] 连接与清理 fail-closed；没有访问 `gongkar` 或任意其他目标的路径。
- [x] Work 1 管理脚本与产品运行时职责分离；调查器不能借脚本获得写权限。
- [x] 性能、执行计划与慢日志共同构成事实，不把单一指标或“DDL 成功”伪装成修复成功。

## 产品路线

- [x] 已收敛为会话式 DevOps Copilot：一个慢查询问题先打通调查、证据、审批、执行、Verify 和服务留痕。
- [x] 多 Agent 对应 DB/Log/Server 的独立责任域；确定性 Collector 负责真实事实，LLM 不作为数据库安全边界。
- [x] 用户可见过程限定为状态、摘要、耗时、证据和不确定性，不泄露 CoT 或敏感原始内容。
- [x] Markdown 全文检索、服务 Connector、Provider、MCP 均有分期边界；未实现能力不能伪装可用。

## 结论与停止条件

P4.0 的靶场和产品边界满足 P4.1 的前提。P4.1 仅可实现会话触发的**只读**证据调查；若需要改公开 API、迁移或将模型参数传入真实读取，必须停止并新建 Design → Review → 用户授权。
