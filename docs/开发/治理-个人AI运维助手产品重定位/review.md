# R1 / P3.5 产品重定位 — 独立审查

> 日期：2026-07-29　|　结论：✅ 产品方向与 P3.5 Design 通过；❌ 未授权实现。

## 审查范围

- 个人长期多轮会话是否成为用户主线；
- P2 Session/Message/Run/Result/SSE 契约是否被准确继承；
- 旧 P3 Run 工作台假设是否被隔离，而不是删除技术基线；
- 监控、告警、处理、多人协作和 `report/` 边界是否诚实；
- 后续实现是否拆为可独立验证的最小切片。

## 核对结果

| 审查项 | 结论 |
|---|---|
| 目标用户 | 符合用户决策：个人、轻量、日常使用；当前排除多人协作与复杂 RBAC。 |
| 用户主对象 | 符合：Session/Conversation 与 Message 为主线，Run 是 Investigation 的内部执行记录。 |
| 首个可行场景 | 符合：使用现有 P2 `POST /sessions/{id}/runs` 表达“调查型多轮对话”，不虚称通用聊天。 |
| P2 契约继承 | 符合：保留 `input_message_id`、`run_id`、幂等键、cursor、UTC、错误资源、持久化 SSE 和 `Last-Event-ID`。 |
| 成功/失败/取消 | 符合：成功依赖已持久化 assistant Message + Result；失败/取消只显示调查卡，不伪造助手回复。 |
| 刷新与 SSE | 符合：Message 流先于视觉展示，所有未终态 Run 都需 events 回放和 SSE 恢复；终态后重读 Run/Message。 |
| 长期历史分页 | 已识别阻塞：现有正序 cursor 未定义“最近优先、向前加载”；P3.6 小范围验证可暂时完整读取，扩展前必须新开 API Design。 |
| 普通聊天语义 | 已识别阻塞：P2 只有调查型 Run 受理，不得靠前端伪造普通 assistant Message。 |
| 监控/告警/处理 | 符合：仅定义未来进入会话关系，不创建假资源、假数据或自动修复承诺。 |
| `report/` 边界 | 符合：完整 Trace 仍是研发/调试的受控跳转，非主产品页面。 |
| 旧计划隔离 | 符合：`README.md` 明确旧 P0/P3 体验文件不再驱动新 UI；API 与测试事实保留。 |
| 计划与规则镜像 | 已同步 A-Plan、B-Plan、`AGENTS.md`、`CLAUDE.md`、开发规范；AGENTS/CLAUDE 逐字一致需在最终核验中再次确认。 |
