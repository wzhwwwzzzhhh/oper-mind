# P3.5c Step3 — 后续最小切片、验收与非目标设计

> 日期：2026-07-29　|　状态：✅ Design 完成，未授权实现　|　依赖：`step1-个人会话主体验设计.md`、`step2-会话契约与恢复设计.md`

## 目标

将 P3.5 的体验和契约决策分解为可独立提交的后续工作，避免“会话优先”成为一次跨前端、Mock、后端、监控、告警和执行器的大改造。

## P3.6 的建议切片（仅 Design 结论）

### P3.6a — 会话壳与只读 Turn 投影

范围：只使用现有 P2 GET 契约，把 Session、Message、Run、Result 投影为个人会话；不发送、不订阅 SSE、不改 API。

验收：

- 会话列表与当前会话以 Message 流为视觉主线；
- 成功/失败/取消/运行中 Investigation 都挂在对应用户 Message 后；
- Result 被表现为助手答复的证据层；
- 读取错误、空会话、归档会话与协议异常均诚实表达；
- 无监控、告警、Action 或多人协作假数据；`report/` 保持受控入口。

### P3.6b — 调查型发送与幂等恢复

范围：接入既有 `POST /sessions/{id}/runs`、Idempotency-Key、Session Runs、events 和 SSE；不新增普通聊天 API。

验收：

- 同一发送动作只有一个稳定 key，网络未知结果用同 key 重试；
- `202` 后用 `input_message_id` 对账，不重复显示用户消息；
- queued/running/succeeded/failed/cancelled 与 HTTP/协议错误区分；
- 刷新后以 Message 为主线恢复，且恢复全部未终态 Run；
- SSE 使用 `Last-Event-ID` 和持久化 events 补偿，不把 sequence 暴露成主界面内容。

### P3.6c — 调查详情渐进披露与人工验收

范围：将 Result、安全事件摘要、agent_summary、关联 ID 和 `report/` 入口放入可展开调查详情；不创建真实监控/告警/执行。

验收：

- 默认答复按判断、影响/不确定性、证据、建议、继续追问排序；
- 只有用户主动展开才显示技术细节；
- `requires_approval` 仅显示“需要审批/当前不能执行”的诚实状态；
- 独立 Mock、类型检查、前端测试、构建、代理核验和人工浏览器验收通过；
- P3.4c 因 Windows 排除端口后置的浏览器验收可在独立 8100 Mock + 非排除端口环境合并补做，但不能改连 8000。

## 每个实现切片的固定验证

```text
Design Review
→ Mock 合同/前端类型
→ 单元或组件测试
→ 独立 Mock HTTP/SSE 核验
→ 前端构建
→ 人工主流程验收
→ 独立 Review
→ Commit
```

当实现涉及新的 API、数据库或 Agent/Action 行为时，必须拆出相应后端 Step；不得把它藏在 P3.6 前端提交中。

## Mock 策略

- 继续使用现有确定性 Mock 与独立 Mock FastAPI；Mock 只能代表已定义的 `/api/v1` 契约；
- “会话中有调查”可通过 P2 Message/Run/Result 夹具表达；
- 监控、Alert、自动处理、真实环境和多人协作没有契约时，不新增假夹具；
- 每个 Mock 状态必须区分：服务端业务失败、读取错误、协议错误、连接中断和终态恢复。

## 人工验收主脚本（未来实现后）

1. 打开会话列表，新建或选择已有会话；
2. 发送一个调查型问题，观察本地发送、受理、调查摘要和最终答复；
3. 刷新页面，确认用户消息、调查与答复不重复且可恢复；
4. 断开并恢复 SSE，确认先回放持久化事件再恢复连接；
5. 检查失败、取消、归档、空会话和读取错误不会伪造助手答复；
6. 展开调查详情，确认 Result 结构化字段、关联 ID 和 `report/` 边界正确；
7. 确认页面没有假监控大盘、假 Alert、假审批/执行或多人协作入口。

## 明确非目标

- 不把 P3.6 当作通用聊天、监控平台、告警中心或自动运维执行器；
- 不做共享会话、多人协作、成员邀请或 RBAC；
- 不绕过真实数据源/审批前置条件；
- 不修改旧 `/diagnose`、`/diagnose/stream`；
- 不把 `report/` 改造为主产品。

## Review

切片按只读投影 → 幂等/SSE 发送 → 渐进披露拆分，前端、Mock 与未来后端变更不会混在一个提交。只有用户单独授权 P3.6 实现后，才可按此顺序进入代码。
