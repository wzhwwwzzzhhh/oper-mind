# M7 Step5 — 联调与视觉收口

> 日期：2026-07-25　|　状态：🟡 开发中　|　分支：`feat/m7-frontend-visualization`
> 稳定基线：`db93ea5 docs: 修正M7.4提交状态`

## Design

M7.5 只做发布前收口：真实 mock 后端与 Vite 代理联调、1366×768 桌面视觉验收、核心交互回归、构建体积可读性与 M7 已知限制记录。不得重构既有路由、SSE 或图表功能；发现缺陷只修阻碍稳定演示的最小问题。

验收主路径：健康检查 → 发起实时诊断 → 接收真实 SSE trace / 最终报告 → 检查 direct / chain / parallel fixture 回放 → 检查 M5 图表来源和局限说明。SSE 不可用时应显示明确通知并走已有同步 fallback。展示仅使用 mock 模式，不暴露密钥或实验原始案例。

当前项目 `.venv` 的解释器路径失效（指向不存在的 Python 3.11）；M7.5 首先尝试使用工作区提供的 Python 执行后端，若依赖缺失则记录为环境阻塞，不以绕过或重写后端替代。

## Step

1. 检查并记录后端 Python 运行环境；启动 mock FastAPI 与 Vite 前端。
2. 浏览器在 1366×768 进行健康检查、SSE 诊断、同步降级、三路线回放和 M5 看板视觉验收。
3. 修复仅影响稳定演示的前端缺陷；评估 ECharts chunk 警告，选择最小可解释方案。
4. 运行前端全量测试 / typecheck / build；后端可运行时执行 API SSE 测试。
5. 生成可复核的截图 / 验收记录，回填 M7 Review、A-Plan 与已知限制；独立审查后提交。
