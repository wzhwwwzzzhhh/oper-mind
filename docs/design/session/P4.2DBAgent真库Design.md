# P4.2 会话 DBAgent 工具接真实 PostgreSQL · Design

> 状态：已确认
> 更新：2026-08-05
> 关联：P4（服务中心变真）完成；本阶段把会话里 DBAgent 的三个数据库诊断工具从 mock 接真库。

## 1. 目标与范围

P4 已让服务中心快照连真实 PostgreSQL（`postgres-production`）。但会话工作台里的 DBAgent 工具
（`explain_sql` / `show_index` / `show_create_table`）**仍写死走 `data/mock_db.py`**——
即使在真实模式（非 mock api_key）下，工具也返回 P2 订单演示的假 EXPLAIN/假索引，而不是查询真实库。

本阶段把 DBAgent 工具接到与 P4 相同的真实 PostgreSQL 只读数据源，实现「会话里的数据库诊断变真」。

### 范围（做什么）
- DBAgent 三个工具在**真实模式**下读真实 PostgreSQL：
  - `explain_sql` → 执行真实 `EXPLAIN` 得到执行计划
  - `show_index` → 从 `pg_indexes` / `pg_catalog` 读真实索引
  - `show_create_table` → 从 `pg_catalog` 拼真实建表语句
- **mock 模式完全保留**：`api_key == "mock"` 时仍走 `mock_db.py`，S1–S4 评测确定性不受影响。
- 复用 P4 一切已验证资产：DSN 来源、只读引擎构造、3 秒超时、三态失败分支。

### 不做什么（明确排除）
- 不接 MySQL / Redis（P4.2 只覆盖 PostgreSQL，其余后续按同模式复制）
- 不做写操作 / DDL / DML（纯只读）
- 不新增配置项（DSN 就是 P4 的 `OPERMIND_PG_DSN`，表名不做白名单映射）
- 不改 `data/mock_db.py`、不改 `data/scenarios.py`、不改 S1–S4 评测路径
- 不动前端（接口契约不变；Trace 展示不新增字段）
- 不做 EXPLAIN ANALYZE（真正执行 SQL，超范围；本阶段仅 `EXPLAIN` 计划，不执行）

## 2. 模式判定（双模式，对齐既有范式）

DBAgent 工具与 `server_tools.py` 一样采用 `get_active_scenario()` 判定模式：

```python
from data.scenarios import get_active_scenario

class ExplainTool(Tool):
    def execute(self, sql: str) -> str:
        active = get_active_scenario()
        if active is not None:
            return _explain_mock(sql)        # 现有 mock 逻辑，原样保留
        return self._explain_real(sql)       # 新增真实分支
```

- `get_active_scenario()` 非 None ⇒ mock 模式（bootstrap 在 api_key==mock 时 `set_active_scenario("S1")`）
- `get_active_scenario()` 为 None ⇒ 真实模式（`clear_active_scenario()`）

**关键**：mock 分支**原样保留**（不要动 `_explain_mock` 现有实现），只新增 `_explain_real` 分支。

## 3. 连接来源与引擎（复用 P4，零新增配置）

```python
from src.config import load_service_settings
from src.infrastructure.services.postgres_connector import PostgresServiceConnector
```

- DSN 唯一来源：`load_service_settings().pg_dsn`（P4 已实现的 `OPERMIND_PG_DSN` 环境变量）。
- 引擎构造复用 P4 的 `PostgresServiceConnector._create_engine()`（psycopg 驱动 + 3s 超时 +
  `SET TRANSACTION READ ONLY`）。**建议把 `_create_engine` 提为模块级函数或类方法，供工具复用**——
  P4 已在类里实现，本阶段抽取为 `backend/src/infrastructure/services/postgres_engine.py` 的
  独立工厂 `create_read_only_postgres_engine(dsn)`，Connector 与工具共用同一实现。
- **无 DSN**：真实模式下工具返回「数据库未配置，无法查询」的诚实降级，不抛异常。
- **连接失败/超时**：返回「数据库不可用」的中性降级，不把异常详情外泄（网关 `_finish` 已兜底）。

## 4. 三个工具的真实查询（定死，照此实现）

所有真实查询都在只读事务内（`SET TRANSACTION READ ONLY`），只发 SELECT，参数用绑定变量防注入。

### 4.1 `explain_sql(sql: str) -> str`

- 安全约束：**只接受 SELECT 开头的查询**。`sql.strip().upper()` 不以 `SELECT` 开头 ⇒ 拒绝，返回
  「只支持分析 SELECT 查询，已拒绝」。
- 执行 `EXPLAIN <原 SQL>`（绑定参数无法用于 EXPLAIN 目标，但 SQL 已限定 SELECT 只读，
  参数化由 psycopg 的 `text()` + 上下文管理器完成；SQL 是只读 SELECT，网关脱敏兜底）。
- 格式化输出（真实计划各列，**只输出有限字段**，不含完整 SQL 原文回显到 Trace）：
  ```
  EXPLAIN 执行计划:
    节点: <Plan Node Type>
    表: <Relation Name / 无>
    访问方式: <Seq Scan | Index Scan | ...>
    行估算: <Plan Rows>
    成本: <Total Cost>
    耗时: <Actual Rows>（有 ANALYZE 才有，本阶段不 ANALYZE，无实际耗时）
    ...
  ```
  输出由 psycopg 的 `cursor.description` 或结果行格式化，**列名作为表头**。
- mock 分支保持现有 `explain_sql` 逻辑不变。

### 4.2 `show_index(table: str) -> str`

- 安全约束：`table` 必须是标识符（`^[A-Za-z_][A-Za-z0-9_]*$`），拒绝空格/分号/注释等注入。
- 查询 `pg_indexes`（只读系统目录，无需 extra 权限）：
  ```sql
  SELECT indexname, indexdef, tablespace, ...
  FROM pg_indexes
  WHERE schemaname = 'public' AND tablename = :table
  ORDER BY indexname
  ```
- 表不存在 ⇒ 返回「表 'x' 不存在」；无索引 ⇒ 返回「表 'x' 没有索引」。
- 格式化输出：索引名 + `indexdef`（如 `CREATE INDEX idx ON public.orders USING btree (status)`）。
- mock 分支保持现有 `get_indexes` 逻辑不变。

### 4.3 `show_create_table(table: str) -> str`

- 安全约束：同 4.2 的标识符校验。
- 从 `pg_catalog` 拼建表语句（只读系统目录）：
  - `pg_class` + `pg_attribute` + `pg_attrdef`（列、类型、默认值）
  - `pg_constraint`（主键/唯一/外键/检查）
  - `pg_indexes`（索引）
- 表不存在 ⇒ 返回「表 'x' 不存在」。
- 格式：仿 `CREATE TABLE public.x (...) ;`，字段/约束/索引分行，用 PostgreSQL 类型名。
- mock 分支保持现有 `get_create_table` 逻辑不变。

## 5. 装配（工具如何拿到引擎）

**不改 `bootstrap.build_coordinator` 的注册方式**（`DBAgent` 内 `tools.register(ExplainTool())`）。

真实模式下，工具内部在 `execute()` 里懒加载引擎：
```python
def _real_engine(self):
    dsn = load_service_settings().pg_dsn
    if not dsn:
        return None
    return create_read_only_postgres_engine(dsn)
```
每次调用现取 DSN、现建引擎（或短生命周期连接），**不跨 Run 持有引擎单例**——
与 `build_coordinator` 每 Run 现造内核的并发隔离原则一致，避免 DSN 变更或并发踩踏。

> 备选：在 `DBAgent.__init__` 注入 dsn。但 `build_coordinator` 每 Run 现造 DBAgent，
> 注入与懒加载结果等价；懒加载改动最小（工具 self-contained），故选懒加载。

## 6. 脱敏与安全边界

- 凭据：DSN 只从 `load_service_settings()` 读，不进日志/结果/Trace/前端（P4 已验证）。
- 输出脱敏：工具真实输出经网关 `desensitize()` 兜底（`sk-`、`password=`、`scheme://u:p@host`）。
  工具自身不把凭据放进返回值。
- **Trace 展示**：`coordinator_executor._event_data` 只取 `tool_invoked` 的 `summary[:280]`，
  不含工具完整输出——新增真实分支不改变 Trace 展示内容。
- SQL 注入：`EXPLAIN` 只接受 SELECT；`table` 参数用标识符正则 + 绑定变量。系统目录查询全部参数化。
- 权限：真实查询只读 `pg_catalog`/`pg_indexes`，不查 `pg_stat_statements`（P4 快照已覆盖指标）。
- 超时：引擎连接 3s + `statement_timeout=3000`（P4 已验）。

## 7. 测试策略

### 单元测试（不连真库，仿 `test_postgres_connector.py` 用假 engine/假连接注入）
新增 `backend/tests/test_db_tools_real.py`：
1. **mock 分支保留**：`set_active_scenario("S1")` 下 `ExplainTool().execute(...)` 返回原 mock 结果（回归保护）。
2. **无 DSN**：`clear_active_scenario()` + 环境变量置空 → 工具返回「未配置」降级，不抛异常。
3. **连接失败**：假 engine 抛 OperationalError → 返回「不可用」降级。
4. **explain 只接受 SELECT**：非 SELECT 输入 → 拒绝文案，不触库。
5. **show_index 正常**：假连接返回 pg_indexes 行 → 格式化输出含索引名/indexdef。
6. **表不存在**：假连接返回空 → 「表 'x' 不存在」。
7. **show_create_table 正常**：假连接返回列/约束行 → 输出含 `CREATE TABLE`。
8. **脱敏**：真实输出经 `desensitize()` 后不含凭据/DSN 明文。

### 回归
- `test_postgres_connector.py`、`test_p4_service_center.py` 全绿（引擎抽取不改行为）。
- `test_agent_gateway.py`、`test_tool_gateway.py` 全绿（工具注册路径不变）。
- 现有 mock 评测路径（S1–S4）不受影响。

### 不做
- 不连真实 PG 的集成测试（本地手动验证，需真实 DSN）。

## 8. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 引擎代码重复（Connector 与工具各一份） | 抽 `create_read_only_postgres_engine` 共用 |
| 真实 EXPLAIN 输出格式不理想 | 只取有限列名/字段，格式化有测试保护 |
| 表名注入 | 标识符正则 + 绑定变量，非 SELECT 拒绝 |
| 无 DSN 环境炸 | 返回「未配置」降级，不抛异常 |
| mock 评测被破坏 | mock 分支原样保留 + 回归测试锁定 |
| 每 Run 建引擎开销 | 每次调用现建，短生命周期；诊断场景低频可接受 |

回滚：删除真实分支、工具回到纯 mock（改 `db_tools.py` 一处），或整体 revert 本阶段提交。
