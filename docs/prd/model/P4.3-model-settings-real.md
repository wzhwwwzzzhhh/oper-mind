# 模型设置页读取真实生效配置 · PRD

## 背景
前端 `frontend/src/features/models/ModelSettingsPage.tsx` 是**纯静态展示 + localStorage 本地偏好**：
- Provider 卡片、模型卡片、Agent 策略都是写死的静态数组（`providers` / `models` / `agent_policies`）。
- 页面标题明确写着"当前页面只保存本地偏好，不代表任何 Provider 已真实连接"，所有按钮（检查连接 / 添加模型服务 / 刷新模型列表）都是 toast 假操作。
- 页面数据不读后端；后端 `config.py` 已能读取真实生效配置（`OPERMIND_API_KEY` / `OPERMIND_BASE_URL` / `OPERMIND_MODEL` 等 env 覆盖 YAML，`load_config()` 已校验完整性），但未暴露给前端。

即：后端有真实配置事实，前端展示的是静态假数据——**诚实性缺口**，与 P4.2/P4.3 会话链路"能力诚实"同源。

关联：`docs/产品定义.md`（用户模型 Provider 与 API Key 设置属平台能力）、`docs/路线图.md`（第四阶段"用户模型 Provider 与 API Key 设置"）、`docs/开发规范.md`（凭据只走环境变量，不得落库）。

## 目标
1. 模型设置页展示后端**当前真实生效**的模型配置（诊断模型 / 裁判模型 / Provider / 连接状态），不再用静态假数据冒充。
2. 不新增凭据保存、Provider 编辑、连接测试能力——这些涉及凭据方案，须另行 Design→Review→确认。

## 用户故事
作为运维工程师，我打开模型设置页，应看到后端当前正在使用的诊断模型与裁判模型配置（Provider、模型名、连接状态），而不是静态示例——以便确认当前配置是否如我预期，以及是否需要联系管理员调整。

## 范围

### 做什么
- 后端新增**只读**模型配置读取接口，返回当前生效配置的安全视图（不返回 API Key 明文）。
- 前端模型设置页从后端读取该配置，替换静态 Provider/模型展示为真实生效配置；未配置字段诚实显示"未配置"。

### 不做什么（明确排除）
- 不新增 API Key 输入/保存/编辑能力（涉及凭据方案，另行设计）。
- 不新增 Provider 编辑、删除、测试连接能力。
- 不做模型列表自动发现（Ollama 等 Provider 的模型枚举）。
- 不做 Agent 调用策略（Coordinator/DB/Server...开关）的真实化——该策略当前无后端事实，保留前端本地偏好或降级为只读展示。
- 不改后端配置机制本身（`load_config` / env 覆盖逻辑）。
- 不涉及数据库迁移。

## 功能需求

### 1. 只读模型配置接口
- **输入**：`GET /api/v1/model/config`（或既有 v1 下的等价路径）。
- **行为**：
  - 返回后端当前生效的模型配置安全视图：诊断模型（provider/base_url 主机/model）、裁判模型（同，若配置了）、连接模式（mock/real）。
  - **绝不返回 API Key 明文**，也不返回含凭据的完整 URL。
- **输出**：结构化安全视图。

### 2. 前端读取并展示真实配置
- **输入**：前端模型设置页挂载。
- **行为**：
  - 从后端读取只读配置接口，替换静态 Provider/模型展示为真实生效配置。
  - 后端未返回的字段（如裁判模型未配置）如实显示"未配置"，不伪造。
  - 保持页面既有"本地偏好"部分（当前模型选择）不动——那是本地 UI 状态，可保留。
- **输出**：真实生效配置的页面展示。

## 非功能需求
- **安全**：接口只返回安全视图，绝不含 API Key / 凭据 / DSN；脱敏为硬约束。
- **诚实**：未配置字段显示"未配置"，不伪造示例；接口不可用时显示错误，不回退到静态假数据。
- **性能**：接口为本地配置读取，无外部调用，响应应在 ms 级。

## 数据与接口影响
- 数据：无新增持久化，无迁移。
- 接口：新增只读模型配置接口；前端模型设置页接入；无既有接口契约变化。

## 验收标准
- [ ] AC1: 当请求 `GET /api/v1/model/config` 时，应返回后端当前生效的诊断模型配置（provider/base_url 主机/model），且不含 API Key 明文。
- [ ] AC2: 当后端为 mock 模式（`OPERMIND_API_KEY=mock`）时，接口应返回 `mode=mock` 并如实标注。
- [ ] AC3: 当裁判模型未配置时，接口的裁判模型字段应返回"未配置"（或等价空态），不伪造。
- [ ] AC4: 接口响应中不得出现 `sk-`、API Key、密码或完整 DSN 明文。
- [ ] AC5: 前端模型设置页挂载时，应读取后端真实配置并展示，替代静态 Provider/模型假数据。
- [ ] AC6: 当接口不可用（后端错误）时，前端模型设置页应显示错误状态，不回退到静态示例假数据。
- [ ] AC7: 模型设置页的"添加模型服务 / 测试连接"等未接入能力应保持禁用/提示，不假装已实现。
- [ ] AC8: 回归 —— 后端既有测试全绿；前端 `typecheck` / `test` / `build` 通过。

## 边界与约束
- 安全边界：只读；接口脱敏为硬约束；无凭据保存/落库/日志/Trace。
- 降级策略：接口不可用时前端显示错误，不伪造；未配置字段显示"未配置"。
- 兼容性：Agent 调用策略开关无后端事实，保留前端本地偏好，不冒充真实装配；mock/real 模式如实标注。
