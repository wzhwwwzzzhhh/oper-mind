# 用量与成本统计——token 计数与花费查询 · PRD

## 背景

模型设置页当前没有**用量/成本统计**能力（`docs/接口清单.md` 第四大模块"缺少"表："用量 / 成本统计：无 token 计数与花费统计接口"）。

现状：后端 `backend/src/core/llm.py` 的 `LLMClient` 有实例级 `total_tokens` 累加（真实调用累加 usage.total_tokens，mock 恒为 0，"供评测成本核算"），但**不落库、不跨实例、不暴露接口**。真实调用产生的 token 用量只在单次进程的单个实例内存里，进程重启即丢，运维无从查询"系统这个月调模型花了多少 token"。

产品定义把"用量/成本统计"列为模型设置域的平台能力（`docs/产品定义.md`：用户模型 Provider 设置属平台能力），当前无任何查询入口。

关联：`docs/接口清单.md`（第四大模块缺表）、`docs/prd/model/P6-model-provider-key-management.md`（Provider/Key 管理已落地）、`docs/prd/model/P8-model-params-config.md`（同批 P8，模型参数配置）、`docs/产品定义.md`（模型设置域）。

## 目标

1. 运维能查询模型调用的 **token 用量与估算花费**（按时间窗 / 按模型）。
2. 真实调用的 token 用量**落库持久化**（跨进程、可追溯），mock 恒为 0 如实标注。
3. 花费为**估算**（按模型单价 × token，单价可配置或内置默认），如实标注"估算"。

## 用户故事

作为运维工程师，我想知道"这个月模型调用花了多少 token、大概多少钱、按哪个模型"，应有一个用量统计接口——以便核算成本、发现异常用量。

## 范围

### 做什么
- 用量采集：`LLMClient` 真实调用时把 usage（input/output/total tokens）**落库**，mock 不采集（恒 0 如实）。
- 统计接口：`GET /model/usage`（或等价），按时间窗（from/to）与模型过滤，返回 token 用量与估算花费。
- 花费估算：按模型单价 × token 估算，单价可配置（应用库键值）或内置默认，响应标注"估算"。
- 前端适配：模型设置页新增"用量"区域或独立入口，展示统计。

### 不做什么（明确排除）
- 不做精确账单/计价（`docs/产品定义.md` §7 未决；只做估算）。
- 不做按会话/Run 的用量明细下钻（首版只做聚合统计，明细后续）。
- 不做用量告警/限额（另行排期）。
- 不采集 mock 用量（mock 恒 0，如实标注）。
- 不暴露调用内容、prompt、响应、API Key 或凭据（只暴露聚合计数）。

## 功能需求

### 1. 用量采集落库
- **输入**：真实 LLM 调用完成的响应（含 usage）。
- **行为**：在 `LLMClient` 真实调用完成后，把 input/output/total tokens、模型名、时间戳**写入应用库**；mock 调用不采集（恒 0）。采集不依赖实例级 `total_tokens`（每 Run 新造 Coordinator/LLMClient，实例内存会随 Run 结束丢失）——落库是采集的持久化载体，采集点位于调用返回处。
- **输出**：用量记录持久化（跨进程可追溯）。

### 2. 用量统计接口（GET /model/usage）
- **输入**：可选时间窗（from/to）、模型过滤。
- **行为**：按时间窗/模型聚合 token 用量（input/output/total），按单价估算花费；无记录返回空态。
- **输出**：聚合统计（按模型分组，含 token 数与估算花费）；标注"估算"。

### 3. 花费估算
- **输入**：模型单价（应用库键值，可配置）。
- **行为**：按单价 × token 估算花费；未配置单价用内置默认；mock 恒 0。
- **输出**：估算花费，明确标注"估算"。

### 4. 前端用量展示
- **输入**：模型设置页 / 独立用量入口。
- **行为**：展示统计（按模型分组的 token 与估算花费），支持时间窗筛选；空态/失败态诚实展示。
- **输出**：用量统计界面。

## 非功能需求
- **诚实**：mock 恒 0 如实标注；花费标注"估算"；无记录空态。
- **安全**：只暴露聚合计数，不含调用内容/prompt/响应/API Key/凭据。
- **性能**：统计为库内聚合查询，分页/限时；用量采集为每调用一次写入，不应明显拖慢调用。
- **可靠**：单次采集失败不影响调用（采集是副作用，失败降级不阻断）。

## 数据与接口影响
- 数据：新增用量记录表（usage 表：模型名、input/output/total tokens、时间戳），涉及数据库迁移；花费单价键值（应用库）。
- 接口：新增 `GET /model/usage`；既有接口契约不变。

## 验收标准
- [ ] AC1: 当真实 LLM 调用完成时，应把 usage（input/output/total tokens + 模型名 + 时间戳）落库。
- [ ] AC2: 当请求 `GET /model/usage` 时，应按时间窗/模型返回 token 用量聚合统计。
- [ ] AC3: 当用时间窗过滤时，应只返回窗口内的用量。
- [ ] AC4: 花费应标注"估算"；未配置单价用内置默认，配置后按配置估算。
- [ ] AC5: mock 调用不采集用量（统计中 mock 恒 0，如实标注）。
- [ ] AC6: 无用量记录时返回空态，不抛错。
- [ ] AC7: 用量统计响应不得包含调用内容、prompt、响应、API Key、`sk-` 或凭据。
- [ ] AC8: 单次用量采集失败不影响 LLM 调用本身（采集是副作用）。
- [ ] AC9: 前端用量区域可展示统计，支持时间窗筛选，空态/失败态诚实。
- [ ] AC10: 回归 —— 既有 `test_agent_gateway.py` / `test_model_provider_api.py` 相关全绿；前端 `typecheck`/`test`/`build` 通过。

## 边界与约束
- 安全边界：只暴露聚合计数，不含调用内容/凭据；采集不阻断调用。
- 降级策略：采集失败 → 不影响调用；无记录 → 空态；mock → 恒 0 如实。
- 兼容性：既有接口契约不变；mock 模式行为一致。

## 开放问题
1. **单价来源**：内置默认模型单价表 + 应用库可覆盖，还是纯配置？→ 推荐内置默认 + 可覆盖，Design 定。
2. **用量明细下钻**：首版只做聚合，是否预留按会话/Run 下钻的字段？→ 推荐预留 `run_id`（或等价）字段便于后续，Design 定。
3. **采集异步化**：用量落库是否异步（不阻塞调用返回）？→ 推荐异步或同事务轻量写，Design 定。
