# 知识文档列表分页——目录浏览容量化 · PRD

## 背景

文档知识库已交付目录内 Markdown 确定性检索与只读浏览（`docs/prd/knowledge/P6-knowledge-retrieval.md`、`P7-knowledge-page.md`）。但 `GET /knowledge/documents` **无分页**——目录规模上去后一次性全量返回（`docs/接口清单.md` 第三大模块"缺少"表："文档列表分页：目录规模上去后一次性全量返回。❌ 欠账（优先级低）"）。

现状：`backend/src/knowledge/reader.py` 的 `list_documents()` 每次现场 `rglob` 受管目录、排除隐藏/凭据路径与含 `sk-` 明文的文档，全量返回 `KnowledgeDocumentMeta` 列表；`GET /knowledge/documents` 直接透传（`backend/src/api/v1/routes.py`）。目录达到数百篇时，一次请求全量遍历并全量返回，无分页/限流。

关联：`docs/接口清单.md`（第三大模块缺表）、`docs/prd/knowledge/P6-knowledge-retrieval.md`（确定性检索）、`docs/prd/knowledge/P7-knowledge-page.md`（目录浏览页）、`docs/产品定义.md` §6（知识库边界：受管目录内 Markdown 确定性检索与只读浏览）。

## 目标

1. `GET /knowledge/documents` 支持**分页**（cursor 或 offset/limit，Design 定），目录大时按页返回，响应体积可控。
2. 分页**确定性排序**（按相对路径，与现状一致），页与页之间不重不漏。
3. 未配置 / 空目录行为不变（`not_configured` + 空列表），既有前端页面兼容（默认取首页）。

## 用户故事

作为用户，我在文档知识库目录里浏览文档，目录已有数百篇，应能翻页浏览而不是一次性加载全部——以便页面流畅、加载可控。

## 范围

### 做什么
- `GET /knowledge/documents` 增加分页参数（cursor/limit，Design 定；兼容默认值），按相对路径确定性排序分页返回。
- 响应包含分页信息（`items` + 下一页 cursor 或 offset/limit 元信息），空页/末尾语义明确。
- 前端文档知识库页面适配分页（滚动加载或翻页按钮，Design 定），目录大时不一次性渲染全部。
- 未配置/空目录返回不变（`not_configured` + 空列表，诚实降级）。

### 不做什么（明确排除）
- 不新增索引/缓存层：现状是每次现场 `rglob`，本 PRD 只加分页，不引入缓存（目录规模优化另行评估，`docs/接口清单.md` 已注明现状代价）。
- 不做全文检索语义变更：`GET /knowledge/search` 不动。
- 不做上传/新建/编辑/删除（只读浏览边界，`docs/接口清单.md` 刻意不做）。
- 不改变单篇读取 `GET /knowledge/documents/{path}` 契约。
- 不暴露隐藏路径、凭据路径或含 `sk-` 的文档（分页沿用既有排除逻辑）。

## 功能需求

### 1. 分页列表（GET /knowledge/documents）
- **输入**：可选分页参数（cursor 或 offset/limit，Design 定）。
- **行为**：
  - 按相对路径确定性排序后分页返回；页大小有上限（如 100，Design 定），超限按上限截断。
  - 无分页参数时返回首页（与现状兼容，前端既有调用不带参数仍可用）。
  - 末页后请求下一页返回空 items 与明确的"无更多"语义（cursor 为 null / items 为空）。
  - 未配置目录 → `not_configured` + 空列表（不变）。
- **输出**：`items`（分页后的文档元数据）+ 分页信息（下一页 cursor 或 offset/limit）；不含文档正文。

### 2. 前端目录分页适配
- **输入**：文档知识库目录页。
- **行为**：按分页加载目录（滚动加载或翻页），加载中/空态/失败态诚实展示；既有"未配置"提示不变。
- **输出**：分页浏览的目录列表，页面不一次性渲染全部文档。

## 非功能需求
- **性能**：单页返回体积受页大小上限约束；不做额外全量物化（排序仍基于现有遍历，Design 评估大数据量下的排序成本与优化边界）。
- **确定性**：相同目录重复请求同一页，内容一致（稳定排序）。
- **安全**：分页沿用既有排除逻辑（隐藏路径/凭据路径/`sk-` 文档不出现）；不暴露目录外路径。
- **兼容性**：无分页参数的既有调用行为不变（返回首页）；单篇读取与搜索契约不变。

## 数据与接口影响
- 数据：无新增持久化、无迁移（现场遍历 + 分页切片）。
- 接口：`GET /knowledge/documents` 响应结构变化（新增分页字段）——**属既有接口契约扩展**，前端 `generated.ts` 需重新生成；单篇读取/搜索契约不变。

## 验收标准
- [ ] AC1: 当请求 `GET /knowledge/documents` 时不带分页参数，应返回首页（与既有行为兼容）。
- [ ] AC2: 当目录文档数超过页大小时，应分页返回，每页不超上限，页与页之间不重不漏。
- [ ] AC3: 当请求超出最后一页时，应返回空 items 与明确的"无更多"语义，不抛错。
- [ ] AC4: 当目录未配置时，应返回 `not_configured` + 空列表（行为不变）。
- [ ] AC5: 当分页参数非法（如页大小超上限、cursor 非法）时，应返回明确错误（如 422）。
- [ ] AC6: 分页结果应确定性排序（相同请求重复返回一致内容）。
- [ ] AC7: 分页列表不得包含隐藏路径、凭据路径或含 `sk-` 的文档。
- [ ] AC8: 前端目录页应支持分页浏览，加载中/空态/失败态诚实展示。
- [ ] AC9: 回归 —— 既有知识库相关测试全绿；前端 `typecheck`/`test`/`build` 通过。

## 边界与约束
- 安全边界：沿用既有排除逻辑，不暴露隐藏/凭据/`sk-` 文档；分页不引入新访问面。
- 降级策略：未配置 → `not_configured` + 空列表；非法分页参数 → 明确错误；读取失败 → 诚实错误。
- 兼容性：无参数调用返回首页；单篇读取与搜索契约不变。

## 开放问题
1. **分页风格**：cursor（键集，与全局列表先例一致）还是 offset/limit？推荐 cursor（与 `GET /runs` 等既有分页先例一致），Design 定。
2. **页大小默认与上限**：默认 50 / 上限 100？Design 定。
3. **大数据量排序成本**：现场 `rglob` + 全量排序在数千篇目录下的成本是否接受，还是需先限流/优化（如按前缀分桶）？推荐首版接受现状成本 + 页上限，Design 评估。
