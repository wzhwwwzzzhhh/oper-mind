# 知识库——目录内 Markdown 确定性检索 · PRD

## 背景
OperMind 多 Agent 内核（Coordinator → DB / Server / Log 等领域 Agent → 受控工具）已能对已接入服务做
只读调查，但**没有知识检索能力**：Agent 只能查实时数据，无法参考运维文档、SOP、历史排障记录等存量知识。
产品定义把"知识检索"列为协调 Agent 可分派的角色之一（`docs/产品定义.md` §2.2），并明确
"知识库、文件、RAG、MCP 的产品边界尚未决策，不得擅自实现"（§6）。知识库域完全未启动（无检索/RAG 代码）。

本 PRD 是知识库的**第一个可交付切片**：**目录内 Markdown 确定性检索**——在受管目录内，按关键词/标题
确定性检索 Markdown 文档并返回脱敏摘要，作为 Agent 工具接入现有工具链路。**不做向量库/Embedding/RAG**，
用确定性检索先验证"知识检索 → Agent 使用 → 结论引用"闭环，诚实、可测、无外部依赖。

关联：`docs/路线图.md`（第四阶段"允许目录内 Markdown 知识检索，以及后续知识库能力"）、
`docs/产品定义.md`（§2.2 知识检索角色、§6 知识库边界未决策）、
`docs/开发规范.md`（Connector/Tool 须显式注册、参数校验、超时、脱敏、权限边界）、
`backend/src/core/tool_registry.py` 与 `backend/src/core/tool_gateway.py`（现有 Tool/网关模式）、
`backend/src/core/bootstrap.py`（领域 Agent 注册，DB/Server/Log 模式，知识检索沿用）。

## 目标
1. 在受管目录内对 Markdown 文档做**确定性检索**（关键词/标题匹配），返回脱敏摘要，无外部依赖。
2. 知识检索以 **Tool 形式接入现有 Agent 工具链路**（`ToolGateway` 白名单准入、超时、脱敏），
   作为新领域 Agent（knowledge）的工具，沿用 DB/Server/Log 注册模式。
3. 诚实空态：未配置知识目录 → "未配置"；目录为空 → "无文档"；无匹配 → "无匹配文档"；不伪造检索结果。
4. 安全边界：只读受管目录，不越权访问目录外文件，不把文件系统结构/全文/凭据暴露到 Trace 或前端。

## 用户故事
作为运维工程师，我在会话中问"我们 kill 慢查询的 SOP 是什么"，
Agent 检索到知识目录里的 Markdown 文档并引用其要点回答，Trace 里能看到"知识检索"步骤及其脱敏摘要。
我能清楚看到检索来源是受管知识目录，而不是对文件系统的任意访问。

## 范围

### 做什么
- 新增**知识检索 Tool**：在配置的知识目录内，按关键词/标题匹配 Markdown 文档，返回匹配文档的脱敏摘要
  （标题 + 命中片段，不含凭据）。
- 新增 **knowledge 领域 Agent**（或复用协调路由），注册知识检索工具，沿用现有领域 Agent 模式。
- 知识目录经**配置**（环境变量，默认空 → 未配置降级），不硬编码路径，不越权访问目录外文件。
- 确定性检索：关键词/标题匹配，不引入向量/Embedding/RAG（后续阶段）。
- 检索结果只进 Agent 上下文，Trace 只展示"知识检索"步骤 + 脱敏摘要；不展示全文/目录结构/凭据。

### 不做什么（明确排除）
- 不做向量数据库 / Embedding / RAG / 语义检索（后续阶段，需单独 Design）。
- 不做文件管理 / 上传 / 编辑知识文档的前端或接口（只读检索）。
- 不授予对任意文件系统路径的访问（只能检索配置的知识目录，路径受参数校验约束）。
- 不检索非 Markdown 文件 / 二进制 / 凭据文件（.env、config.local.yaml、密钥文件明确排除）。
- 不接入外部知识源（网站、Confluence、工单系统等）。
- 不改 mock 数据源（`data/mock_db.py`、`data/scenarios.py`）与 S1–S4 评测路径。
- 不做知识写入 / 索引构建的持久化（本阶段为目录即时确定性检索）。

## 功能需求

### 1. 知识目录配置
- **输入**：环境变量（如 `OPERMIND_KNOWLEDGE_DIR`），指向受管 Markdown 知识目录。
- **行为**：读取目录下 Markdown（`.md`）文档清单；目录未配置/不存在 → "未配置"状态。
- **输出**：受管文档集合（只读）；无配置时诚实降级，不崩溃、不伪造。

### 2. 确定性检索
- **输入**：检索词（关键词/短语，参数校验：长度限制、拒绝路径注入字符）。
- **行为**：在受管文档中按标题与正文关键词匹配，返回匹配文档的脱敏摘要
  （文档标题 + 命中片段），按相关度排序（可基于命中次数/标题优先），限制返回条数。
- **输出**：匹配文档摘要列表；无匹配 → "无匹配文档"诚实空态。

### 3. 知识检索 Tool 接入 Agent 链路
- **输入**：knowledge 领域 Agent（或协调路由）调用检索工具。
- **行为**：工具经 `ToolGateway` 白名单准入，参数校验、限时、脱敏兜底（沿用现有网关行为）；
  检索结果进入 Agent 上下文，用于结论引用。
- **输出**：Agent 可在诊断/回答中引用知识要点；Trace 展示"知识检索"步骤与脱敏摘要。

### 4. 安全与脱敏
- **输入**：任意检索词 / 任意文档内容。
- **行为**：只读受管目录，参数校验防路径逃逸；排除凭据文件；结果经网关 `desensitize` 兜底；
  凭据/DSN/全文/目录结构不进 Trace、前端、事件。
- **输出**：脱敏后的检索摘要，无凭据、无目录结构、无越权访问。

## 非功能需求
- **性能**：检索限时（复用网关超时模式）；文档量受限（受管目录），检索线性可接受。
- **安全**：只读受管目录；参数校验防路径逃逸；凭据文件排除；脱敏兜底。
- **可靠**：未配置/目录空/无匹配均诚实降级，不抛异常。
- **诚实**：检索来源标注为受管知识目录；无匹配如实空态；不把目录检索伪装成实时数据库查询。

## 数据与接口影响
- 数据：无新增持久化（本阶段即时目录检索，不建索引表）。
- 接口：无新增公开 API（知识检索作为 Agent 工具，不暴露前端直连接口）；前端不变或仅 Trace 展示
  "知识检索"步骤（若需展示，复用现有 Trace 事件模型，不新增字段契约）。

## 验收标准
- [ ] AC1: 当知识目录未配置或不存在时，检索工具返回"未配置"诚实状态，不崩溃、不伪造结果。
- [ ] AC2: 当知识目录为空（无 Markdown 文档）时，检索工具返回"无文档"诚实状态。
- [ ] AC3: 当检索词在受管文档中有匹配时，返回匹配文档的脱敏摘要（标题 + 命中片段），
      按相关度排序，条数受限。
- [ ] AC4: 当检索词无匹配时，返回"无匹配文档"诚实空态。
- [ ] AC5: 检索工具只读受管知识目录；目录外路径/路径逃逸输入被拒绝（参数校验），不返回目录外文件。
- [ ] AC6: 凭据文件（`.env`、`config.local.yaml`、含 `sk-` 内容）不在检索范围，检索结果不含凭据。
- [ ] AC7: 知识检索作为 Agent 工具经 `ToolGateway` 白名单准入、限时、脱敏兜底；
      知识检索结果进入 Agent 上下文用于结论引用。
- [ ] AC8: Trace 只展示"知识检索"步骤与脱敏摘要，不含文档全文、目录结构或凭据。
- [ ] AC9: mock 评测（S1–S4）路径不受影响；既有后端测试、前端 typecheck/test/build（如涉及）全绿。

## 边界与约束
- 安全边界：只读受管目录；参数校验防路径逃逸；凭据文件排除；脱敏兜底；无外部网络访问。
- 降级策略：未配置 → "未配置"；目录空 → "无文档"；无匹配 → "无匹配文档"；均不抛异常。
- 兼容性：mock 评测（S1–S4）行为不变；知识检索为新增能力，不影响既有 DB/Server/Log 工具。
- 工程闸门：本 PRD 涉及**新增 Tool/能力与配置读取**，按开发规范须先 Design → Review → 用户确认
  才能实施；本 PRD 是需求层，不替代 Design 文档。
