# 服务监控历史趋势与页面内告警 · PRD

## 背景
P4 已让服务中心快照连真实 PostgreSQL（`PostgresServiceConnector`），`health_snapshot()` 提供**单次现读快照**：
连接状态（availability）、基础性能标量（p50/p95/慢查询计数/超时计数）与数据库高层信号（database.signal），
3s 超时、纯只读、脱敏。但当前只有"这一个瞬间"，没有历史：

1. **无历史趋势数据**：服务详情页"运行趋势"卡片是空态占位（"当前接口未提供历史趋势数据"），
   用户无法判断服务是否在恶化。
2. **快照是"读一次"，不是"持续观察"**：每次打开页面才现读一次，且同一时刻只能看到一个点，
   无法回答"最近一小时延迟是不是在涨"。
3. **告警缺失**：慢查询/超时异常只能靠人工盯快照，无异常点标记。

产品诚实性硬约束（`docs/产品定义.md` §5.5、`docs/开发规范.md` §5）：监控必须明确区分
当前快照 / 历史记录 / 模拟数据 / 不可用 / 未知，**不得把一次读取伪装成长期实时监控**。
本 PRD 的数据来源、采样机制、保留窗口与告警范围，正属于产品定义 §6 留待确认的"监控数据来源、轮询/推送策略、历史保留与告警范围"。

关联：`docs/路线图.md`（第四阶段"历史监控、趋势和告警"；第二阶段服务中心"基础当前状态 / 监控入口"）、
`docs/design/service-center/P4服务中心变真Design.md`（Section 1 明确"不做完整历史监控趋势（缺接口，P5 才做）"；Section 4 定义 `ServiceSnapshotData` 字段）、
`docs/产品定义.md` §5.5 与 `docs/开发规范.md` §5（监控诚实性）、
`docs/prd/service-center/P4.4-service-instances.md`（多服务实例注册与命名空间 DSN，采样对象来源）。

## 目标
1. 后端对已注册服务**周期采样**（复用现有只读快照能力），把脱敏标量写入历史样本，形成可查询的时间序列。
2. 新增历史趋势查询接口，服务详情页"运行趋势"卡片从空态变真态，展示延迟/慢查询/可用性趋势。
3. 页面内对异常采样点做高亮标记（慢查询>0、可用性变化、超时>0），**不**做外部推送。
4. 全程诚实：标注数据来源（定时采样）、采样频率、保留窗口；无数据/未配置/不可用如实展示，不伪造实时性。

## 用户故事
作为运维工程师，我在服务详情页想看到已接入服务（如 `postgres-production`）最近一段时间的
延迟、慢查询和可用性**趋势**，并让异常采样点被标记出来——以便判断服务是否在恶化。
我能清楚看到这是"每 5 分钟一次的定时采样历史记录"，而不是假装实时的监控。

## 范围

### 做什么
- 后端定时采样器：周期对**静态注册表内每个已注册服务**调用只读快照（复用 P4 快照能力与超时），
  将脱敏标量写入历史样本。
- 历史样本持久化：**含数据库迁移**；样本只存脱敏标量，不存 SQL/对象名/凭据。
- 历史趋势查询接口：按服务 + 时间窗口返回样本序列；空窗口返回空序列（诚实空态）。
- 前端服务详情页"运行趋势"卡片接入历史接口，展示延迟/慢查询/可用性趋势。
- 页面内异常高亮：慢查询>0、超时>0 或可用性状态变化的采样点被标记，并在摘要列出。
- 诚实标注：接口与前端标注"定时采样 · 每 5 分钟 · 保留最近 24 小时 · 历史记录"。

### 不做什么（明确排除）
- 不做外部告警推送（邮件 / Slack / Webhook / 企业微信 / 短信）：无通知渠道，如实标注未启用。
- 不做实时/近实时监控（采样频率固定，不承诺秒级）；趋势图展示的是**历史记录**，不是实时值。
- 不做采样器高可用 / 分布式 / 补采样（单进程定时任务，能力边界如实声明）。
- 不做跨服务对比、历史搜索、导出、聚合报表。
- 不新增监控凭据/连接：复用 P4.4 命名空间 DSN；未配置服务不采样有效值，如实展示"未配置"。
- 不改 mock 数据源（`data/mock_db.py`、`data/scenarios.py`）与 S1–S4 评测路径。

## 功能需求

### 1. 后端定时采样器
- **输入**：静态服务注册表内已注册的服务（复用 `ServiceRegistry` 已注册 Connector）。
- **行为**：
  - 周期（默认每 5 分钟，可配置）对每个已注册服务调用只读快照；
  - 单次采样超时复用 P4 快照超时（3s），超时/失败/未配置不抛异常，不阻塞其他服务；
  - 采样结果按来源状态如实落库：available / not_configured / unavailable（含 timeout）。
- **输出**：每个服务一条脱敏样本（service_id、时间戳、availability、p50_ms、p95_ms、
  slow_query_count、timeout_count、performance_signal、source 状态）。

### 2. 历史样本持久化
- **输入**：采样器产出的脱敏样本。
- **行为**：样本写入历史表；只含收敛标量，不含 SQL、对象名、原始日志、凭据；有限保留窗口
  （默认保留最近 24 小时，超窗由清理机制移除，保留窗口可配置）。
- **输出**：可查询的时间序列数据。

### 3. 历史趋势查询接口
- **输入**：`service_id` + 时间窗口（起止时间，默认最近 24 小时）。
- **行为**：
  - 返回该服务在窗口内的样本序列，按时间升序；
  - 服务未注册/无样本 → 空序列 + 诚实状态（未采样/未配置/无数据），不伪造；
  - 接口只返回脱敏标量，不返回 SQL/对象名/凭据。
- **输出**：历史样本序列（JSON）。

### 4. 前端服务详情页趋势展示
- **输入**：服务详情页"运行趋势"卡片。
- **行为**：
  - 从历史接口读取样本，渲染延迟（p50/p95）、慢查询计数与可用性趋势；
  - 明确标注"定时采样 · 每 5 分钟 · 保留最近 24 小时 · 历史记录"，不得标注为"实时监控"；
  - 无样本/未配置/不可用时保持诚实空态（"暂无历史采样"），不画假趋势线。
- **输出**：趋势图 + 数据来源标注。

### 5. 页面内异常高亮
- **输入**：已渲染的历史样本序列。
- **行为**：
  - 阈值判定：slow_query_count>0、timeout_count>0、availability 状态变化（如 ok→unavailable）的采样点被标记；
  - 页面在趋势图上高亮异常样本点，并在摘要列出最近的异常样本（时间 + 触发指标）；
  - 高亮只表述为"采样点异常"，**不**声称"正在告警/正在推送"，不伪造实时监控。
- **输出**：异常点标记 + 异常摘要列表。

## 非功能需求
- **性能**：采样器异步/低阻塞，不影响现有服务快照与接口；历史查询接口限制最大窗口范围。
- **安全**：只读；样本只含脱敏标量；不落 SQL/对象名/凭据；复用 P4 快照的安全边界。
- **诚实**：区分采样来源状态（available/not_configured/unavailable）；趋势图标注为历史记录而非实时；
  无数据如实空态。
- **可靠**：采样失败不影响单次快照与现有接口；单服务采样失败不拖累其他服务。

## 数据与接口影响
- 数据：新增历史样本表（service_id、采样时间戳、脱敏标量、source 状态），**含数据库迁移**；
  保留窗口策略（默认 24 小时，清理机制可选实现）。
- 接口：新增历史趋势查询接口（按服务 + 窗口返回样本序列）；`GET /services/{id}` 等既有快照契约不变。

## 验收标准
- [ ] AC1: 当已注册服务已配置 DSN 时，定时采样器按周期写入脱敏样本，历史查询接口能读到按时间升序的样本序列。
- [ ] AC2: 当服务未配置 DSN 时，该服务不产生有效样本，查询接口返回空序列 + "未配置"诚实状态，不伪造数值。
- [ ] AC3: 当采样连接失败/超时时，该次样本记录为"不可用"状态，不抛异常、不阻塞其他服务采样，接口不暴露异常详情。
- [ ] AC4: 历史查询接口按 service_id + 窗口返回，样本只含脱敏标量，不含 SQL、对象名或凭据。
- [ ] AC5: 当历史接口无样本（新接入服务/刚启动）时，前端"运行趋势"卡片显示"暂无历史采样"诚实空态，不画假趋势线。
- [ ] AC6: 当存在 slow_query_count>0 或 availability 状态变化的采样点时，前端趋势图高亮该点并在摘要列出，标记为"采样点异常"而非"正在告警"。
- [ ] AC7: 前端趋势卡片在展示历史数据时，标注"定时采样 · 每 5 分钟 · 保留最近 24 小时 · 历史记录"，不出现"实时监控"表述。
- [ ] AC8: 回归 —— mock 模式（S1–S4）评测路径不受采样器影响；`GET /services/{id}` 等既有服务接口契约不变，相关回归测试全绿。
- [ ] AC9: 采样器不写入 SQL、对象名、原始日志或凭据（含 `.env`/`config.local.yaml`/`sk-` 内容），历史表与查询接口均不出现。

## 边界与约束
- 安全边界：纯只读；采样对象只能是静态注册表内已注册服务；样本只含收敛标量；无写路径、无凭据落库。
- 降级策略：未配置 → "未配置"；连接失败/超时 → "不可用"；无样本 → 诚实空态；均不抛异常、不伪造。
- 兼容性：mock 评测（S1–S4）行为不变；既有服务快照接口契约不变；采样为新增能力，不影响单次快照读取。
- 工程闸门：本 PRD 涉及**新增监控能力与数据库迁移**，按开发规范必须先完成 Design → Review → **用户确认**后才能实施；本 PRD 是需求层，不替代 Design 文档。

## 已确认决策
1. 历史数据来源：**后端定时采样器**（复用现有只读快照能力，不新增连接/凭据能力）。
2. 告警范围：**页面内高亮**（异常采样点标记 + 摘要），不做外部推送，未启用能力如实标注。
