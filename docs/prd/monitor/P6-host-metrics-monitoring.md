# 服务主机指标监控 · PRD

## 背景

Server 工具目前提供 CPU/内存/磁盘/进程/网络的**单次快照**（`CheckCpuTool` / `CheckMemoryTool` / `CheckDiskTool` / `CheckProcessTool` / `CheckNetworkTool`），经 `psutil` 采集本机指标，mock 模式读 `data/scenarios.py` 确定性场景。但这些指标是**会话内一次性工具输出**，未纳入服务中心、未做历史采样，也没有"服务→主机指标"的绑定视图。

现状缺口：运维接入服务后，无法从服务中心查看服务所在主机的 CPU/内存/磁盘/进程/网络指标，也无法看历史趋势；主机指标只存在于会话工具输出，未进产品主链。这与 P5 历史监控（数据库指标）同构，是路线图第三阶段明确列出的能力（"服务与主机：CPU、内存、进程、网络"）。

关联：`docs/design/monitor/P5监控历史趋势与页面告警Design.md`（采样器/样本表/历史 API/前端趋势）、`docs/prd/monitor/P5-monitor-trends.md`（历史监控 PRD）、`docs/产品定义.md`（服务监控/状态页面）、`docs/路线图.md`（第三阶段"服务与主机：CPU、内存、进程、网络"）、`backend/src/tools/server_tools.py`（psutil 单次快照）。

## 目标

1. 主机指标（CPU/内存/磁盘/进程/网络）纳入服务中心，作为服务详情的一部分展示。
2. 主机指标纳入历史采样与趋势（复用 P5 采样器/样本表），可看历史走势。
3. 未配置/不可用诚实标注；mock 模式行为不变。

## 用户故事

作为运维工程师，我在服务中心打开一个服务的详情页，应看到该服务所在主机的 CPU/内存/磁盘/网络当前状态与历史趋势——以便在数据库或缓存变慢时，从产品主链判断是否主机的资源瓶颈，而不是 SSH 上去 `top`/`df`。

## 范围

### 做什么
- 主机指标纳入服务中心：服务详情展示 CPU/内存/磁盘/网络当前状态（复用并扩展现有 psutil 采集）。
- 历史采样：主机指标纳入 P5 `MonitorSampler` 定时采样，写入历史样本表，趋势页自动展示。
- 进程指标：异常进程（高 CPU/高内存）展示（复用现有 psutil 采集，纳入快照）。
- mock 模式行为不变，S1–S4 评测确定性不受影响。

### 不做什么（明确排除）
- 不做远程主机的 SSH/Agent 部署（本阶段只采后端所在主机，远程主机接入后续阶段）。
- 不做主机级告警规则（P5 告警范围沿用，不新增）。
- 不新增独立"主机监控"页面（并入服务详情页）。
- 不接外部监控系统（Prometheus / Grafana 等，后续阶段）。
- 不改 mock 数据源与 S1–S4 评测路径。

## 功能需求

### 1. 主机指标纳入服务中心
- **输入**：服务详情页挂载。
- **行为**：服务详情展示主机 CPU/内存/磁盘/网络当前状态与异常进程；指标来自后端受控采集，不绕过网关。
- **输出**：主机指标作为服务详情的一部分展示（当前状态 + 异常进程）。

### 2. 历史采样与趋势（复用 P5）
- **输入**：主机指标纳入采样器遍历的服务集合。
- **行为**：`MonitorSampler` 定时采集主机指标，写入历史样本表（复用 P5 样本结构或扩展主机指标字段），趋势页自动展示 CPU/内存/磁盘走势。
- **输出**：主机指标历史样本进入历史趋势，服务详情页可看走势。

### 3. 诚实降级
- **输入**：psutil 不可用 / 采样失败。
- **行为**：psutil 缺失或采集失败 → 诚实标注"不可用"，不伪造数值；mock 模式读确定性场景。
- **输出**：确定性降级文案；不可用标量置 null，不用 0 代替缺失。

## 非功能需求
- **安全**：只读本机指标；不经网关的输出一律不进入前端；无凭据进日志/Trace/结果。
- **可靠**：每日志/主机独立降级；采样限时（复用 P5）；不阻塞 API 事件循环。
- **诚实**：未配置/不可用如实标注；指标语义明确（不冒充数据库延迟）。
- **性能**：采样复用 P5 限时机制；psutil 采集不阻塞事件循环。

## 数据与接口影响
- 数据：历史样本表可能新增主机指标字段（CPU/内存/磁盘等标量，方案待 Design）；无服务注册/凭据改动。
- 接口：服务详情/历史接口结构扩展（主机指标字段），既有字段兼容。

- [ ] AC3: 主机指标应被 `MonitorSampler` 定时采样，历史样本进入趋势接口，服务详情页可看 CPU/内存走势。

- [ ] AC5: mock 模式下（`set_active_scenario("S1")`），主机指标返回原 mock 结果，与改动前一致。

## 边界与约束
- 安全边界：只读本机指标；不经网关不输出；脱敏硬约束。
- 降级策略：psutil 不可用/采样失败 → 不可用；mock 模式读场景。
- 兼容性：mock 评测（S1–S4）行为不变；既有服务快照/历史接口字段兼容。
