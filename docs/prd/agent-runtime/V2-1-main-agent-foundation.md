# V2-1 单主 Agent 地基 · PRD

## 背景

V2-0 已合入：主 Agent 用一次性决策图接入了既有 Run 主干，验证了冻结输入、typed 交付、安全投影、失败关闭和 `text.literal_compare@1` 能力。它证明的是“V2 能接进同一条 Run 脊”，不是“能力可以插拔”，也不是“主 Agent 会循环”。

当前代码仍把能力写死在单一文本比较上：任务与决策类型带 `text.literal_compare` 字面量，工具注册按 `text_compare` 分支，单 Run 最多一次工具调用，没有知识型能力，也没有“观察结果后继续决策”的循环。这些是 V2-1 要解决的地基问题。

关联依据：

- [V2 计划骨架](../../进行中/V2-主Agent闭环/方向/计划骨架.md) 的 V2-1 阶段与“一契约 + 两轴”。
- [V2-0 首闭环 Design](../../进行中/V2-主Agent闭环/首闭环/Design.md) 与 [Workpack-审查](../../进行中/V2-主Agent闭环/首闭环/Workpack-审查.md)。
- [产品定义](../../事实源/产品定义.md)、[路线图](../../事实源/路线图.md)、[开发规范](../../事实源/开发规范.md)。

## 目标

1. 主 Agent 通过 ReAct 循环完成一个知识型任务（只读排查手册）和一个执行型任务（文本比较），两类能力共用同一套选择、校验、观测和交付机制。
2. 同一 Run 内可以多步：模型决策 → 加载知识或调用工具 → 观察结果 → 再决策，直到回答、追问、安全失败或预算耗尽。
3. 知识辅助回答与已校验能力结果在公开交付和界面上可区分；知识建议不冒充实时事实。
4. `text.literal_compare@1` 迁移到通用契约后行为不退化；V1 默认入口和 V1 调查链不受影响。

## 用户故事

- 作为研发或运维用户，我想问“慢查询一般怎么排查”，主 Agent 加载内置只读排查手册，给出有步骤的回答，并明确这是知识建议、没有读取我的实时数据。
- 作为用户，我想比较两段文本，主 Agent 调用已注册的比较能力，返回逐行差异；结果与 V2-0 一致。
- 作为用户，我想在会话里看到本次用了哪个能力、走了几步、是否失败或不可用，而不是只看到一段无法核对的文字。
- 作为验收者，我想用固定的 mock 场景和公开 API／界面证据验证两条路径，不需要真实模型、数据库或外部网络。

## 范围

### 做什么

- **Capability 契约 v1**：一个能力必须声明身份与版本、类型（知识型／执行型）、模型可见说明与使用指引、输入与输出契约、所需资源与权限、允许的工具、完成条件与失败语义。
- **能力注册表**：显式注册、按 `capability_id + version` 解析；未知能力或未知版本安全失败；不做扫描、自动发现、热加载或市场。
- **知识型能力**：`ops.readonly_playbook@1`，装一份受管“只读排查手册”。选中后由程序把手册内容装入本次上下文，模型基于手册回答；不调用外部工具，交付标注为知识辅助回答。
- **执行型能力**：把 `text.literal_compare@1` 迁移到通用契约；保留原有输入、规则、结果与验收边界。
- **ReAct 主循环**：每步一次结构化模型决策；决策至少覆盖普通回答、材料追问、加载知识型能力、调用执行型能力；观察结果以 typed 安全摘要返回模型；循环受程序预算限制。
- **交付与展示**：公开交付能区分普通回答、知识辅助回答、材料追问和已校验比较结果；界面显示本次能力、步骤和状态；知识辅助回答必须有明确标注。
- **回归**：V2-0 的比较路径、取消、重跑、幂等、安全投影和 V1 默认入口保持。

### 不做什么（明确排除）

- 不做子 Agent 委派、独立主 Agent 协作、Task／Attempt 控制面、长期记忆、Recovery、分布式调度或跨进程通信。
- 不接真实模型、数据库、Redis、日志系统、Web 搜索或任何外部网络；知识手册是仓库内受管静态内容，不是实时检索。
- 不做 RAG、向量检索、Embedding、MCP 或通用插件市场；不做任意技能目录、用户自定义代码、热加载。
- 不新增服务类型、Connector、凭据方案、权限模型、审批动作或高风险执行。
- 不切换默认录入入口；V1 仍是默认，V2 保持显式切换。
- 不重写整个前端；只增加本次能力、步骤、知识标注和失败／不可用展示。
- 不把“多能力编排”作为本阶段验收项。循环允许自然组合，但本阶段只验收知识路径和比较路径两条独立链路。
- 不新增事件类型或数据库表，除非 Design 证明必要并单独取得用户确认；优先复用现有事件与 JSON 交付。
- 不修改 V1 Coordinator、领域 Agent、历史 fixture 或已归档工作包。
- 不宣称真实 Provider 兼容、真实服务联通或生产可用。

## 功能需求

### 1. Capability 契约

- **输入**：一个能力声明，必须包含：
  - `capability_id` 与 `version`，同一版本只能注册一次；
  - 类型：知识型或执行型；
  - 模型可见的说明与使用指引；
  - 输入契约：本次任务需要哪些输入（例如目标、材料引用、服务引用），哪些是必填；
  - 输出契约：成功交付的类型与必要字段；
  - 所需资源与权限：执行型能力必须声明；知识型能力声明为“无外部资源”；
  - 允许使用的工具：执行型能力声明；知识型能力为空；
  - 完成条件与失败语义；
  - 知识型能力还必须声明受管 Skill 内容的来源与版本。
- **行为**：
  - 注册表按 id + version 解析；重复注册、未知 id、未知版本、类型与声明不一致时安全失败。
  - 主 Agent 只看到已注册能力的安全摘要，不直接读取能力内部实现或资源句柄。
  - 增加一个能力只允许扩展注册、配置和该能力自身的声明；不得要求修改主循环、会话服务或工具网关。
- **输出**：可供模型选择的能力菜单、可被程序校验的能力声明、可被公开投影的能力身份。

### 2. ReAct 主循环

- **输入**：本 Run 的冻结输入（目标、必要上下文、可选材料引用）、已注册能力、程序预算。
- **行为**：
  1. 程序构造安全的模型输入：目标、上下文、能力摘要、材料是否存在及引用；不包含材料原文。
  2. 模型每步返回一个结构化决策，至少支持：
     - 普通回答；
     - 材料追问；
     - 加载一个知识型能力；
     - 调用一个执行型能力。
  3. 程序校验决策：能力是否注册、版本是否匹配、类型是否允许、必填输入是否满足、材料引用是否属于本 Run、预算是否足够。校验失败安全失败，不执行任何工具。
  4. 知识型能力：程序把该能力的受管 Skill 内容装入本次上下文，记录一次安全观察；模型基于该内容继续决策。Skill 内容不可用时，能力标记为不可用，模型可以继续普通回答，但不得声称已加载该能力。
  5. 执行型能力：程序经既有 ToolGateway 调用该能力声明的工具；观察结果只包含安全摘要和 typed 结果引用，不把原始材料、原始异常或凭据返回模型。
  6. 循环在以下任一条件终止：模型给出普通回答、模型要求材料追问、能力返回需交付的结果、发生安全失败、预算耗尽、Run 被取消。
- **输出**：恰好一个 typed 交付或一个封闭安全失败；过程事件只含能力身份、步骤、状态和脱敏摘要。

### 3. 知识型能力：只读排查手册

- **输入**：用户目标；可选会话上下文；不需要文本材料。
- **行为**：
  - 能力被选中后，程序装入受管的“只读排查手册”。手册至少覆盖：慢查询、锁等待／阻塞、连接池、服务健康、日志错误模式、只读原则与何时需要人工升级。
  - 手册内容是仓库内受管静态文本，有版本、有大小上限，不来自用户、不来自网络、不来自实时服务。
  - 模型基于手册组织回答；不得声称读取了实时指标、日志、SQL 结果或服务状态。
  - 交付标记为“知识辅助回答”；界面显示“未读取实时数据”。
  - 手册缺失、损坏或超过大小上限时，该能力标记为不可用；模型可以给出普通回答，但界面必须显示该能力不可用，不得伪造手册内容。
- **输出**：知识辅助回答；不产生比较结果、诊断结果、提案或动作。

### 4. 执行型能力：文本比较迁移

- **输入**：本 Run 的 A／B 材料引用；现有 2000 码点／100 行等限额不变。
- **行为**：
  - 通过通用能力契约被模型选择，经 ToolGateway 执行。
  - 结果仍由确定性程序生成；模型不阅读 A／B 原文，不编写差异块，不用自然语言替代结构化结果。
  - 循环可以在工具返回后让模型继续决策，但比较交付必须来自工具结果，不能来自模型复述。
- **输出**：与 V2-0 相同的已校验比较交付；无差异、有差异、超限、失败和不可用的语义不变。

### 5. 交付、界面与过程视图

- **输入**：循环产生的 typed 交付和过程事件。
- **行为**：
  - 公开交付至少区分：普通回答、知识辅助回答、材料追问、已校验比较结果。
  - 知识辅助回答必须能被界面识别，并显示“知识辅助回答 · 未读取实时数据”；界面的固定标注区域不得把该交付标成“已校验”“已读取”“已诊断”。
  - 已校验比较结果继续显示差异块、行号、引文和能力／规则版本。
  - 界面显示本次使用的能力 id、版本、类型、步骤数和终态；失败与不可用显示安全文案。
  - 过程视图只展示能力、步骤、状态、耗时和脱敏摘要；不展示 CoT、Prompt、原始材料、原始工具输出或原始异常。
- **输出**：用户可理解、可核对的会话结果与过程视图。

### 6. 安全与可观测性

- **输入**：运行期决策、观察、事件、日志。
- **行为**：
  - 所有执行型能力只经既有 ToolGateway；模型不能直接访问 DB、Shell、文件、网络或凭据。
  - 观察结果进入模型前必须收敛为安全摘要；材料原文、原始工具输出、原始异常和凭据不得进入模型观察、事件、日志、导出或公开列表。
  - 知识手册是受管内容，可以进入模型上下文；它不得包含凭据、用户数据或实时服务事实。
  - 失败、超时、预算耗尽、能力不可用和取消都必须如实投影，不得渲染为成功。
  - 新增日志只记录能力 id、步骤、状态和封闭错误码。
- **输出**：安全事件、封闭失败码、可审计的能力使用记录。

## 非功能需求

- **确定性**：相同输入、相同能力版本、相同显式 mock 场景应产生相同交付。
- **限额**（服务端版本化常量；调整需 PRD／Design 更新）：
  - 目标 ≤200 码点；每段材料 ≤2000 码点、≤100 行；上下文 ≤4 条消息、合计 ≤2000 码点；回答 ≤4000 码点。
  - 单个 Skill 内容 ≤4000 码点；超过即能力不可用，不静默截断。
  - 每 Run 最多 6 次模型决策、2 次知识加载、3 次工具调用。
  - 单次模型调用超时 30 秒；单次工具等待 3 秒；Run 总时间预算 120 秒；无自动重试。
- **性能**：本阶段不接外部资源，测试必须可在隔离环境内确定性运行。
- **安全**：默认只读、最小权限、脱敏、超时和参数校验；知识回答与已校验结果必须可区分。
- **兼容性**：V1 默认入口、V1 调查链、V2-0 公开字段和既有数据读取保持；新增字段必须向后兼容。

## 数据与接口影响

- **数据**：
  - 优先不新增表、不新增迁移；能力注册、Skill 内容和循环状态在进程内装配，Run 输入／交付继续使用既有 JSON 扩展表。
  - 若 Design 认为必须新增交付 kind 或新事件类型，必须同时给出迁移、upgrade／downgrade 验证和用户确认；不得静默改既有 CHECK 约束。
- **接口**：
  - 复用现有创建 Run 接口：`runtime_kind=main_agent`，`query` 必填，`text_a`／`text_b` 可选；不新增端点。
  - Run 资源需要以加法方式暴露知识辅助接地信息、能力身份和步骤摘要；既有字段语义不变。
  - Run 详情继续返回本 Run 的冻结输入（用户自己提供的材料）；列表、事件、导出、Trace、审计和 usage 不返回材料原文。
  - 更新 OpenAPI 与前端生成类型；`generated.ts` 只允许重新生成，不手改。
- **事件**：优先复用现有事件类型和脱敏 data 字段；不新增事件类型，除非 Design 明确必要并取得用户确认。

## 验收标准

- [x] AC1：当知识型能力和执行型能力同时注册时，主 Agent 能看到两者的安全摘要，并按 `capability_id + version` 选择；重复注册、未知 id、未知版本或不匹配类型应安全失败，不执行工具。
- [x] AC2：当用户提出一个只读排查问题且不提供材料时，主 Agent 应加载 `ops.readonly_playbook@1`，至少经过两次模型决策后给出知识辅助回答；整个过程不调用工具。
- [x] AC3：当知识辅助回答出现在会话中时，界面的固定标注区域应显示“知识辅助回答 · 未读取实时数据”，且不得把该交付标成“已校验/已读取/已诊断”；模型正文属于用户可见内容，系统不承诺对其中的自然语言做关键词改写，但提示词必须要求模型不得声称读取实时数据。
- [x] AC4：当 Skill 内容缺失、损坏或超过 4000 码点时，该能力应标记为不可用；主 Agent 可以给普通回答，但不得伪造手册内容，界面应显示能力不可用。
- [x] AC5：当用户提供两段文本并要求比较时，主 Agent 应经通用契约调用 `text.literal_compare@1`，返回与 V2-0 相同的已校验比较交付；既有比较测试全部通过。
- [x] AC6：当新增知识型能力或迁移执行型能力时，主循环、会话服务和工具网关不应出现按能力 id 写死的分支；两类能力应走同一套选择、校验、观察和交付路径。
- [x] AC7：当模型决策次数、知识加载次数或工具调用次数超过上限时，Run 应以封闭安全失败结束，不产生部分交付或伪造结果。
- [x] AC8：当单次模型或工具超时、或 Run 总时间预算耗尽时，应安全失败；取消后不得写入迟到交付、助手消息或第二终态。
- [x] AC9：当模型返回未知决策、额外字段、未注册能力、错误版本或不属于本 Run 的材料引用时，应安全失败，零工具执行。
- [x] AC10：模型输入和观察中不应出现 A／B 原文；Run 列表、事件、导出、Trace、审计、usage 和日志不应出现材料原文、原始工具输出、原始异常或凭据。Run 详情仅返回当前 Run 的冻结输入（用户自己提供的材料），用于回看本次输入；该原文不得进入上述其他面。
- [x] AC11：知识辅助回答的公开交付不得被标记为比较结果或诊断结果；普通回答、知识辅助回答和已校验比较结果三者应可区分。
- [x] AC12：界面应显示本次能力 id、版本、类型、步骤数和终态；失败与不可用显示安全文案；过程视图不展示 CoT、Prompt、原始材料或原始工具输出。
- [x] AC13：当 Run 在循环中被取消时，应停止后续步骤，不写入取消后的交付或消息；取消事件和安全终态与现有行为一致。
- [x] AC14：重跑和幂等行为应保持 V2-0 语义：冻结输入可复制、同键重放返回同一结果、未知规则或版本安全失败。
- [x] AC15：V1 默认录入、V1 调查链和既有 48 项会话页行为应保持不变；V2 仍是显式入口。
- [x] AC16：既有公开字段保持向后兼容；新增字段为加法；OpenAPI 和前端生成类型同步；不新增公开端点。
- [x] AC17：本阶段测试不得调用真实模型、数据库、Redis、日志或外部网络；mock 必须在界面与服务端如实标注。
- [x] AC18：若存在迁移，upgrade／downgrade 与约束必须验证；若无迁移，应明确记录“无数据库变更”。
- [x] AC19：后端全量、前端全量、`typecheck`、`build`、`ruff`、`mypy`、`git diff --check` 均通过；敏感字面量扫描无命中。
- [x] AC20：本阶段不得引入子 Agent、多主 Agent、长期记忆、Recovery、RAG／MCP、真实外部连接或 V1 退役。

## 边界与约束

- **安全边界**：执行型能力只经 ToolGateway；只读、最小权限、参数校验、超时、脱敏；模型不直接访问 DB／Shell／文件／网络；知识回答不得冒充实时事实。
- **降级策略**：
  - 模型不可用 → 封闭失败，固定安全文案；
  - 决策无效 → 封闭失败，不重试、不猜测；
  - 能力不可用／Skill 缺失 → 能力标记不可用，可普通回答但不伪造；
  - 工具失败／超时 → 封闭失败或安全不可用；
  - 预算耗尽 → 封闭失败，不交付半成品；
  - 取消 → 取消终态，无迟到写入。
- **兼容性**：V1 默认入口和调查链不变；V2-0 的比较交付、失败码、损坏行安全不可用投影保持；历史数据库记录只读兼容。
- **能力诚实**：知识型与执行型必须在公开交付和界面上可区分；未执行的能力不得出现在结果里；未读取的数据不得由界面标注为已读取。模型正文由提示词约束，系统不做运行时关键词改写。
- **依赖边界**：不新增框架依赖；优先复用现有 LangGraph、BaseAgent、ToolGateway、LLMClient 与事件链。
