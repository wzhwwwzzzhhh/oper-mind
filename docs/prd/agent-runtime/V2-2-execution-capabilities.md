# V2-2 执行型能力与插件性 · PRD

## 背景

V2-1 已完成并合入 main（PR #139）：Capability 契约、ReAct 内核、知识型只读排查手册与公开投影落地，默认入口仍是 V1。V2-1 证明了“同一套契约和循环能跑知识型与执行型两条路径”，但执行型只覆盖了纯计算的 `text.literal_compare@1`，没有触碰真实外部资源，也没有验证“第二个、第三个能力只靠声明和绑定接入”。

V2-2 要证明的是插件性：**一次性扩展能力契约以支持服务/资源输入与结构化结果，然后新增两个不同领域的执行型能力；第二个能力不得再改主循环、会话服务或工具网关。**

本阶段已获用户授权的真实资源：

- 目标库：`gongkar_service_readonly_test`（本地 127.0.0.1:5433，非生产只读测试副本）。
- 只读角色：`opermind_readonly`（已创建；`default_transaction_read_only=on`，仅安全列 SELECT，无 INSERT/UPDATE/DELETE，授予 `pg_monitor` 只读统计权限）。
- 凭据：保存在仓库外的本地凭据文件；运行时通过环境变量/服务注册注入，不进入仓库、日志、Trace、事件、响应或截图。
- 可用数据：`provider_call_logs` 3,649 行（2026-07 至 2026-09）、`feishu_sync_log` 971 行（2026-03 至 2026-06）、`agent_tasks` 15 行；PostgreSQL 健康统计可用。

关联依据：

- [V2 计划骨架](../../进行中/V2-主Agent闭环/方向/计划骨架.md) 的 V2-2 阶段。
- [V2-1 PRD](V2-1-main-agent-foundation.md)（已完成，PR #139）与 V2-1 Design。
- [产品定义](../../事实源/产品定义.md)、[路线图](../../事实源/路线图.md)、[开发规范](../../事实源/开发规范.md)、[架构与开发路径](../../事实源/架构与开发路径.md)。

## 目标

1. 新增两个执行型能力：`service.health_summary@1` 与 `service.log_scan@1`，在同一套 Capability 契约和 ReAct 循环上运行。
2. 一次性扩展契约：支持服务/资源输入槽位、资源声明（PostgreSQL，只读）、结构化结果交付；扩展完成后，第二个能力只靠注册、声明和绑定接入。
3. 用授权真实库完成只读验收：连接池/库大小/错误摘要、provider/飞书日志聚合；明确数据窗口，不把历史数据说成实时监控。
4. 保持 V1 默认入口、V2-0/V2-1 行为、既有 Connector 与工具网关；不新增 Connector 或服务类型。

## 用户故事

- 作为研发或运维用户，我在会话中选择一个已接入的 PostgreSQL 服务，问“这个服务健康吗”，主 Agent 调用健康摘要能力，返回当前连接池、最大连接、库大小、窗口内错误摘要和数据时间范围。
- 作为用户，我问“最近 provider 调用有什么错误”，主 Agent 调用日志扫描能力，按 provider/operation 返回调用量、错误率、错误码分类和 P95 延迟。
- 作为用户，我能看到本次使用的能力、数据窗口、步骤和状态；不会看到原始请求/响应 payload、完整错误消息或连接串。
- 作为用户，如果服务不可用、窗口内没有数据或查询超时，我看到诚实的“不可用/无数据”，而不是伪造的 0 或实时结论。

## 范围

### 做什么

- **契约扩展（一次性）**：
  - 新增服务/资源输入槽位：本次 Run 绑定一个已注册的 `service_id`，由用户在会话中选择，并在受理时冻结；模型不能自行发明、替换或跨 Run 借用服务。
  - 新增资源声明：PostgreSQL、只读、目标服务绑定；执行型能力必须显式声明资源与权限。
  - 新增结构化结果契约：交付形态采用**通用 `structured` kind**，payload 携带 `result_schema` 与 typed result（如 `service_health.v1`、`log_scan.v1`）；主循环按声明投影，不按能力 id 写分支。
  - 该 kind 需要一次迁移修改 `run_deliveries.kind` CHECK；迁移细节、upgrade/downgrade 与约束验证在 Design 中定稿并取得用户确认。
  - 扩展完成后，新增能力只允许改注册、声明、ToolBinding 和结果模型。
- **`service.health_summary@1`**：
  - 输入：冻结的 `service_id`；可选数据窗口（用于错误摘要）。
  - 复用：现有 PostgreSQL 只读健康/连接池工具与库大小统计。
  - 输出：连接总数、活跃/空闲/等待、最大连接、利用率、库大小、窗口内 provider/飞书错误总量、`observed_at`、`data_window`。
  - 当前连接池是实时读取；日志错误摘要按窗口聚合，界面必须显示窗口。
- **`service.log_scan@1`**：
  - 输入：冻结的 `service_id`、`from`/`to`（显式时间窗）、可选 `provider`/`operation`/`status` 过滤。
  - 查询：`provider_call_logs` 安全列聚合（调用量、错误率、错误码、平均/P95 延迟）；`feishu_sync_log` 安全列聚合（成功/失败、错误码分类、耗时）；可选 `agent_tasks` 状态摘要。
  - 输出：计数、错误率、错误码分类、P95 延迟、实际数据时间范围。
  - 不读取、不返回 `request_payload`、`response_payload`、完整 `error_message`、连接串或凭据。
- **只读执行边界**：
  - 应用只使用 `opermind_readonly`，不使用超级用户 `myuser`。
  - 固定参数化 SELECT，只读事务；不提供任意 SQL、写操作、DDL 或通用执行器。
  - 连接超时、语句超时、窗口上限由程序限制；超时/不可用安全降级。
- **公开投影与界面**：
  - Run 资源以加法方式暴露能力身份、数据窗口、结构化结果摘要和状态；不新增端点。
  - 界面显示能力 id/版本/类型、步骤、数据窗口、证据摘要、失败/不可用；不展示原始 payload 或完整错误消息。
  - 明确区分“实时连接池”与“窗口内历史日志”，不伪造实时性。
- **测试与验收**：
  - 确定性 mock 覆盖健康/日志两条路径、无数据、超时、不可用、非法服务、非法窗口、原始列拒绝。
  - 授权真实库做一次只读冒烟；可使用带标记的合成日志行覆盖当前时间窗口，但不修改既有业务行。
  - V1 默认入口、V1 调查链、V2-0/V2-1 行为回归。

### 不做什么（明确排除）

- 不新增 Connector、服务类型、网络协议或真实外部目标；只使用已授权的 `gongkar_service_readonly_test` 与现有 PostgreSQL Connector。
- 不做任意 SQL、通用查询器、写操作、DDL、审批动作或高风险执行；不授予应用写权限。
- 不读取或暴露 `request_payload`、`response_payload`、完整 `error_message`、原始日志行、连接串、凭据。
- 不做子 Agent、多主 Agent、长期记忆、Recovery、RAG/向量/MCP、分布式调度。
- 不切换默认入口；V1 仍是默认，V2 显式。
- 不新增依赖、不重写前端、不改 V1 Coordinator/领域 Agent/历史 fixture。
- 不把历史日志窗口包装成实时监控；不把不可用/无数据渲染成成功。
- 不新增公开端点；结构化交付只新增一个通用 `structured` kind 及其迁移，不按能力各建 kind；迁移细节先经 Design 并取得用户确认。

## 功能需求

### 1. 服务输入与资源绑定

- **输入**：用户在会话中选择一个已注册 PostgreSQL 服务；受理时把 `service_id` 写入本 Run 的冻结输入。
- **行为**：
  - 程序校验服务已注册、类型为 PostgreSQL、只读、当前可用；未知/未授权服务安全失败，不建立连接。
  - 模型只看到服务的显示名/摘要，不看到 DSN、host/port、凭据或任意服务列表。
  - 模型不能替换 `service_id`；能力调用必须使用本 Run 冻结的服务绑定。
  - 重跑复用同一冻结服务；不得在重跑时自动切换到其他服务。
- **输出**：冻结的服务引用、可校验的能力输入、可投影的服务显示信息。

### 2. 健康摘要能力

- **输入**：冻结的 `service_id`；可选窗口（默认最近 30 天，最大 366 天）。
- **行为**：
  - 当前连接统计：总数、活跃、空闲、等待、最大连接、利用率。
  - 数据库大小。
  - 窗口内 provider 调用错误总量与飞书同步失败总量（高等级计数，不展开错误码明细；明细由日志扫描能力承担）。
  - 返回 `observed_at` 与 `data_window`；连接池为当前读取，日志摘要为窗口聚合。
- **输出**：结构化健康摘要；无原始日志/payload/凭据。

### 3. 日志扫描能力

- **输入**：冻结的 `service_id`、显式 `from`/`to`、可选过滤。
- **行为**：
  - `provider_call_logs` 按 provider/operation 聚合调用量、错误码分布、平均/P95 延迟。
  - `feishu_sync_log` 按 table/status 聚合成功/失败、错误码分类、耗时。
  - 可选 `agent_tasks` 状态/失败子任务摘要。
  - 返回实际数据时间范围；窗口内无数据时显式 `no_data`。
  - `error_message` 只提取封闭错误码/分类；无法识别时归为 `unknown`，不返回原文。
- **输出**：结构化日志扫描结果；不包含原始 payload、完整错误消息或凭据。

### 4. 只读、超时与降级

- **行为**：
  - 应用只使用 `opermind_readonly`；连接设置 `default_transaction_read_only=on`，查询在只读事务中运行。
  - 固定参数化 SELECT；拒绝任意 SQL、写语句和未知表/列。
  - 连接超时 3 秒、语句超时 3 秒；超时/连接失败返回安全不可用，不重试风暴。
  - 窗口超过上限、时间倒置、服务未知、列权限不足均安全失败。
  - 数据库角色即使被误授予写权限，应用也不发出写语句；验收包含原始 payload 列拒绝和写操作拒绝的负向测试。
- **输出**：封闭失败码、能力不可用状态、诚实空态。

### 5. 公开投影与界面

- **行为**：
  - Run 资源以加法方式暴露能力 id/版本/类型、步骤、数据窗口、结构化结果摘要、不可用状态。
  - 健康摘要展示“当前连接池”和“窗口内错误摘要”两个区块，并标注 `observed_at` / `data_window`。
  - 日志扫描展示窗口、调用量、错误率、错误码分类、P95；不展示原始日志行或完整错误消息。
  - 失败/超时/无数据显示安全文案；不伪造 0 或“健康”。
- **输出**：用户可核对的结果与安全过程视图。

### 6. 重跑、幂等与版本

- **行为**：
  - `service_id` 与时间窗口进入冻结输入/重跑指纹；同键重放返回同一结果，重跑复用同一服务。
  - 能力版本、结果 schema 版本和规则版本显式记录；未知版本安全失败。
  - 能力被移除或资源不可用时，在该 Run 的选择/执行步骤安全失败。
- **输出**：可追溯的冻结输入与结果版本。

## 非功能需求

- **只读与最小权限**：应用角色无 CREATE/INSERT/UPDATE/DELETE；只授予安全列 SELECT；`pg_monitor` 仅用于只读统计。
- **凭据**：只从仓库外本地凭据文件/环境变量或服务中心加密 DSN 注入；不进入仓库、日志、Trace、事件、结果、截图或接口响应。
- **限额**：
  - 默认窗口 30 天，最大 366 天；时间倒置/超限安全失败。
  - 连接超时 3 秒；语句超时 3 秒；单次查询失败不自动重试。
  - 每 Run 的模型决策/工具调用预算沿用 V2-1；新增能力不扩大预算。
- **确定性**：mock 场景固定；真实库冒烟记录环境、时间窗口和原始输出摘要，不宣称可重复的毫秒级结果。
- **兼容性**：V1 默认入口、V1 调查链、V2-0/V2-1 字段与行为保持；新增字段为加法。
- **可观测性**：事件只含能力 id/版本/类型、步骤、状态、窗口和脱敏摘要；不含原始 SQL、DTO、payload、错误原文或凭据。

## 数据与接口影响

- **数据**：
  - 复用既有 `run_inputs` / `run_deliveries` JSON 扩展表；`service_id`、窗口等冻结输入进入快照。
  - 结构化结果使用通用 `structured` 交付（payload 带 `result_schema` 与 typed result），只加一个 kind；需要一次迁移修改 `run_deliveries.kind` CHECK，并验证 upgrade/downgrade，取得用户确认。不按能力各建 kind。
  - 不新增业务表、不修改目标库结构；验收合成数据只插入带标记的新行，不更新/删除既有行。
- **接口**：
  - 复用现有创建 Run 接口，增加可选 `service_id` 与窗口输入；不新增端点。
  - Run 资源增加结构化结果/数据窗口/能力归属的加法字段；既有字段语义不变。
  - 更新 OpenAPI 与前端生成类型；`generated.ts` 只允许重新生成。
- **事件**：优先复用现有事件类型和脱敏 data 字段；新增事件类型需 Design 与用户确认。

## 验收标准

- [ ] AC1：当两个执行型能力注册时，主 Agent 能看到安全摘要并按 `capability_id + version` 选择；未知服务、未授权服务、错误类型或未知能力应安全失败，不建立连接、不执行工具。
- [ ] AC2：当用户在会话中选择已授权的 PostgreSQL 服务并请求健康摘要时，应返回连接池、最大连接、库大小、窗口内错误摘要、`observed_at` 和 `data_window`；不得返回原始 SQL、payload 或凭据。
- [ ] AC3：当用户请求日志扫描并给出显式时间窗时，应按 provider/operation 返回调用量、错误率、错误码分类和 P95，并按 table/status 返回飞书同步摘要；不得返回原始 payload 或完整错误消息。
- [ ] AC4：当窗口内没有数据时，应返回显式 `no_data`；当服务不可用、连接失败或语句超时时，应返回安全不可用；不得伪造 0、健康结论或实时性。
- [ ] AC5：当应用执行查询时，只读角色应处于 `default_transaction_read_only=on`；原始 payload 列 SELECT 应被拒绝；INSERT/UPDATE/DELETE 应被拒绝；应用不得发出写语句。
- [ ] AC6：当应用配置真实服务时，应使用 `opermind_readonly`，不得使用 `myuser`；凭据不得出现在仓库、日志、Trace、事件、结果、截图或接口响应。
- [ ] AC7：当新增第二个执行型能力时，只允许改注册、声明、ToolBinding 和结果模型；主循环、会话服务、工具网关不得出现按能力 id 写死的分支。
- [ ] AC8：界面应显示本次能力 id/版本/类型、步骤、数据窗口、结构化结果摘要与状态；不得展示原始 payload、完整错误消息或 CoT/Prompt。
- [ ] AC9：服务引用应在受理时冻结并进入重跑指纹；重跑不得切换到其他服务，模型不得替换 `service_id`。
- [ ] AC10：V1 默认入口、V1 调查链、V2-0/V2-1 既有行为应保持不变；不新增 Connector、服务类型或授权外目标。
- [ ] AC11：当新增通用 `structured` kind 时，应通过一次性迁移扩展 `run_deliveries.kind` CHECK；upgrade/downgrade 与约束必须验证，并取得用户确认；不得静默修改 CHECK，也不得按能力各建 kind。
- [ ] AC12：测试应使用确定性 mock；授权真实库冒烟只读执行；合成数据只插入带标记的新行，不修改既有行；负向测试覆盖原始列拒绝、写拒绝、超时和不可用。
- [ ] AC13：后端全量、前端全量、`typecheck`、`build`、`ruff`、`mypy`、`git diff --check` 均通过；敏感字面量扫描无命中。
- [ ] AC14：本阶段不得引入子 Agent、多主 Agent、长期记忆、Recovery、RAG／MCP、真实目标外访问或 V1 退役。
- [ ] AC15：健康摘要与日志扫描必须显示数据窗口；历史日志不得被描述为实时监控，当前连接池与窗口内错误摘要必须分区展示。
- [ ] AC16：错误码/错误分类应使用封闭枚举或安全归类；无法识别的错误归为 `unknown`，不得透传完整错误消息。
- [ ] AC17：时间窗超过上限、时间倒置、服务未知或列权限不足时，应安全失败；不得重试风暴。
- [ ] AC18：公开结果 schema 与能力版本应可追溯；未知 schema/能力版本安全失败。

## 边界与约束

- **真实资源授权记录**：
  - 目标：`gongkar_service_readonly_test`，本地非生产只读测试副本；不访问 `gongkar` 主库或其他库。
  - 只读角色：`opermind_readonly`；凭据在仓库外；应用不持有管理员账号。
  - 只读边界：固定 SELECT、只读事务、安全列；不写、不 DDL、不读 payload/完整错误消息。
  - 合成数据：仅插入带 `opermind_v2_test` 标记的新行，验收后可清理这些标记行；不修改既有业务数据。
- **降级策略**：服务不可用/超时 → 安全不可用；无数据 → `no_data`；未知错误码 → `unknown`；不支持的能力/版本 → `CAPABILITY_UNAVAILABLE`。
- **兼容性**：V1 默认入口、V1 调查链、V2-0/V2-1 行为与字段保持；新增字段加法。
- **能力诚实**：实时连接池、窗口日志、历史数据三类必须可区分；未读取/未执行的数据不得出现在结果里。
- **依赖边界**：不新增框架依赖；复用现有 PostgreSQL Connector、ToolGateway、ReAct 内核与 Run 主脊。

## 完成定义（DoD）

- [ ] 全部 AC 通过。
- [ ] 两个能力在同一 ReAct 内核上运行；第二个能力没有改主循环/会话/工具网关。
