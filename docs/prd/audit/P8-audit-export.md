# 审计导出——审计活动留档与外部核验 · PRD

## 背景

审计/操作记录已交付跨服务跨会话活动检索（`GET /audit/activities`，P8 issue #62）：调查 Run + 受控动作里程碑事件的安全摘要分页列表，支持时间窗/服务/类型/结果过滤，复用 runs 与 action_events 既有表，无新增持久化。但**无法导出**审计记录用于留档或外部核验（`docs/接口清单.md` 汇总表审计行："导出/报表（另行排期）"）。

现状：`GET /audit/activities` 只返回当前页（cursor 分页），前端只能一页页看，没有"按条件导出全量"的入口；审计数据是合规审查与安全留痕的关键资产（`docs/产品定义.md` §4 安全治理层"审计"），留档与核验需要可导出的安全快照。

关联：`docs/接口清单.md`（汇总表审计行）、`docs/prd/audit/P8-audit-activity-log.md`（#62，检索已交付）、`docs/design/audit/P8审计操作记录Design.md`（已确认架构方案）、`docs/产品定义.md` §4（安全治理层审计）、`docs/开发规范.md` §4/§5（脱敏与留痕纪律）。

## 目标

1. 运维能按与 `GET /audit/activities` **相同的过滤条件**导出审计活动全量（或受上限约束）到文件，用于留档与外部核验。
2. 导出内容沿用**同一套安全摘要投影**：不含 CoT/Prompt/原始工具输出/原始 SQL/原始异常/凭据，审批人字段如实"未记录"。
3. 导出为**确定性、可复现**格式（CSV 或 Markdown/JSON，Design 定），带明确的导出元信息（时间、条件、条数）。

## 用户故事

作为运维工程师，季度合规核验需要本季度全部审计活动记录，应能按时间窗一键导出为文件（CSV/文档）——以便存档备查，且导出内容与审计页看到的安全摘要一致，不含敏感原始数据。

## 范围

### 做什么
- 新增 `GET /audit/export`：按与 `GET /audit/activities` 相同的过滤条件（from/to、service_id、action_type、result）导出审计活动，返回可下载文件（格式 Design 定：CSV / Markdown / JSON 选一或组合）。
- 导出条数受上限约束（如单次导出 ≤ N 条或分片导出，Design 定），超限明确提示，不返回截断不标明的半截文件。
- 导出内容与列表同构（同一资源投影与脱敏纪律），附带导出元信息（导出时间、过滤条件、条数、标注"估算/快照"）。
- 前端审计页新增"导出"入口（带当前过滤条件），下载导出文件，失败/空结果诚实提示。

### 不做什么（明确排除）
- 不做报表/图表/统计汇总（本 PRD 只做**明细导出**；聚合报表另行排期）。
- 不做定时导出 / 邮件发送 / 归档订阅（无告警通道，`docs/接口清单.md` 刻意不做）。
- 不导出原始事件、Trace 内部事件、CoT/Prompt、原始工具输出、原始异常、凭据/DSN/`sk-`。
- 不新增持久化/迁移（复用既有 runs/action_events 数据，导出为只读快照）。
- 不改变 `GET /audit/activities` 契约与行为。
- 不做身份/权限模型（`docs/产品定义.md` §7 未决）。

## 功能需求

### 1. 审计导出（GET /audit/export）
- **输入**：与 `GET /audit/activities` 相同的可选过滤（from/to、service_id、action_type、result）+ 导出格式（Design 定，如 `?format=csv|md|json`）。
- **行为**：
  - 按过滤条件导出审计活动全量（受条数上限约束，Design 定上限与分片策略）。
  - 每项内容与列表资源同构（Run 项：类型/时间/服务/会话/摘要/严重度/置信度/提案与验证状态；Action 项：类型/时间/审批人"未记录"/动作摘要等），沿用脱敏纪律。
  - 导出头/元信息：导出时间、过滤条件、条数、快照标注。
  - 无匹配记录 → 明确空态（如空文件 + 元信息"0 条"），不抛错。
  - 超上限 → 明确提示超限（建议收窄时间窗），不返回截断未标明的文件。
- **输出**：可下载的导出文件（Content-Disposition 附件）。

### 2. 前端导出入口
- **输入**：审计操作记录页。
- **行为**：提供"导出"按钮，携带当前过滤条件触发导出下载；导出中展示进行态；空结果/超限/失败诚实提示。
- **输出**：下载的导出文件；空态/失败态诚实展示。

## 非功能需求
- **安全**：导出沿用列表脱敏纪律——不含凭据/DSN/`sk-`/原始证据/CoT/异常详情；导出前对敏感字面量做兜底脱敏。
- **诚实**：空结果返回空态；超限明确提示；导出元信息如实（时间/条件/条数/快照标注）；审批人"未记录"如实。
- **性能**：导出为批量只读查询 + 流式写出（Design 定），大结果集受上限约束，不一次性撑爆内存。
- **确定性**：相同条件重复导出，内容一致（稳定排序，与列表排序一致）。
- **兼容性**：`GET /audit/activities` 契约不变；导出不改变留痕。

## 数据与接口影响
- 数据：无新增持久化、无迁移（复用 runs/action_events 既有数据，只读快照）。
- 接口：新增 `GET /audit/export`；既有审计检索契约不变。

## 验收标准
- [ ] AC1: 当请求 `GET /audit/export` 时，应返回可下载的导出文件，内容与列表同构的安全摘要。
- [ ] AC2: 当带过滤条件导出时，应只包含匹配条件的审计活动（与列表过滤语义一致）。
- [ ] AC3: 当无匹配记录时，应返回明确空态（0 条元信息），不抛错。
- [ ] AC4: 当结果超过上限时，应明确提示超限，不返回截断未标明的半截文件。
- [ ] AC5: 导出文件不得包含 CoT、Prompt、原始工具输出、原始 SQL、原始异常、凭据、`sk-` 或完整 DSN。
- [ ] AC6: 审批人字段应如实"未记录"（无身份模型下不得伪造）。
- [ ] AC7: 导出文件应含导出元信息（导出时间、过滤条件、条数、快照标注）。
- [ ] AC8: 相同条件重复导出，内容应一致（确定性）。
- [ ] AC9: 前端审计页应提供"导出"入口，携带当前过滤条件，空/超限/失败态诚实展示。
- [ ] AC10: 回归 —— 既有 `test_audit_api.py` 相关全绿；前端 `typecheck`/`test`/`build` 通过。

## 边界与约束
- 安全边界：只读导出，沿用脱敏纪律；不暴露凭据/原始证据/CoT。
- 降级策略：空结果 → 空态；超限 → 明确提示；读取失败 → 明确错误。
- 兼容性：`GET /audit/activities` 契约不变；导出不改变留痕与检索行为。

## 开放问题
1. **格式**：CSV / Markdown / JSON 选哪种（或组合）？推荐 CSV（留档核验通用）+ Markdown（人读），Design 定。
2. **条数上限**：单次导出上限与分片策略（如单次 ≤ 5000 条，超出建议收窄时间窗）？推荐明确上限 + 提示，Design 定。
3. **导出字段集**：与列表资源完全一致，还是精简字段集？推荐与列表一致（同投影），Design 定。
4. **导出排序**：与列表排序一致（time desc, id desc）？推荐一致，Design 定。
