# 会话管理——全局 Run 列表与会话搜索 · PRD

## 背景

会话工作台是产品主入口（`docs/产品定义.md` §2.1），但管理视角有两个缺口（`docs/接口清单.md` 第一大模块"缺少"表）：

1. **无全局 Run 列表**。只有 `/sessions/{id}/runs`（单会话下）和 `/services/{id}/activities`（单服务下），无法跨会话跨服务看"最近所有调查"。接口清单标注影响："无法跨会话跨服务看最近所有调查。"
2. **会话搜索缺失**。会话多了只能靠 cursor 翻。侧栏那个 `Ctrl K` 提示目前是假的（`docs/完善清单.md` P1-12："Ctrl K 快捷键提示，全项目无键盘监听"）。

`docs/prd/session/P8-workbench-loop-closure.md`（已确认 #54）覆盖了独立消息/取消 Run/全局提案列表，明确排除"全局 Run 列表 `GET /runs` 与会话搜索（另行排期）"——本 PRD 是它的后继：补齐这两个管理视角缺口。两者都是只读检索能力，切口独立，可作同一工作包。

关联：`docs/接口清单.md`（第一大模块缺表）、`docs/prd/session/P8-workbench-loop-closure.md`（#54，明确排除本 PRD 内容）、`docs/完善清单.md` P1-12（Ctrl K 假提示）、`docs/产品定义.md` §2.1（会话主入口）。

## 目标

1. 用户能**跨会话跨服务**查看最近的调查 Run（含状态、时间、关联服务/会话），无需逐会话翻。
2. 用户能按标题**搜索会话**，侧栏 `Ctrl K` 成为真实的会话切换入口。
3. 两者均为只读检索，与既有 cursor 分页/脱敏纪律一致。

## 用户故事

- 作为用户，我想看到"最近所有调查"并按服务/状态筛选，应有一个跨会话的 Run 列表——以便快速定位某次调查，而不是记得它在哪个会话里。
- 作为用户，会话很多时，我应按 `Ctrl K` 输入标题关键字跳转到对应会话——以便快速切换，不靠翻页。

## 范围

### 做什么
- 全局 Run 列表：新增 `GET /runs`（跨会话跨服务，cursor 分页，支持状态/服务过滤）。
- 会话搜索：`GET /sessions` 增加 `q`（标题关键词）过滤参数，或新增独立搜索接口（Design 定）。
- 前端适配：会话侧栏"最近会话"区域提供搜索框；`Ctrl K` 聚焦搜索框（真实可用）；新增"最近调查"入口展示全局 Run 列表。

### 不做什么（明确排除）
- 不做消息编辑/删除（接口清单欠账，另行排期）。
- 不做重跑/重新生成（接口清单欠账，另行排期）。
- 不做会话导出（接口清单欠账，另行排期）。
- 不改变既有 `GET /sessions` / `GET /sessions/{id}/runs` 的既有契约与行为（搜索是新增参数，兼容扩展）。
- 不做跨会话的消息全文搜索（只搜会话标题，不搜消息内容）。
- 不暴露证据原文、工具输出、CoT/Prompt 或凭据。

## 功能需求

### 1. 全局 Run 列表（GET /runs）
- **输入**：可选状态过滤（queued/running/succeeded/failed/cancelled）、service_id 过滤、cursor 分页。
- **行为**：跨会话跨服务返回 Run 安全摘要列表（run id/状态/发起时间/关联会话 id 与标题/关联服务/错误摘要）；按状态或服务过滤时只返回匹配项；无匹配返回空列表。
- **输出**：Run 分页列表；点击某项进入既有 Run 详情。

### 2. 会话搜索
- **输入**：搜索关键词（标题匹配），配合 cursor 分页。
- **行为**：按会话标题做关键词匹配（复用既有会话列表的脱敏/分页纪律）；无匹配返回空列表；关键词非法（超长/控制字符）返回明确错误。
- **输出**：匹配会话列表（与既有 `GET /sessions` 响应结构一致）。

### 3. 前端适配
- **输入**：会话侧栏"最近会话"区域、全局导航。
- **行为**：侧栏提供搜索框；`Ctrl K` 聚焦搜索框（真实键盘监听，替代 P1-12 假提示）；新增"最近调查"入口展示全局 Run 列表。
- **输出**：可搜索的会话侧栏 + 全局 Run 列表页。

## 非功能需求
- **性能**：列表为库内查询 + 脱敏收敛，分页限长；搜索为标题匹配，秒级。
- **诚实**：无匹配/空列表诚实空态；搜索不可用时如实提示。
- **安全**：全局 Run 列表与搜索结果均不含证据原文、工具输出、CoT/Prompt、凭据/DSN/`sk-`。
- **可靠**：过滤参数非法返回明确错误；单会话无记录不影响整体。

## 数据与接口影响
- 数据：无新增持久化、无迁移（复用 sessions / runs 既有表）。
- 接口：新增 `GET /runs`；`GET /sessions` 增加可选 `q` 参数（兼容扩展，既有调用不受影响）。

- [ ] AC3: 当用 service_id 过滤 `GET /runs` 时，应只返回该服务的 Run；不存在的 service_id 返回空列表不抛错。

- [ ] AC7: 搜索关键词非法（超长/控制字符）时返回明确错误。
- [ ] AC8: 前端会话侧栏应提供搜索框，`Ctrl K` 聚焦搜索框（真实可用，替代 P1-12 假提示）。

## 边界与约束
- 安全边界：只读检索；脱敏纪律与既有会话/Run 列表一致；不暴露凭据/原始数据。
- 降级策略：无匹配 → 空态；参数非法 → 明确错误；搜索不可用 → 如实提示。
- 兼容性：既有 `GET /sessions` / `GET /sessions/{id}/runs` 契约不变；mock 模式行为一致。

## 开放问题
1. **会话搜索实现方式**：`GET /sessions` 加 `q` 参数（兼容扩展）还是独立 `GET /sessions/search`？→ 推荐前者（复用既有分页/脱敏），Design 定。
2. **`Ctrl K` 交互范围**：聚焦搜索框还是弹出命令面板（含新建会话/搜索/跳转）？→ 推荐首版聚焦搜索框，命令面板后续。
3. **全局 Run 列表排序**：按发起时间倒序（推荐），是否支持其他排序？→ Design 定。
