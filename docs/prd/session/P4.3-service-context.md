# 会话服务上下文贯通与服务选择 · PRD

## 背景
P4 已让服务中心快照连真实 PostgreSQL（服务 `postgres-production`，`PostgresServiceConnector`），
并有 `POST /services/{service_id}/sessions` 创建"服务上下文会话"的入口。
但服务上下文目前只停在**会话表字段**，没有贯通到诊断执行链路：

1. **service_id 白名单与真实服务不一致**：`SessionData` 校验器与数据库 CHECK 约束仍只认
   `order-service`（旧订单演示服务），而真实注册服务是 `postgres-production`。结果是
   `create_service_session("postgres-production")` 建会话会被拒绝——从服务中心发起调查的链路实际是断的
   （现网测试未覆盖这条路径，尚未暴露）。
2. **Run 执行链路完全不消费服务上下文**：`CreateRunCommand` 无 service_id；
   `DiagnosisExecutor.stream(query)` 只传 query；DBAgent 工具按模式固定走
   `data/mock_db.py`（真实模式下的真库接入是 P4.2 的范围）。会话绑定了哪个服务，调查并不知道。
3. **普通会话工作台没有服务选择入口**：只有服务中心能发起服务绑定调查；会话工作台首页
   快捷问题与 `create_session({title})` 都不带 service_id。路线图第二阶段"服务选择与服务上下文"
   只落地了一半。

关联：`docs/路线图.md`（第二阶段"服务选择与服务上下文"、服务中心子骨架）、
`docs/产品定义.md`（会话主入口、选择或关联已接入服务、受控 Tool/Connector）、
`docs/P4.2DBAgent真库Design.md` 与 `docs/prd/session/P4.2-db-agent-real.md`（真实模式 DBAgent 工具接真库，本 PRD 前置）。

## 目标
1. 会话能关联已接入服务（service_id 贯通：会话 → Run → 执行器 → 内核 → DBAgent 工具）。
2. 会话工作台与服务中心都能选择目标服务发起只读调查。
3. 服务上下文只贯通 DB Agent；Server/Log 不假装按服务连接。

## 用户故事
作为运维工程师，我从服务中心或会话工作台选择一个已接入的 PostgreSQL 服务并发起慢查询调查，
应看到**针对该服务**的只读调查，而不是演示假数据或固定某个服务的查询。

## 范围

### 做什么
- 修复 service_id 白名单：合法服务集从静态服务注册表派生，放开 `postgres-production`。
- 服务上下文贯通 Run 执行链路：会话 service_id 带入 Run → 执行器 → 内核 → DBAgent 工具，
  工具按会话绑定服务从注册表取只读 Connector 连接。
- 会话工作台首页发起调查时提供服务选择入口；服务中心"发起调查"入口保留。
- mock 模式（`api_key == mock`）行为完全不变，S1–S4 评测确定性不受影响。

### 不做什么（明确排除）
- 不做 Server / Log Agent 的服务上下文贯通（无真实服务 Connector，不假装按服务连接）。
- 不做跨服务联合调查（P6+）。
- 不做会话中途切换服务 / 服务上下文编辑。
- 不做服务选择权限管理与多租户（后续阶段）。
- 不改 mock 数据源（`data/mock_db.py`、`data/scenarios.py`）与 S1–S4 评测路径。
- 不新增凭据/配置（复用 `OPERMIND_PG_DSN`）。

## 功能需求

### 1. service_id 合法值集（修复不一致）
- **输入**：服务会话创建 / 普通会话创建时的 `service_id`。
- **行为**：合法值集由静态服务注册表（已注册 Connector 的 id）派生；`postgres-production` 合法，
  `order-service` 不再作为校验基线。
- **输出**：未注册的 service_id 被拒绝；已注册的 service_id 可建会话。

### 2. 服务上下文贯通 Run 执行链路
- **输入**：会话绑定的 service_id。
- **行为**：
  - Run 接受并持久化其来源会话的 service_id。
  - 执行器按 service_id 从注册表解析只读 Connector；解析失败时安全降级，不抛异常炸会话。
  - DBAgent 工具按会话绑定服务连接真实库（真实模式下）；mock 模式行为不变。
  - 未绑定 service_id 的会话，DB 相关调查被拒绝并提示先选择目标服务；Server/Log 调查不依赖服务上下文，行为不变。
  - 服务未配置（无 DSN）时，工具返回诚实"未配置"降级；连接失败/超时返回"不可用"，不暴露异常详情。
- **输出**：针对绑定服务的只读调查结果。

### 3. 前端服务选择入口
- **输入**：用户从会话工作台首页或服务中心发起调查。
- **行为**：用户可选已接入服务；选定后该会话绑定该 service_id，预填问题与调查都针对该服务。
- **输出**：带服务上下文的会话与调查发起；会话页展示本次调查针对的服务。

## 非功能需求
- **性能**：工具调用限时复用 P4 引擎超时（3s），超时降级为"不可用"。
- **安全**：只读；参数化；无凭据/DSN 外泄；工具输出经网关 `desensitize` 兜底。
- **可靠**：无 DSN/连接失败/服务未注册均降级，不抛异常炸会话。
- **诚实**：未配置/不可用状态如实展示，不伪造服务绑定。

## 数据与接口影响
- 数据：`sessions.service_id` 字段与约束调整（CHECK 约束随白名单放开）；Run 持久化补充 service_id 上下文。
- 接口：普通会话创建请求可携带 service_id；Run 资源新增 service_id 字段，会话页可展示本次调查针对的服务。**含数据库迁移。**

- [ ] AC4: 会话工作台首页发起调查时可选择已接入服务，创建的会话绑定该 service_id。
- [ ] AC5: 服务中心"发起调查"入口保留，行为与 AC2 一致。

- [ ] AC12: 当 Run 资源包含 service_id 时，会话工作台应展示本次调查针对的服务；未绑定时不展示假服务。

## 边界与约束
- 安全边界：纯只读，无写路径；service_id 只能来自静态注册表，不接受运行时动态服务定义。
- 降级策略：未配置 → "未配置"；连接失败/超时 → "不可用"；均不抛异常。
- 兼容性：mock 评测（S1–S4）行为不变；既有服务快照接口契约不变；DBAgent 真实模式接入为 P4.2 前置。

## 已确认决策
1. 普通会话未选择服务时：拒绝发起 DB 相关调查（诚实提示先选择目标服务）；Server/Log 调查不依赖服务上下文，行为不变。
