# 日志真实源接入 · PRD

## 背景

Log Agent 的日志分析目前**全部走 mock 场景数据**：`SearchLogsTool` / `AggregateErrorsTool` / `QuerySlowLogTool` 从 `data/scenarios.py` 的当前激活场景读取日志（`active_or_default().logs`），真实模式下也返回演示假日志，不做任何真实日志源访问。

现状缺口：运维接入服务后，无法从产品主链分析**真实日志**（错误模式 / 超时 / 异常关联）；日志分析只能靠人工 `grep` 或第三方日志系统，未进产品主链。这与 P4.2（DB Agent 接真库）、P6-redis（Redis 只读监控）同为"把技术切片接入真实源"的诚实化方向——日志是路线图第三阶段明确列出的能力（"日志：错误模式、超时、异常关联"）。

关联：`docs/产品定义.md`（Connector/Tool 受控访问日志源）、`docs/路线图.md`（第三阶段"日志：错误模式、超时、异常关联"）、`docs/开发规范.md`（凭据只走环境变量、只读边界、脱敏）、`backend/src/agents/log_agent.py`、`backend/src/tools/log_tools.py`。

## 目标

1. Log Agent 在真实模式下分析**真实日志源**（错误模式 / 超时 / 异常关联），mock 模式行为不变。
2. 日志源经受控 Connector 接入，只读、脱敏、限时、凭据零落库。
3. 复用既有会话 → Run → Log Agent → 受控 Tool 链路，不新增独立入口。

## 用户故事

作为运维工程师，我在会话里问"服务最近为什么有大量 timeout"，应看到针对**真实日志源**的只读分析结果（错误聚合 / 超时模式），而不是演示假日志——以便定位真实故障根因。

## 范围

### 做什么
- 新增日志源 Connector（真实日志文件 / 日志接口，具体方案待 Design），实现只读检索、错误聚合、慢查询/超时关联。
- 日志检索按会话绑定服务上下文取日志源（复用 service_id 贯通）；未配置日志源诚实降级。
- 日志内容经网关脱敏兜底（凭据/DSN/`sk-` 不进 Trace、结果、日志）。
- mock 模式（`api_key == mock`）行为完全不变，S1–S4 评测确定性不受影响。

### 不做什么（明确排除）
- 不做日志写入、轮转、删除或任何非只读日志操作。
- 不做前端直连接日志源；日志访问只经后端显式注册的 Connector/Tool。
- 不新增独立"日志中心"页面（沿用会话工作台调查入口）。
- 不接外部日志系统（ELK / Loki / CloudWatch 等，后续阶段，需单独 Design）。
- 不改 mock 数据源与 S1–S4 评测路径。

## 功能需求

### 1. 日志源接入与凭据
- **输入**：日志源配置（经环境变量注入，具体命名待 Design）。
- **行为**：Log Agent 真实模式经受控 Connector 访问配置的日志源；未配置 → `not_configured`；连接失败/超时 → `unavailable`；只读，不做任何写操作。
- **输出**：日志源按配置接入；未配置实例诚实降级。

### 2. 日志只读检索与分析
- **输入**：用户会话中的日志检索/错误聚合/超时关联问题。
- **行为**：按关键字/时间范围检索真实日志；聚合错误类型与频率；关联慢查询/超时模式。结果脱敏后进入 Agent 上下文。
- **输出**：针对真实日志源的只读分析结果（命中数 / 错误聚合 / 超时模式）。

### 3. 诚实降级与脱敏
- **输入**：未配置 / 连接失败 / 超时 / 含凭据的日志行。
- **行为**：未配置 → `not_configured`；失败/超时 → `unavailable`（不暴露异常详情）；日志片段经网关 `desensitize` 兜底，凭据/DSN 一律替换。
- **输出**：确定性降级文案；凭据/原始异常不进 Trace、结果、日志。

## 非功能需求
- **安全**：只读；凭据只走环境变量；无凭据/DSN/原始日志进日志、Trace、结果、前端；日志行脱敏兜底。
- **可靠**：每日志源独立降级；限时（复用网关 3s）；不阻塞 API 事件循环。
- **诚实**：未配置/不可用如实标注，不伪造日志内容；mock 模式行为不变。

## 数据与接口影响
- 数据：无新增持久化（沿用既有 Run/Trace）；无迁移（日志源为配置驱动，非数据库）。
- 接口：无新增公开接口；沿用既有会话/Run/工具链路；若日志源需新 Tool 契约，随 Design 定。

## 验收标准
- [ ] AC1: 当日志源已配置且真实模式时，`search_logs` 等日志工具应返回真实日志源的只读检索结果，而非场景 mock 数据。
- [ ] AC2: 当日志源未配置时，日志工具应返回"未配置"降级文案，不崩溃、不伪造。
- [ ] AC3: 当日志源连接失败/超时（模拟）时，日志工具应返回"不可用"，不把异常详情外泄。
- [ ] AC4: mock 模式下（`set_active_scenario("S1")`），日志工具返回原 mock 结果，与改动前一致。
- [ ] AC5: 日志分析结果中不得出现凭据、DSN、`sk-` 或原始异常全文；日志行脱敏后进入上下文。
- [ ] AC6: 日志工具输出经网关限时与脱敏兜底；Trace 只展示工具名/状态/耗时/脱敏摘要，不展示原始日志全文。
- [ ] AC7: 回归 —— `test_agent_gateway.py`、`test_diagnosis.py`、`test_tool_gateway.py` 全绿。

## 边界与约束
- 安全边界：纯只读；凭据只走环境变量；脱敏硬约束。
- 降级策略：未配置 → not_configured；失败/超时 → unavailable；均不抛异常。
- 兼容性：mock 评测（S1–S4）行为不变；既有接口契约不变。
