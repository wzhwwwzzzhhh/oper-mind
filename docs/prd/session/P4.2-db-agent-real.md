# 会话 DBAgent 工具接入真实 PostgreSQL · PRD

## 背景
P4 已让服务中心快照连真实 PostgreSQL（`postgres-production`，`POSTGRES/PostgresServiceConnector`）。
但会话工作台里的 DBAgent 三个数据库诊断工具（`explain_sql` / `show_index` / `show_create_table`）
**仍写死走 `data/mock_db.py`**：即使在真实模式（非 mock api_key）下，也返回 P2 订单演示的假 EXPLAIN/假索引，
而不是查询真实库。

关联：`docs/产品定义.md`（服务上下文、受控 Tool/Connector 读取）、`docs/路线图.md`（第三阶段扩展能力经统一 Connector 接入）、
`docs/design/service-center/P4服务中心变真Design.md`（P4 已验证的 DSN 来源/只读引擎/超时/降级方案）。

## 目标
1. 会话里 DBAgent 工具在真实模式下查询真实 PostgreSQL（执行计划/索引/建表语句）。
2. mock 模式（api_key == mock）行为完全不变，S1–S4 评测确定性不受影响。
3. 复用 P4 已验证的连接来源与只读安全边界，零新增配置、零新增凭据。

## 用户故事
作为运维工程师，我在正式会话里问"这条 SELECT 为什么慢"，应看到**真实 PostgreSQL 的执行计划与索引情况**，
而不是演示假数据——以便基于真实库状态给出可信的优化结论。

## 范围

### 做什么
- DBAgent 三个工具在真实模式下读真实 PostgreSQL：
  - `explain_sql` → 执行真实 `EXPLAIN` 得到执行计划
  - `show_index` → 从 `pg_indexes` 读真实索引
  - `show_create_table` → 从 `pg_catalog` 拼真实建表语句
- mock 模式完全保留（`data/scenarios.get_active_scenario()` 判定，行为原样不变）。
- 复用 P4 的 DSN 来源（`load_service_settings().pg_dsn` / `OPERMIND_PG_DSN`）、只读引擎构造、3 秒超时、三态失败分支。

### 不做什么（明确排除）
- 不接 MySQL / Redis（后续按同模式复制）。
- 不做写操作 / DDL / DML（纯只读）。
- 不新增配置项；不做表名白名单映射（表结构来源：真库系统目录）。
- 不改 `data/mock_db.py`、`data/scenarios.py`、S1–S4 评测路径。
- 不动前端（接口契约不变，Trace 展示不新增字段）。
- 不做 `EXPLAIN ANALYZE`（真正执行 SQL，超范围；本阶段仅 `EXPLAIN` 计划）。

## 功能需求

### 1. 模式判定（双模式，对齐既有范式）
- **输入**：当前进程的 mock/真实模式。
- **行为**：
  - `get_active_scenario()` 非 None ⇒ mock 模式，工具走 `data/mock_db.py` 原逻辑。
  - `get_active_scenario()` 为 None ⇒ 真实模式，工具走真实 PostgreSQL 分支。
- **输出**：对应分支的格式化结果。

### 2. 连接来源与引擎（复用 P4）
- **输入**：环境变量 `OPERMIND_PG_DSN`（P4 已实现的 `load_service_settings().pg_dsn`）。
- **行为**：
  - 真实模式下工具懒加载只读引擎；**每次调用现取 DSN、现建引擎/短生命周期连接，不跨 Run 持有单例**（与 `build_coordinator` 每 Run 现造内核的并发隔离一致）。
  - 引擎构造复用 P4 的只读引擎工厂（psycopg 驱动 + `connect_timeout=3` + `statement_timeout=3000` + `SET TRANSACTION READ ONLY`）。
  - 无 DSN：工具返回「数据库未配置，无法查询」的诚实降级，不抛异常。
  - 连接失败/超时：返回「数据库不可用」的中性降级，不把异常详情外泄（网关 `desensitize` 兜底）。
- **输出**：真实查询结果或降级文案。

### 3. explain_sql(sql) —— 真实 EXPLAIN
- **输入**：`sql` 字符串。
- **行为**：
  - 安全约束：只接受 `SELECT` 开头的查询（`sql.strip().upper()` 不以 `SELECT` 开头 ⇒ 拒绝，返回「只支持分析 SELECT 查询，已拒绝」）。
  - 执行 `EXPLAIN`（只读事务内），得到真实执行计划。
  - 格式化输出真实计划有限字段（节点类型/表/访问方式/行估算/成本等），**不把完整 SQL 原文回显到 Trace**。
- **输出**：真实执行计划文本。

### 4. show_index(table) —— 真实索引
- **输入**：`table` 字符串。
- **行为**：
  - 安全约束：`table` 必须是标识符（`^[A-Za-z_][A-Za-z0-9_]*$`），拒绝空格/分号/注释等注入。
  - 查询只读系统目录（参数化），得到真实索引。
  - 表不存在 ⇒ 「表 'x' 不存在」；无索引 ⇒ 「表 'x' 没有索引」。
- **输出**：真实索引列表（索引名 + `indexdef`）。

### 5. show_create_table(table) —— 真实建表语句
- **输入**：`table` 字符串。
- **行为**：
  - 安全约束：同 `show_index` 的标识符校验。
  - 从只读系统目录读取并拼建表语句。
  - 表不存在 ⇒ 「表 'x' 不存在」。
- **输出**：仿 PostgreSQL 建表语句文本。

## 非功能需求
- **性能**：每次工具调用限时 3 秒（复用 P4 引擎超时），超时降级为「数据库不可用」。
- **安全**：只读；参数化；无凭据外泄；工具输出经网关 `desensitize` 兜底。
- **可靠**：无 DSN/连接失败/超时均降级，不抛异常炸会话。

## 数据与接口影响
- 数据：无新增持久化。
- 接口：无，接口契约不变；Trace 展示字段不新增。

## 验收标准
- [ ] AC1：mock 模式下（`set_active_scenario("S1")`），`ExplainTool().execute(...)` 返回原 mock 结果，与改动前一致。
- [ ] AC2：真实模式 + 无 DSN（环境变量置空）时，工具返回「未配置」降级文案，不抛异常。
- [ ] AC3：真实模式 + 假 engine 抛 OperationalError 时，工具返回「数据库不可用」降级文案，不把异常详情外泄。
- [ ] AC4：`explain_sql` 收到非 SELECT 输入时返回「只支持分析 SELECT」拒绝文案，且不触库。
- [ ] AC5：`show_index` 收到含空格/分号的非法表名时被拒绝，不触库。
- [ ] AC6：`show_index` 在假连接返回 `pg_indexes` 行时，输出含索引名与 `indexdef`。
- [ ] AC7：`show_index` 在表不存在时返回「表 'x' 不存在」。
- [ ] AC8：`show_create_table` 在假连接返回列/约束时，输出含 `CREATE TABLE`。
- [ ] AC9：真实工具输出经 `desensitize()` 后不含凭据/DSN 明文。
- [ ] AC10：回归 —— `test_postgres_connector.py`、`test_p4_service_center.py`、`test_agent_gateway.py`、`test_tool_gateway.py` 全绿。

## 边界与约束
- 安全边界：纯只读，无写路径；参数化；无凭据进日志/结果/Trace/前端；非 SELECT 与非法表名一律拒绝。
- 降级策略：无 DSN → 「未配置」；连接失败/超时 → 「不可用」；均不抛异常。
- 兼容性：mock 评测（S1–S4）行为不变；既有接口契约与 Trace 展示不变。
