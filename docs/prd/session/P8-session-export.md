# 会话导出——会话记录留存与分享 · PRD

## 背景

会话工作台是产品主入口（`docs/产品定义.md` §2.1），会话内沉淀了完整的问题-回答-调查链路。但用户**无法把一段会话导出**（`docs/接口清单.md` 第一大模块"缺少"表："会话导出：—。❌ 欠账（优先级低）"）：要留存记录只能手动复制粘贴，且容易把敏感内容一起拷走。

现状：会话、消息、Run 与结果均已持久化且有安全摘要接口——`GET /sessions/{id}`（详情）、`GET /sessions/{id}/messages`（消息列表）、`GET /sessions/{id}/runs`（Run 列表）、`GET /runs/{id}`（Run 详情与结果，含安全投影的证据摘要）；审计检索（`GET /audit/activities`，P8 #62）已证明"安全摘要投影"纪律可用。缺的是一个**按会话聚合、安全脱敏、可留存分享**的导出入口。

关联：`docs/接口清单.md`（第一大模块缺表）、`docs/prd/session/P8-workbench-loop-closure.md`（#54）、`docs/prd/session/P8-session-management.md`（#64，全局 Run 列表）、`docs/产品定义.md` §2.1（会话主入口）、`docs/开发规范.md` §4（凭据/隐私隔离）与 §5（Trace 安全投影）。

## 目标

1. 用户能把一个会话（标题、消息、Run 摘要、结论要点）**导出为可读文档**，用于留存、分享与复盘。
2. 导出内容**只含安全投影**：不含 CoT、Prompt、原始工具输出、原始异常、原始 SQL、凭据或完整连接细节。
3. 导出为**确定性、可复现**的格式，前端一键触发，失败时诚实降级。

## 用户故事

作为用户，我完成了一段排障会话，应能一键把它导出为 Markdown 文档，内容包含问题、回答、调查步骤摘要与结论——以便留存复盘或分享给同事，而不用担心把内部凭据或原始证据一起带出去。

## 范围

### 做什么
- 新增 `GET /sessions/{id}/export`：把会话聚合为**安全摘要文档**（Markdown 为主格式，Design 定是否同时支持 JSON），包含会话标题、消息时间线（user 问题 + assistant 回答的安全投影）、各 Run 的结论与证据摘要。
- 前端会话页提供"导出"入口，下载导出文档；导出失败/空会话时诚实降级（如明确提示"无可导出内容"）。
- 复用既有安全投影纪律：消息正文按既有资源投影，Run 结果按既有结果资源投影（含 severity/confidence/summary/evidence 摘要），不新增暴露面。

### 不做什么（明确排除）
- 不做"导出原始证据包"：不导出工具原始输出、SQL、日志原文、Trace 内部事件、Prompt/CoT、异常堆栈或凭据。
- 不做批量导出 / 全局导出（按会话单个导出，不做全量打包）。
- 不做定时导出 / 导出订阅 / 邮件发送（无告警通道，`docs/接口清单.md` 告警通道刻意不做）。
- 不做导出后编辑 / 回传（导出是只读快照，单向输出）。
- 不改变既有会话/消息/Run 接口契约与留痕。

## 功能需求

### 1. 会话导出（GET /sessions/{id}/export）
- **输入**：会话 ID。
- **行为**：
  - 按会话聚合：标题、创建时间、消息时间线（user/assistant 消息正文安全投影）、各 Run 的结论摘要（query/status/severity/confidence/summary/证据摘要）。
  - 输出格式为 Markdown（Design 定是否同时提供 JSON 变体）；内容确定性排序（按时间线）。
  - 会话不存在 → 404；会话无可导出内容（无消息无 Run）→ 明确空态（如导出头 + "无可导出内容"），不伪造。
  - 超时 / 数据读取失败 → 明确错误（如 503），不返回半截文档。
- **输出**：`text/markdown` 文档（或 JSON，Design 定），可下载。

### 2. 前端导出入口
- **输入**：会话页工具栏。
- **行为**：提供"导出"按钮触发下载；导出中展示进行态；失败展示错误与重试；空会话提示无可导出内容。
- **输出**：下载的导出文档；失败/空态诚实展示。

## 非功能需求
- **安全**：导出内容与既有安全投影一致——不含 CoT/Prompt/原始工具输出/原始 SQL/原始异常/凭据/完整 DSN；导出前对敏感字面量（`sk-`、`postgres://` 完整 DSN 等）做兜底脱敏。
- **诚实**：空会话如实提示；失败不返回半截或伪造内容。
- **性能**：导出为单会话聚合查询，数量级与 `GET /sessions/{id}/messages` + `GET /sessions/{id}/runs` 相当；大会话限时或分页导出（Design 定）。
- **确定性**：相同会话重复导出，内容一致（不含随机标识符或不稳定字段）。

## 数据与接口影响
- 数据：无新增持久化、无迁移（复用会话/消息/Run/结果既有数据）。
- 接口：新增 `GET /sessions/{id}/export`；既有接口契约不变。

- [ ] AC2: 当会话含 Run 时，导出应包含各 Run 的结论摘要（query/status/severity/confidence/summary/证据摘要）。

- [ ] AC4: 当会话无可导出内容时，应返回明确空态，不抛错、不伪造内容。
- [ ] AC5: 当导出读取失败/超时时，应返回明确错误（如 503），不返回半截文档。
- [ ] AC6: 导出内容不得包含 CoT、Prompt、原始工具输出、原始 SQL、原始异常、凭据、`sk-` 或完整 DSN。

## 边界与约束
- 安全边界：只读导出，只含安全投影；导出文档不得含凭据/CoT/原始证据。
- 降级策略：空会话 → 空态；读取失败/超时 → 明确错误；敏感字面量 → 兜底脱敏。
- 兼容性：既有会话/消息/Run 接口契约不变；导出不改变留痕。

## 开放问题
1. **格式**：只做 Markdown，还是同时提供 JSON 变体？推荐首版仅 Markdown（人可读、可分享），JSON 后续。
2. **证据摘要粒度**：导出中 Run 的证据摘要与 `GET /runs/{id}` 一致（Design 定截断策略），还是更精简？
3. **大会话**：超过阈值（如 500 条消息）时是完整导出、分页导出还是明确限制？推荐明确限制并提示，Design 定。
4. **导出范围**：是否包含被删除的消息（配合消息编辑/删除 PRD 的软删除）？推荐导出不含已删除消息，Design 定。
