# 数据库深度只读诊断——锁与连接池（慢查询深化第一切片） · PRD

## 背景
会话 DBAgent 已具备真实 PostgreSQL 只读诊断能力（P4.2：`explain_sql` / `show_index` / `show_create_table`，
双模式 mock/真实），受控动作闭环已打通（P5：联合索引重建）。但慢查询排障中常见的两类问题
**目前无法诊断**：

1. **锁等待/阻塞**：一条慢 SQL 背后可能是另一条未提交事务持有锁，形成阻塞链——现有工具看不到锁与阻塞关系；
2. **连接池耗尽**：慢查询堆积导致连接耗尽、新查询全部排队——现有工具看不到连接占用与利用率。

`docs/路线图.md` 第三阶段规划"数据库：慢查询深化、锁、连接池、容量、索引"。本 PRD 是该深化的
**第一切片：锁与连接池诊断**（与慢查询最直接相关的两个维度）；容量（库/表大小、膨胀）与
索引效用分析留作后续切片，不在本 PRD。

关联：`docs/prd/session/P4.2-db-agent-real.md`（双模式、只读引擎、DSN 来源、超时与降级方案，
本 PRD 沿用）、`docs/prd/approval/P5-controlled-action-real.md`（受控动作闭环，本 PRD 不新增动作）、
`docs/产品定义.md`（§5 安全边界：模型不得任意 SQL 访问；§2.2 证据摘要可审计）、
`docs/开发规范.md`（Connector/Tool 须显式注册、参数校验、超时、脱敏、权限边界）。

## 目标
1. 会话 DBAgent 具备**锁诊断**能力：查看当前锁、识别锁等待与阻塞链，输出结构化脱敏事实。
2. 会话 DBAgent 具备**连接池诊断**能力：查看连接总数/活跃/空闲/等待与利用率，输出结构化脱敏事实。
3. 全程只读与脱敏：不杀锁、不修改连接；结果不含用户名、客户端 IP、原始 SQL 与凭据；
   Trace 只展示脱敏摘要。

## 用户故事
作为运维工程师，我在会话里问"刚才那个库是不是有锁等待？连接是不是打满了？"，
Agent 调用锁与连接池诊断工具，返回阻塞链和连接利用率的脱敏结论，并据此给出排障建议
（如"存在 1 个锁等待链，源头事务已运行 20 分钟；连接利用率 95%，接近上限"）——
我能基于真实库状态判断下一步（继续调查或走受控动作提案），而不是靠猜。

## 范围

### 做什么
- 新增**锁诊断工具**（只读）：查询当前锁与锁等待，识别阻塞链（阻塞源头、等待时长），
  输出结构化脱敏事实。
- 新增**连接池诊断工具**（只读）：统计连接总数/活跃/空闲/等待、最大连接数与利用率，
  输出结构化脱敏事实。
- 双模式（mock/真实）：真实模式查询真实 PostgreSQL；mock 模式走确定性场景数据，
  行为完全不变（沿用 `get_active_scenario()` 判定；新工具 mock 分支定义在工具模块内，不改
  `data/scenarios.py`/`data/mock_db.py`）。
- 复用 P4/P4.2 已验证的连接来源（`load_service_dsn(service_id)`，即 `OPERMIND_SERVICE_<ID>_DSN`；
  实际实现不使用 `load_service_settings().pg_dsn`）、只读引擎、3 秒超时、
  三态降级（成功/不可用/未配置）。
- 结构化输出：跨层数据使用 Pydantic/TypedDict；Trace 只展示脱敏摘要（锁类型/数量/等待时长/
  连接利用率等收敛指标），不展示明细行。

### 不做什么（明确排除）
- 不做写操作：不杀锁、不 `terminate` 会话、不修改连接（写能力属受控动作，后续另行 Design）。
- 不做容量诊断（库/表大小、膨胀率）——后续切片。
- 不做索引效用分析（重复/未使用索引）——后续切片。
- 不做 MySQL/Redis 同型诊断（本 PRD 仅 PostgreSQL，其他类型后续按同模式复制）。
- 不做 `EXPLAIN ANALYZE`（真正执行 SQL，超范围）。
- 不新增配置项、不新增凭据、不新增公开 REST API（作为 Agent 工具接入，跟随 P4.2 模式）。
- 不改 `data/mock_db.py`、`data/scenarios.py`、S1–S4 评测路径。
- 不将 `pg_stat_activity` 明细行（用户名、客户端 IP、原始 SQL、application_name）暴露到
  Trace、事件、结果或前端——只输出脱敏聚合事实。

## 功能需求

### 1. 锁诊断
- **输入**：可选过滤（数据库名；Design 定是否支持按表过滤）。默认**当前连接数据库**
  （DSN 指向的库，已确认 Design 决策 1），可选 `database` 参数过滤；不做按表过滤。
- **行为**：查询当前锁与锁等待状态，识别锁等待链（持有锁的源头会话、被阻塞的会话、等待时长、
  锁类型/模式）；无锁等待时返回诚实"无锁等待"状态；仅 PostgreSQL 真实模式，mock 模式返回
  确定性场景事实（锁诊断 mock 如实返回"无锁等待"）。
- **输出**：结构化脱敏事实——锁等待链数量、每条链的阻塞时长、锁类型/模式分布、
  相关对象名（可展示的收敛信息，不含 SQL/用户名/IP）。

### 2. 连接池诊断
- **输入**：无（默认全库统计）。
- **行为**：统计当前连接总数、活跃/空闲/等待（状态分类）、最大连接数与利用率；
  连接利用率 = 当前连接总数 / 最大连接数；超限或接近上限如实标注。
- **输出**：结构化脱敏事实——连接总数/活跃/空闲/等待、最大连接数、利用率、
  健康程度表述（正常/接近上限/已耗尽）。

### 3. 双模式与降级
- **输入**：当前进程的 mock/真实模式（沿用 `get_active_scenario()`）。
- **行为**：mock 模式走 scenario 原逻辑，行为与 S1–S4 评测完全一致；真实模式走真实库分支；
  未配置 DSN → "未配置"；查询超时/失败 → "不可用"，不抛异常、不阻塞其他工具。
- **输出**：对应分支的格式化结果。

### 4. 安全与脱敏
- **输入**：任意库状态（可能存在持锁的长事务、高负载连接）。
- **行为**：纯只读查询（只读引擎 + 事务只读）；超时兜底；结果脱敏（不含用户名/IP/原始 SQL/凭据）；
  工具经 `ToolGateway` 白名单准入、参数校验、限时、脱敏兜底（沿用既有网关行为）。
- **输出**：脱敏后的结构化事实，Trace 只展示收敛摘要。

## 非功能需求
- **性能**：单次诊断限时（复用 P4 的 3s 超时模式），不拖累其他工具与接口。
- **安全**：纯只读；只读引擎（`SET TRANSACTION READ ONLY`）；脱敏兜底；无写路径。
- **可靠**：未配置/超时/失败均诚实降级，不抛异常、不阻塞其他工具。
- **诚实**：无锁等待如实返回"无锁等待"；连接利用率如实计算；不伪造实时监控语义。

## 数据与接口影响
- 数据：无新增持久化、无数据库迁移。
- 接口：**无新增公开 API**（诊断作为 Agent 工具接入，跟随 P4.2 模式）；既有接口契约不变。
- Trace：复用现有 Trace 事件模型，只展示工具类别 + 脱敏摘要，不新增字段契约。

## 验收标准
- [ ] AC1: 当真实库存在锁等待时，锁诊断返回结构化事实（等待链数量、阻塞时长、锁类型分布）；
      当无锁等待时，返回诚实"无锁等待"状态，不伪造。
- [ ] AC2: 锁诊断能识别阻塞链：被阻塞会话关联到其阻塞源头（事务运行时长、锁类型），
      输出不含原始 SQL、用户名、客户端 IP。
- [ ] AC3: 连接池诊断返回连接总数/活跃/空闲/等待、最大连接数与利用率；
      利用率接近或达到上限时如实标注（如"接近上限/已耗尽"）。
- [ ] AC4: mock 模式（S1–S4 评测路径）行为完全不变，确定性不受影响。
- [ ] AC5: 诊断工具为纯只读：不执行 DML/DDL、不杀锁、不 terminate 会话（有测试锁定）。
- [ ] AC6: 诊断结果经脱敏兜底，不含用户名、客户端 IP、原始 SQL、DSN 或凭据。
- [ ] AC7: 当未配置 DSN 时，诊断返回"未配置"；当查询超时/失败时，返回"不可用"，
      不抛异常、不阻塞其他工具与接口。
- [ ] AC8: 工具经 `ToolGateway` 白名单准入；Trace 只展示脱敏摘要，不展示明细行。
- [ ] AC9: 回归 —— 既有后端测试、前端 typecheck/test/build（如涉及）全绿；
      未新增公开 API、未改 mock 数据源。

## 边界与约束
- 安全边界：纯只读（只读引擎 + 事务只读）；不杀锁、不修改会话；结果脱敏；
  无新增公开 API、无新增凭据/配置。
- 降级策略：未配置 → "未配置"；查询超时/失败 → "不可用"；无锁等待 → "无锁等待"；均不抛异常、不伪造。
- 兼容性：mock 评测（S1–S4）行为不变；P4.2 既有工具行为不变；诊断为新增能力，不影响既有工具。
- 工程闸门：本 PRD 涉及**新增 Tool/能力**（真实库只读查询），按开发规范须先 Design → Review →
  用户确认才能实施；本 PRD 是需求层，不替代 Design 文档。

## 已确认决策（技术方案见 Design，执行 AI 不必重新设计）
> 来源：`docs/design/session/P7DB锁与连接池诊断Design.md`（已确认）。以下为执行 AI 必须遵守的技术约束。

1. ✅ 锁诊断默认范围 = **当前连接数据库**（DSN 指向的库），可选 `database` 参数过滤；不做按表过滤。
2. ✅ 连接"等待"判定口径：`wait_event_type IS NOT NULL AND state <> 'idle'` 计为等待。
3. ✅ 健康档位阈值：利用率 `>=100%` 已耗尽、`>=80%` 接近上限、否则正常。
4. ✅ 工具命名：`check_lock_status` / `check_connection_pool`。
5. ✅ 新工具 mock 分支在工具模块内定义确定性映射，**不改** `data/scenarios.py`/`data/mock_db.py`；
   锁诊断 mock 如实返回"无锁等待"，连接池按场景返回确定性占用。
6. ✅ 服务中心服务详情页不同步展示（页面展示属后续切片）。
7. ✅ DSN 来源复用 `load_service_dsn(service_id)`（`OPERMIND_SERVICE_<ID>_DSN`），非
   `load_service_settings().pg_dsn`（旧文本陈旧，已回写）。
