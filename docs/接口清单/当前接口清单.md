# OperMind 当前接口清单

> 状态：基于当前工作区代码盘点
>
> 盘点日期：2026-08-03
>
> 适用范围：`backend/src/app.py`、`backend/src/api/v1/routes.py`、`backend/src/api/v1/schemas.py` 及对应依赖装配
>
> 本文件记录当前已经存在的 HTTP 接口与公开契约，不代表所有接口都已经接入真实外部服务。服务中心当前仍使用代码内注册服务和有限快照；模型 Provider、模型列表、文档知识库和完整历史监控接口当前未在正式 v1 路由中实现。

## 1. 阅读说明

### 1.1 API 前缀

正式产品接口统一使用：

```text
/api/v1
```

健康检查不在 v1 前缀下：

```text
/health
```

### 1.2 通用响应元数据

成功响应通常包含 `meta`：

```json
{
  "meta": {
    "request_id": "<UUID>",
    "trace_id": "<UUID|null>"
  }
}
```

同时通过响应头返回：

- `X-Request-Id`
- 诊断 Run 相关接口通常额外返回 `X-Trace-Id`

### 1.3 分页

列表接口使用 cursor 分页，不使用页码分页：

```text
?cursor=<opaque-cursor>&limit=20
```

当前 `limit` 范围为 `1–100`，默认值为 `20`。

分页响应包含：

```json
{
  "page": {
    "next_cursor": "<opaque-cursor|null>",
    "has_more": false
  }
}
```

客户端不得解析或自行生成 cursor，只应原样保存并回传 `next_cursor`。

### 1.4 错误响应

v1 错误使用统一包络：

```json
{
  "error": {
    "code": "RUN_NOT_FOUND",
    "message": "...",
    "details": null
  },
  "meta": {
    "request_id": "<UUID>",
    "trace_id": "<UUID|null>"
  }
}
```

已明确映射的常见错误状态：

| 错误码 | HTTP 状态 | 说明 |
|---|---:|---|
| `SESSION_NOT_FOUND` | 404 | 会话不存在 |
| `RUN_NOT_FOUND` | 404 | Run 不存在 |
| `ACTION_PROPOSAL_NOT_FOUND` | 404 | 修复提案不存在 |
| `SERVICE_NOT_FOUND` | 404 | 服务不存在 |
| `SESSION_ARCHIVED` | 409 | 会话已归档，不能继续写入 |
| `RUN_ALREADY_TERMINAL` | 409 | Run 已经进入终态 |
| `IDEMPOTENCY_KEY_REUSED` | 409 | 幂等键与已有请求不匹配或重复使用 |
| `RUN_INPUT_MESSAGE_INVALID` | 409 | Run 输入消息状态不合法 |
| `ACTION_PROPOSAL_INVALID_STATE` | 409 | 提案当前状态不允许该操作 |
| `ACTION_PROPOSAL_EXPIRED` | 409 | 提案已过期 |
| `SERVICE_CENTER_UNAVAILABLE` | 503 | 服务中心当前不可用 |
| `VALIDATION_ERROR` | 422 | 请求参数校验失败 |
| `INVALID_CURSOR` | 400 | 分页游标无效 |
| `INVALID_EVENT_CURSOR` | 400 | Run 事件游标无效 |

内部异常不会通过 v1 API 暴露原始堆栈、凭据或工具细节，而是返回 `INTERNAL_ERROR`。

### 1.5 幂等键

创建 Run、审批提案和请求执行均要求请求头：

```http
Idempotency-Key: <UUID>
```

当前代码会校验其为 UUID。客户端重试时必须复用同一个幂等键，不得为同一业务请求随机生成新键。

## 3. 系统接口

### 3.1 健康检查

```http
GET /health
```

用途：用于前端状态栏、部署探活和基础运行状态检查。该接口不返回敏感配置。

当前响应字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | `string` | 当前为 `ok` |
| `mode` | `string` | 当前运行模式摘要 |
| `model` | `string` | 当前装配的 LLM 模型标识 |

当前实现会返回共享 LLM 的模型名，但不会返回 API Key、Base URL 或凭据内容。

## 4. 服务中心接口

> 当前服务中心依赖 `ServiceRegistry(())` 的代码内注册服务。正式接口已存在，但服务类型、Connector、真实凭据和完整监控能力尚未全部接入。

### 4.1 服务列表

```http
GET /api/v1/services
```

用途：服务中心首页读取服务列表。

响应主体：

```json
{
  "items": [
    {
      "id": "order-service",
      "title": "...",
      "kind": "postgres_orders_demo",
      "supported_investigations": [],
      "action_boundary": "...",
      "snapshot": {}
    }
  ],
  "meta": {}
}
```

每个服务包含：

- 服务身份：`id`、`title`、`kind`
- 支持的固定调查入口
- 动作边界说明
- 当前有限快照

### 4.2 服务详情

```http
GET /api/v1/services/{service_id}
```

用途：服务详情页读取服务身份、能力边界和当前有限快照。

当前 `ServiceSnapshotResource` 字段：

| 字段 | 说明 |
|---|---|
| `observed_at` | 快照观测时间 |
| `mode` | `disabled`、`mock` 或 `target` |
| `availability` | `healthy`、`unhealthy`、`unavailable` 或 `not_configured` |
| `performance_signal` | 慢查询、无慢查询、数据不足、不可用或未配置 |
| `server_metrics` | 有限服务器/性能指标 |
| `database` | 收敛后的数据库安全状态 |

`server_metrics` 当前字段：

- `source_status`
- `window_size`
- `p50_ms`
- `p95_ms`
- `slow_query_count`
- `timeout_count`

`database` 当前字段：

- `source_status`
- `signal`

当前并不是完整的 MySQL、PostgreSQL 或 Redis 监控大盘，也没有正式的历史趋势查询接口。

### 4.3 服务活动

```http
GET /api/v1/services/{service_id}/activities?cursor=<cursor>&limit=20
```

用途：读取服务绑定会话中的 Run 以及修复闭环安全摘要。

响应中的活动包含：

- `session_id`、`session_title`
- `run_id`、`run_status`
- `created_at`、`finished_at`
- `summary`、`severity`、`confidence`
- `proposal_status`
- `verification_status`

### 4.4 创建服务上下文会话

```http
POST /api/v1/services/{service_id}/sessions
```

用途：从服务中心进入会话时创建带服务上下文的 Session。

重要边界：

- 只创建会话
- 不会自动创建诊断 Run
- 不会自动读取外部服务
- 不会自动执行修复动作

## 5. 会话接口

### 5.1 创建会话

```http
POST /api/v1/sessions
Content-Type: application/json
```

请求体：

```json
{
  "title": "订单服务慢查询调查",
  "environment_id": null,
  "incident_id": null
}
```

字段约束：

- `title`：必填，1–200 字符，首尾空白会被清理
- `environment_id`：可选 UUID
- `incident_id`：可选 UUID

成功状态：`201 Created`。

### 5.2 会话列表

```http
GET /api/v1/sessions?cursor=<cursor>&limit=20&status=active
```

用途：读取会话工作台的会话列表。

- 按更新时间倒序
- `status` 可选：`active` 或 `archived`
- 使用 cursor 分页

### 5.3 会话详情

```http
GET /api/v1/sessions/{session_id}
```

返回单个 Session 资源：

- `id`
- `title`
- `status`
- `environment_id`
- `incident_id`
- `service_id`
- `created_at`
- `updated_at`
- `archived_at`

### 5.4 更新会话

```http
PATCH /api/v1/sessions/{session_id}
Content-Type: application/json
```

请求体可更新：

```json
{
  "title": "新的会话标题",
  "status": "archived"
}
```

至少提供一个字段。已归档会话不能重新激活。

### 5.5 归档会话

```http
DELETE /api/v1/sessions/{session_id}
```

这是逻辑归档，不是物理删除。重复归档保持 `204 No Content`。

### 5.6 消息历史

```http
GET /api/v1/sessions/{session_id}/messages?cursor=<cursor>&limit=20
```

按创建时间正序返回：

- `id`
- `session_id`
- `run_id`
- `role`：`user`、`assistant` 或 `system`
- `content`
- `created_at`

## 6. 诊断 Run 接口

### 6.1 会话下 Run 列表

```http
GET /api/v1/sessions/{session_id}/runs?cursor=<cursor>&limit=20
```

用途：刷新页面后恢复会话中的诊断工作区。

Run 状态：

```text
queued | running | succeeded | failed | cancelled
```

### 6.2 创建诊断 Run

```http
POST /api/v1/sessions/{session_id}/runs
Idempotency-Key: <UUID>
Content-Type: application/json
```

请求体：

```json
{
  "query": "订单服务最近变慢，请先做只读调查"
}
```

约束：

- `query` 必填
- 长度 1–4000 字符
- 首尾空白会被清理
- 必须携带合法 UUID 格式的 `Idempotency-Key`

成功状态：`202 Accepted`。

接口先原子受理 Run，HTTP 响应完成后再启动后台执行。客户端应随后订阅 SSE 或读取 Run 状态。

### 6.3 Run 详情

```http
GET /api/v1/runs/{run_id}
```

返回：

- Run 基础状态
- `trace_id`
- 输入消息 ID
- 创建、开始、结束时间
- 成功时的结构化诊断结果
- 失败时的安全错误

成功 Run 的结果包含：

- `summary`
- `severity`
- `confidence`
- `root_causes`
- `evidence`
- `impact`
- `recommendations`
- `risks`
- `requires_approval`
- `agent_summary`
- 可选 `report_markdown`

`agent_summary` 是用户可理解的 Agent 摘要，不是隐藏思维链。

## 7. Run 事件与 SSE

### 7.1 历史事件列表

```http
GET /api/v1/runs/{run_id}/events?cursor=<cursor>&limit=20
```

按 `sequence` 正序读取已经提交的 RunEvent。

当前事件类型：

```text
run_queued
run_started
route_decided
agent_start
agent_done
conflict_checked
debate_round
report
reflection
run_succeeded
run_failed
run_cancelled
tool_invoked
```

事件统一包含：

- `id`
- `run_id`
- `sequence`
- `type`
- `occurred_at`
- `data`

`tool_invoked` 事件可以包含受控的安全摘要、状态和耗时；不得把原始 Prompt、CoT、凭据、原始敏感日志或未经脱敏的工具参数放入前端事件。

### 7.2 SSE 事件重放

```http
GET /api/v1/runs/{run_id}/stream?after_sequence=0
Accept: text/event-stream
```

也支持通过请求头续接：

```http
Last-Event-ID: <sequence>
```

规则：

- `Last-Event-ID` 和 `after_sequence` 同时存在时必须一致
- 默认从 sequence `0` 开始
- 只能重放已持久化事件
- 不产生未提交的即时 SSE 帧
- 返回 `text/event-stream`
- 禁用缓存并设置 `X-Accel-Buffering: no`

前端应保存最后收到的 sequence，并在断线后使用它续接，而不是从头重复消费。

## 8. 修复提案、审批与执行接口

> 当前接口表达的是安全闭环骨架。具体动作必须经过独立 Design → Review → 用户确认，并由后端注册固定动作；前端不能提交任意 SQL、Shell、DDL、DML 或动作参数。

### 8.1 读取 Run 关联提案

```http
GET /api/v1/runs/{run_id}/action-proposal
```

成功 Run 可以关联一个固定、不可编辑的修复提案；没有提案时返回：

```json
{
  "proposal": null,
  "meta": {}
}
```

### 8.2 读取提案详情

```http
GET /api/v1/action-proposals/{proposal_id}
```

返回内容包括：

- 固定 `action_id`
- 动作摘要和风险说明
- 目标摘要
- 证据 ID
- 验证计划
- 审批记录
- 执行状态
- Verify 状态

当前 Proposal 由来源 Run 固定，不接受前端编辑动作内容。

### 8.3 读取提案审计事件

```http
GET /api/v1/action-proposals/{proposal_id}/events?cursor=<cursor>&limit=20
```

当前事件类型：

```text
proposal_created
approval_recorded
execution_requested
execution_started
precondition_checked
execution_completed
verification_started
verification_completed
action_blocked
action_failed
```

### 8.4 批准或拒绝提案

```http
POST /api/v1/action-proposals/{proposal_id}/approval
Idempotency-Key: <UUID>
Content-Type: application/json
```

请求体：

```json
{
  "decision": "approve",
  "comment": null
}
```

或：

```json
{
  "decision": "reject",
  "comment": "暂不执行，先观察监控"
}
```

约束：

- `decision` 只能是 `approve` 或 `reject`
- 批准时不接受备注
- 拒绝备注最长 500 字符
- 需要合法 UUID 幂等键

### 8.5 请求执行

```http
POST /api/v1/action-proposals/{proposal_id}/executions
Idempotency-Key: <UUID>
Content-Type: application/json
```

请求体当前为空对象：

```json
{}
```

接口只接受固定 Proposal 的二次确认，不接受动作参数。成功状态：`202 Accepted`。

后端随后异步执行唯一白名单动作，并通过 Proposal 详情与审计事件查询执行和验证结果。

## 9. 当前接口与页面映射

| 页面 | 可以使用的现有接口 | 当前可展示内容 | 现阶段限制 |
|---|---|---|---|
| 会话工作台 | Sessions、Messages、Runs、Run Stream | 会话列表、消息、回答、Trace、Tool 摘要 | 前端仍需完成正式 API 接入与错误态细化 |
| 服务中心首页 | `GET /services` | 服务列表、状态、支持调查入口 | 当前服务注册是有限代码内注册，不是完整接入中心 |
| 服务详情页 | `GET /services/{id}`、`GET /activities` | 服务身份、有限快照、活动记录 | 没有完整历史趋势和多服务类型指标 |
| 服务发起调查 | `POST /services/{id}/sessions` → `POST /sessions/{id}/runs` | 带服务上下文的调查会话 | 创建服务会话不会自动读取或调查 |
| 服务监控页 | 部分使用服务详情快照 | 当前状态、性能信号、慢查询摘要 | 暂无独立监控查询、趋势、告警规则接口 |
| 模型服务页 | 当前无正式 v1 接口 | 只能使用原型演示数据 | 没有 Provider、模型列表、连接测试和策略 API |
| 文档知识库页 | 当前未发现正式 v1 路由 | 只能先设计静态原型 | 没有上传、索引、检索和权限接口 |
| 审批/执行界面 | Proposal、Approval、Execution、Action Events | 风险提案、审批状态、执行与验证留痕 | 当前默认依赖未注册具体执行器 |

## 10. 当前后端装配事实

当前 v1 依赖装配包含：

- Session Application Service
- Run Application Service
- Action Application Service
- Service Center Application Service
- `CoordinatorDiagnosisExecutor`
- `KernelReportResultAssembler`
- 空的 `ServiceRegistry(())`
- 未注册具体 Action Executor

诊断内核每个 Run 现造一套 Coordinator 和领域 Agent，以隔离并发 Run 的可变状态。

当前已注册的领域 Agent：

- `DBAgent`
- `ServerAgent`
- `LogAgent`

质量与汇总组件：

- `DebateArena`
- `ReflectionEngine`
- `ReportAgent`

当前模型 Provider 配置并不由 v1 API 暴露；模型由后端配置和运行时装配读取。模型服务原型页中的 Ollama、DeepSeek、OpenAI 和 OpenAI Compatible 均属于待实现产品配置能力，不能当作当前已存在接口。

## 11. 后续接口缺口

以下内容当前不应被前端假定为已存在：

### 模型服务

```text
GET  /model-providers
POST /model-providers
GET  /models
POST /model-providers/{id}/test
PATCH /model-policy
```

以上只是未来可能的接口方向，不是当前契约。

### 服务监控

当前缺少独立的：

- 历史指标趋势查询
- 指标筛选和时间范围查询
- 告警列表与告警详情
- 监控策略配置
- 采集状态与数据新鲜度查询

### 服务接入

当前缺少正式的：

- 服务注册/编辑/停用接口
- 连接测试接口
- 凭据引用配置接口
- 服务类型能力发现接口
- 监控能力配置接口

### 文档知识库

当前缺少正式的：

- 文档上传
- 文档删除或归档
- 索引状态查询
- 文档检索
- 文档权限和来源管理

## 12. 前端接入建议

1. 先读取 `/health`，用于显示后端模式和当前模型摘要。
2. 会话工作台启动时读取 `/sessions`，按需读取 `/messages` 与 `/runs`。
3. 提问时先确保 Session 存在，再调用 `POST /sessions/{session_id}/runs`。
4. 每个 Run 保存 `run_id`、`trace_id` 和最后的 event sequence。
5. 优先订阅 `/runs/{run_id}/stream`；断线时使用 `Last-Event-ID` 或 `after_sequence` 续接。
6. Run 终态后读取 `/runs/{run_id}`，以结构化结果作为最终展示来源。
7. 服务页只展示服务 API 返回的快照，并根据 `mode`、`source_status` 和 `observed_at` 标注真实状态。
8. 未有正式 API 的模型、文档和完整监控功能只能显示为原型或未启用，不能在前端伪造实时状态。
9. 审批和执行按钮必须根据 Proposal 状态渲染，不能让聊天文本直接触发执行。
10. 不在前端保存、打印或回传 API Key、凭据、原始工具参数或敏感服务数据。
