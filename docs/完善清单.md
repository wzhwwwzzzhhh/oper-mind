## P0 必修（核心能力）

### P0-1 受控动作闭环三重断点 —— 端到端永远跑不通
- **现象**：提案卡永不出现；即使绕过第一处，执行也会 BLOCKED。
- **根因**（三处叠加，修一处不够）：
  1. 收集器 `backend/src/infrastructure/diagnosis/postgres_missing_index.py:33`：`to_regclass('public.orders') != "public.orders"`——真实 PG 默认 search_path 下返回 `"orders"`，恒不等 → 信号永不产出。
  2. 执行器 `backend/src/infrastructure/actions/postgres_target_executor.py:155`：`_table_exists` 同款 to_regclass 比较 bug → 前置条件恒失败。
  3. 组装器 `backend/src/infrastructure/diagnosis/result_assembler.py:62-73`：investigation 为 None 时结构化字段全空（confidence 0.0 / severity INFO / 根因证据空）。
- **修复思路**：① 改 `is None` 存在性判断（两处）；② 测试 mock 值 `"public.orders"` → `"orders"`（`tests/test_p5_controlled_action.py:156`）防再犯；③ 修完后补验完整闭环：提案 → 审批 → 执行 → Verify（EXPLAIN 转 Index Scan）。
- 状态：**✅ 已修复**（2026-08-27，issue #100）
  - ① 两处 `to_regclass` 已改为 `is None` / `is not None` 判断，并加注释说明 regclass 按 search_path 简化；
  - ② 测试 mock 已改为 `"orders"`，并新增 4 个收集器用例（简化名产出信号 / 表不存在 / 索引已存在 / 无顺序扫描）；
    `pytest tests/test_p5_controlled_action.py -q` → 11 passed；
  - ③ 受控靶场真实链已完成：Preflight 为 Seq Scan 且固定索引不存在；提案 → `local_operator` 人工审批 → 二次确认 → target 执行 → 独立 Verify；终态 `verified`；
  - Postflight：固定索引存在且有效，Seq Scan=false，命中目标索引的 Index Scan=true；8 类审计事件各一次且顺序完整；
  - 真实链同时修复结果响应 schema 漏接 `missing_index` 导致的 500，并同步 OpenAPI 类型；详见 `docs/workpack/归档/P8-controlled-action-closeout/evidence.md`；
  - 关联卡点：`docs/跑通验证.md` C1 已解决。
