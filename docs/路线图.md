## 不变的产品方向

OperMind 是一个以会话为主入口的正式多 Agent DevOps Copilot Web 产品：用户在类似 DeepSeek 的界面中提问、追问和下达受控运维指令；系统在已授权的服务范围内，由多 Agent 协作调查并给出结论、证据、简要 Trace，以及必要时的审批、执行与验证反馈。

多 Agent 内核保持为：

```text
Coordinator（动态路由）
→ DB / Server / Log 等领域 Agent
→ Debate / Reflection（质量保障）
→ Report Agent
→ 最终诊断报告
```

慢查询只是用于穿过产品全链路的**第一个简单验证问题**，不是产品边界、首页主题或独立的大型建设阶段。

## 四个阶段

### 第一阶段：正式会话与多 Agent 内核整合

目标：让用户能在正式会话页面中实际使用多 Agent 协作能力。

```text
会话消息
→ 创建 Run
→ Coordinator 路由
→ DB / Server / Log Agent
→ Debate / Reflection
→ Report Agent
→ 正式回答 + 安全 Trace + 会话留痕
```

本阶段重点：

- 会话工作台成为默认产品入口；
- 现有会话、Run、SSE、结果持久化与多 Agent 图整合为一条正式请求链；
- Trace 只展示角色、阶段、状态、耗时和证据摘要，不展示 CoT；
- 多 Agent 图是产品智能内核，不再仅通过旧实验接口运行；
- 不把项目退化为固定慢查询、靶场或展示脚本。

完成标志：用户可以开一个正式会话，提出运维问题，真实经过协调、领域调查、质量复核和报告汇总，并在会话里看到结果和安全 Trace。

### 第二阶段：搭全正式产品骨架，并用简单慢查询验证通路

目标：先形成完整、可扩展的产品框架；慢查询仅作为第一个最简单的验证问题穿过这条框架。

```text
会话工作台
├── 会话与消息
├── 服务选择与服务上下文
├── 多 Agent Runtime
├── 安全 Trace、证据、Run 与留痕
├── 服务中心
│   ├── PostgreSQL / MySQL / Redis 服务实例
│   ├── 接入、连接状态与能力声明
│   ├── 基础当前状态 / 监控入口
│   └── 从服务发起会话
├── Connector / Tool 统一框架
└── 风险操作的提案与审批框架
```

简单慢查询只承担以下验证责任：

```text
选择数据库服务
→ 在会话发起慢查询问题
→ DB Agent 调用受控 Tool
→ 产生事实、结果、Trace 与服务页留痕
```

本阶段不以深入慢查询诊断、复杂索引策略或固定修复动作作为目标。服务接入方式、哪些 Connector 首先真实可用、凭据保存和监控深度，必须在实施前单独确认。

### 第三阶段：逐步丰富和深化运维问题能力

目标：在既有的会话、服务、Agent、Tool、Trace 和留痕框架内不断增加能力，而不是为每个问题重建一套产品流程。

能力可逐步扩展为：

- 数据库：慢查询深化、锁、连接池、容量、索引等；
- Redis：健康、内存、连接、慢日志、热点等；
- 服务与主机：CPU、内存、进程、网络等；
- 日志：错误模式、超时、异常关联等；
- 跨来源联合排障：多服务、多 Agent 的证据汇总与诊断。

每项新增能力都应通过统一的 Connector / Tool / AgentTask / Trace / Result 机制接入。

### 第四阶段：逐步增强动作、知识与平台能力

目标：在产品主链稳定后，按真实需求增加更强的产品能力。

包括但不限于：

- 将确有价值的风险动作接入提案 → 人工审批 → 白名单执行 → Verify；
- 允许目录内 Markdown 知识检索，以及后续知识库能力；
- 用户模型 Provider 与 API Key 设置；
- 正式的会话、调查、服务与知识记忆；
- 历史监控、趋势和告警；
- 登录、多用户、团队、RBAC、部署与运维完善。

这些能力均不得抢在正式会话、多 Agent 内核和服务产品骨架之前，也不得以“实验展示”为目的单独成为主线。

## 研发与产品边界

- 测试、mock、Trace、评测和开发脚本是研发或产品底座资产，不是用户产品的中心。
- 不恢复以靶场、固定订单服务、旧阶段编号或演示脚本为中心的叙事。
- 每一个实现工作包服务于上述四阶段之一；架构、公开 API、迁移、Connector、凭据、真实服务访问、监控和高风险执行仍需先完成详细 Design → Review → 用户确认。
- 第一、二阶段的骨架已由 P0–P7 建成；当前工作是**在既有骨架上做完善**，
  不是重开阶段。第三、四阶段的能力扩展在完善阶段收口后再排。
