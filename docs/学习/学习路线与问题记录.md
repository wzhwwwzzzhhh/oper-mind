## 学习方式

先从下面一个问题开始，选对应官方文档或课程章节。不要求先学完全部资料，也不要求现在就决定所有架构细节。

讨论时尽量按四步记录：你现在怎么理解 → 官方如何说明 → 当前项目有什么证据 → V2 哪些仍需设计。AI 的补充也要标注来源或“推断／建议”，没有证据的不写成现状。

“小实验”是后续可选步骤：先确定目标和边界，再以可控输入、确定性替身验证；接入真实模型／服务、产生费用或新增执行权限另行确认。本次没有创建或运行实验。

## 第一组：概念和契约

### Q01 · 我们说的四种 Agent 组合与系统分层有什么不同？

- 本文编号：①单主 Agent；②主 Agent + 技能／能力包；③主 Agent + 子 Agent（委派受限子任务，由主 Agent 汇总交付）；④独立主 Agent ↔ 独立主 Agent（各自负责业务任务，按需请求对方结果）。③与④平行，可以组合使用。
- 当前疑问：为什么第三、第四种可以同时存在，而不是必须逐级升级？
- 对应资料：G06（Workflows and agents）、P09（Multi-agent patterns）。
- 项目参照：[Agent 组合与平行维度图解](../进行中/V2-主Agent闭环/方向/图解/02-Agent组合与平行维度.md)。
- 需要自己解释：任务拆分需求与业务独立性分别决定什么？
- 理解状态：待讨论。

## 第二组：并发和两种协作

### Q06 · 多个请求同时进来，与一个图内部并行有什么区别？

- 对应资料：P01–P03、G04、P07；C02 的 Module 4。
- 需要自己解释：请求并发、Run 隔离、同会话更新、图内分支、工具并发分别在哪一层处理？
- 理解状态：待讨论。

### Q07 · State 和 thread_id 是否足以保证“绝对不串数据”？

- 对应资料：G04、G08、P04–P06、P08。
- 当前代码证据（2026-10-12 核对）：[CoordinatorDiagnosisExecutor](../../backend/src/infrastructure/diagnosis/coordinator_executor.py)每次 stream 调用工厂创建内核，用于隔离不同 Run 的可变 Agent 状态；[BaseAgent](../../backend/src/core/agent.py)持有 short_term、current_query 等实例字段。
- 因此：不能把“当前所有 Run 共享单例而串数据”写成既有事实。这里的工厂隔离也不自动证明所有并发情况均已覆盖。
- 待设计／验证：若缓存图或复用对象，哪些变量仍在共享对象或闭包中？同一会话两个 Run 怎么处理？工具与外部资源还受哪些并发约束？
- 理解状态：待讨论。

### Q08 · Reducer 在解决什么，是否相当于加锁？

- 对应资料：G04 的 Reducers、P07；C02 的 Module 2 / 4。
- 需要自己解释：两个并行分支更新同一字段时，追加、覆盖、去重等规则分别意味着什么？
- 边界：图内状态合并规则不是全局互斥，也不能解决全部共享对象、数据库或外部资源竞争。
- 理解状态：待讨论。

### Q09 · 取消、超时、失败传播和重试怎么区分？

- 对应资料：P03、P06、G08、G10。
- 需要自己解释：停止等待是否等于任务停止？父任务取消后，子任务和工具调用发生什么？重试可能重复什么副作用？
- 待设计：取消责任、错误归属、预算计数、重试上限与幂等处理，不能只添加 timeout 参数就宣布完成。
- 理解状态：待讨论。

### Q10 · 子图、子 Agent、独立主 Agent、Handoff 是不是同一个概念？

- 对应资料：P08–P12、A12；C05 的委派章节。
- 项目参照：[子 Agent 委派](../进行中/V2-主Agent闭环/方向/图解/05-子Agent委派与上下文隔离.md)、[独立主 Agent 协作](../进行中/V2-主Agent闭环/方向/图解/06-独立主Agent协作与交付.md)。
- 需要自己解释：谁拥有上下文、谁限制工具范围、谁负责最后交付？接管会话与请求结果有什么不同？
- 待设计：跨主 Agent 的请求／响应关联、重复请求处理、协作深度限制；不预设必须分布式部署。
- 理解状态：待讨论。
