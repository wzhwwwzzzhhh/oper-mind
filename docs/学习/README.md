## 这份目录收录什么

这里以原始官方材料为主，中文注释帮助定位内容，不替代原文。不会用社区转载、GitHub 星数或未核验的宣传结论代替机制说明。

- [01 · 官方课程与视频](官方资料/01-官方课程与视频.md)：13 项。课程章节、配套资料和官方视频频道。

- [04 · 并发、隔离与协作](官方资料/04-并发隔离与协作.md)：12 项。异步任务、线程、取消、图内合并、子图、路由和接管。

建议从一条短路线开始，其余按遇到的问题查阅；不要求全部读完才继续项目。

## 第一轮：先搞懂我们正在讨论的内容

1. **底层执行模型**：看 [C01 · LangGraph Essentials](官方资料/01-官方课程与视频.md#c01)，再读 [G04 · Graph API](官方资料/02-LangGraph基础与状态.md#g04) 的 State、Schema、Reducers、Nodes、Edges。尝试用自己的话说清“一次运行的数据如何变化”。
2. **契约**：读 [K01 · Pydantic Models](官方资料/03-契约验证与API.md#k01) 和 [K04 · Strict Mode](官方资料/03-契约验证与API.md#k04)。再看 [C02 · Introduction to LangGraph](官方资料/01-官方课程与视频.md#c02) 的 Module 2 中 State Schema、State Reducers、Multiple Schemas。
3. **并发与隔离**：先看 [P01 · FastAPI 并发](官方资料/04-并发隔离与协作.md#p01) 和 [P03 · Coroutines and Tasks](官方资料/04-并发隔离与协作.md#p03)；再看 [P07 · 并发更新错误](官方资料/04-并发隔离与协作.md#p07)、[P08 · Subgraphs](官方资料/04-并发隔离与协作.md#p08)，配合 C02 的 Module 4 中 Parallelization、Sub-graphs、Map-reduce。
4. **能力装配**：读 [A02 · Agents](官方资料/05-能力装配上下文与框架候选.md#a02)、[A04 · Tools](官方资料/05-能力装配上下文与框架候选.md#a04)、[A05 · Structured output](官方资料/05-能力装配上下文与框架候选.md#a05)。再按疑问选 Skills、Middleware 或 Deep Agents 课程。
5. **验证而非猜测**：读 [E01 · Test agents](官方资料/06-评测与官方源码实例.md#e01)，从[官方课程源码 E04](官方资料/06-评测与官方源码实例.md#e04)选择与当前问题对应的最小示例。运行前确认配置、外部访问与费用；本次只整理资料，未运行示例。

每轮只推进一个疑问：官方材料说明机制 → 你用自己的话解释 → 我们对照代码／图解 → 有必要时再做受控小实验。解释不一致时保留问题与证据，不默认 AI 的解释正确。

## 和项目文档怎么配合

- [V2 计划骨架](../进行中/V2-主Agent闭环/方向/计划骨架.md)记录我们拟定的方向；[八张图解](../进行中/V2-主Agent闭环/方向/图解/README.md)帮助定位模块。
- “四档 Agent”更准确地说是**四种组合**；子 Agent 委派和独立业务主 Agent 协作是平行维度，不是四个串行层级。系统分层是另一个概念。
- Capability、任务／结果契约和独立主 Agent 协作协议是应用层待细化设计；官方的 Tool、Skill、Subgraph 或 Handoff 不会自动替我们完成它们。
- 当前事实仍以[产品定义](../事实源/产品定义.md)、[路线图](../事实源/路线图.md)、[开发规范](../事实源/开发规范.md)为准。资料库不改变功能启用状态、执行权限或原有 Design → Review → 用户确认流程。
