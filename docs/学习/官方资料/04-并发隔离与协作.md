# 并发、隔离与协作

> 核验日期：2026-10-12。资料入口与核验边界见[学习目录](../README.md)。
> 共 12 项；“先学 / 按需学 / 进阶”表示建议顺序，不是开发门禁。

按问题分开学习：多个请求同时进入后端、多个 Run 的对象隔离、同一会话的更新、一个图内并行分支、不同 Agent 之间的协作。它们不是同一种“并发”，也不会被一个 thread_id 或一个锁同时解决。

<a id="p01"></a>

## P01 · FastAPI Concurrency and async / await

- 官方入口：[FastAPI Concurrency and async / await](https://fastapi.tiangolo.com/async/)
- 形式／优先级：官方教程；先学。
- 重点看：并发与并行、阻塞 I/O、async def 和普通 def 的使用边界。
- 对应疑问：后端能同时接待请求，为什么仍可能阻塞或串行？

<a id="p02"></a>

## P02 · Python 3.11 asyncio

- 官方入口：[Python 3.11 asyncio](https://docs.python.org/3.11/library/asyncio.html)
- 形式／优先级：官方文档；先学。
- 重点看：事件循环、协程和异步库的整体入口。
- 对应疑问：异步执行和多线程、多进程的区别是什么？

<a id="p03"></a>

## P03 · Python Coroutines and Tasks

- 官方入口：[Python Coroutines and Tasks](https://docs.python.org/3.11/library/asyncio-task.html)
- 形式／优先级：官方文档；先学。
- 重点看：create_task、gather、TaskGroup、取消和超时。
- 对应疑问：多个子任务怎样等待、收集结果、处理失败和取消？
- 使用边界：取消通常需要协作；发出取消请求不证明底层外部操作或任意线程已经停止。

<a id="p04"></a>

## P04 · Python asyncio Synchronization Primitives

- 官方入口：[Python asyncio Synchronization Primitives](https://docs.python.org/3.11/library/asyncio-sync.html)
- 形式／优先级：官方文档；按需学。
- 重点看：Lock、Event、Semaphore；区分互斥、通知和并发额度。
- 对应疑问：什么时候需要保护共享状态，什么时候只需限制同时执行数量？
- 使用边界：asyncio 同步原语面向异步任务，不是通用线程锁，也不自动解决跨进程资源竞争。

<a id="p05"></a>

## P05 · Python threading

- 官方入口：[Python threading](https://docs.python.org/3.11/library/threading.html)
- 形式／优先级：官方文档；按需学。
- 重点看：Thread、Lock、线程共享内存及线程生命周期。
- 对应疑问：同步工具放到线程运行后，可变实例字段由谁保护？

<a id="p06"></a>

## P06 · Python concurrent.futures

- 官方入口：[Python concurrent.futures](https://docs.python.org/3.11/library/concurrent.futures.html)
- 形式／优先级：官方文档；按需学。
- 重点看：Executor、Future、result(timeout)、cancel 和 shutdown。
- 对应疑问：等待超时是否意味着任务已经被中断？
- 使用边界：result(timeout) 只限制等待；已运行任务能否停止取决于实际执行机制，不能把等待超时当执行取消。

<a id="p07"></a>

## P07 · INVALID_CONCURRENT_GRAPH_UPDATE

- 官方入口：[INVALID_CONCURRENT_GRAPH_UPDATE](https://docs.langchain.com/oss/python/langgraph/errors/INVALID_CONCURRENT_GRAPH_UPDATE)
- 形式／优先级：官方错误说明；先学。
- 重点看：并行节点更新同一 State key 的示例，与 G04 的 Reducers 对照。
- 对应疑问：为什么两个分支各自运行成功，合并时却出错？
- 使用边界：修复这一类图内合并错误，不证明不同 Run、用户、线程或外部资源已隔离。

<a id="p08"></a>

## P08 · Subgraphs

- 官方入口：[Subgraphs](https://docs.langchain.com/oss/python/langgraph/use-subgraphs)
- 形式／优先级：官方文档；先学。
- 重点看：父子状态 schema、共享字段与转换、持久化配置。
- 对应疑问：子图的状态如何传递，哪些字段需要共享或隔离？
- 使用边界：子图是图的组合机制；子 Agent 还需要独立任务、上下文、工具范围和结果责任。

<a id="p09"></a>

## P09 · Multi-agent patterns

- 官方入口：[Multi-agent patterns](https://docs.langchain.com/oss/python/langchain/multi-agent)
- 形式／优先级：官方模式文档；按需学。
- 重点看：Subagents、Handoffs、Skills、Router 等模式与选择依据。
- 对应疑问：能力挂载、委派、路由和接管分别解决什么问题？
- 使用边界：四种组合是我们拟定的产品边界，不是官方规定的四个等级。

<a id="p10"></a>

## P10 · Subagents

- 官方入口：[Subagents](https://docs.langchain.com/oss/python/langchain/multi-agent/subagents)
- 形式／优先级：官方模式示例；按需学。
- 重点看：主 Agent 通过受限子任务获取结果的组织方式。
- 对应疑问：派子 Agent 和调用普通 Tool 有什么不同？

<a id="p11"></a>

## P11 · Router

- 官方入口：[Router](https://docs.langchain.com/oss/python/langchain/multi-agent/router)
- 形式／优先级：官方模式示例；按需学。
- 重点看：任务分类、单路或多路分发与结果合并。
- 对应疑问：路由器、主 Agent 和独立业务 Agent 是否承担同一种责任？

<a id="p12"></a>

## P12 · Handoffs

- 官方入口：[Handoffs](https://docs.langchain.com/oss/python/langchain/multi-agent/handoffs)
- 形式／优先级：官方模式示例；按需学。
- 重点看：控制权转交、状态传递和接管后的执行。
- 对应疑问：让另一 Agent 接管当前交互，和请求它交付一个结果有什么区别？
- 使用边界：Handoff 不自动等于 V2 的独立主 Agent 协作协议；请求关联、权限、重复处理与最终交付责任仍待设计。
