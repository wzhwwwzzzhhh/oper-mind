# OperMind 当前文档

> 更新：2026-08-09。本目录按「事实源 / 工作地图 / 执行产物」三层组织，层级决定权威性：
> **冲突时以事实源为准**，工作地图和执行产物都不能推翻它。

## 第一层：事实源（唯一权威）

改动这三份必须先 Design → Review → 用户确认。

| 文件 | 作用 |
|---|---|
| `产品定义.md` | 产品定位、用户体验、模块边界、已决策事项与未决事项。 |
| `路线图.md` | 四阶段产品路线、当前所处阶段、下一步必须完成的设计。 |
| `开发规范.md` | 前后端、Agent、Tool、凭据、安全、测试、提交与完善流程规则。 |
| `架构与开发路径.md` | 架构北极星：主脊、硬规则、不可妥协边界与阶段路径。 |

## 第二层：工作地图（当前在做什么）

反映当前实际状态，随开发滚动更新，不需要 Design 门。

| 文件 | 作用 |
|---|---|
| `完善清单.md` | **当前阶段主线**：P0/P1/P2 分级的待修条目，逐条含现象、根因、修复思路、状态。 |
| `backlog.md` | 体验发现收集入口：起服务用出来的新问题先挂这里，再分级并入完善清单。 |
| `跑通验证.md` | mock 与真实模式全链路验证记录、环境拓扑、卡点清单。 |
| `接口清单.md` | 按四个管理分类的接口现状：已有 / 未接线 / 契约不完整 / 缺失（区分欠账与刻意不做）。 |

## 第三层：执行产物（按域/阶段归档）

| 目录 | 作用 |
|---|---|
| `prd/` | 需求唯一事实来源，按域+阶段两级组织；索引见 `prd/README.md`。 |
| `design/` | 各切片的技术 Design（arch-design 产出，需 Review 与用户确认）。 |
| `workpack/` | 工作包执行记录：计划 → 审查 → 证据；索引见 `workpack/README.md`。 |
| `Suggestion/` | PRD 工程化审查与待 PM 决策事项；不是产品事实源。 |
| `归档/` | 已被取代的历史文档，只读保留，**不作为当前上下文**。 |

## 文档使用规则

- 事实源冲突时以第一层为准；工作地图与执行产物只能补充细节，不能改变产品边界。
- 当前代码是已有技术资产，不自动等同于产品规格；已实现 ≠ 已确认。
- `归档/` 内文档（含 `正式产品架构设计-v1.md`、`P3前端重构实施计划.md`、历史接口清单）只作历史参考。
- 任何重大产品、数据模型、凭据、Connector、监控、权限、执行或外部连接决策，必须先写进第一层，再进入实现。
- 未实现的能力在文档和 UI 中都必须如实标注"未启用"，不得制造产品承诺。
