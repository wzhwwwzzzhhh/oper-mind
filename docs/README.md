## 2. 文档分层

1. **进度层**：只有 `_A-Plan-总览.md` 能声明项目状态、执行顺序和“当前唯一下一步”。
2. **产品/范围层**：R1 产品重定位目录定义当前体验优先级；`_B-V1产品化开发计划.md` 定义阶段二范围和里程碑展开。
3. **规则层**：`docs/开发规范.md` 定义研发、文档、交接和安全规则。
4. **契约与证据层**：P0 API 契约、P2/P3 测试记录及源码是可继承的技术事实；它们不能反向决定未经确认的产品体验。
5. **历史层**：原始方案、早期路线图、`docs/初始开发/`、M 阶段日志和完成里程碑的开发日志均保留，不删除、不改写成当前计划。

## 3. 历史材料入口

- `00-项目方案说明书.md`：原始多 Agent 运维诊断方案与阶段一背景。
- `开发路线图与规划.md`：阶段一研发路线的历史快照。
- `前端开发路线图.md`：`report/` 的 M7 研发/实验/Trace 前端历史路线。
- `初始开发/`：早期学习与实现记录，不再新增。
- `A-Plan/`：对外材料，与研发执行日志分离。

## 4. 防止文档再次跑偏

- 计划调整先更新 A-Plan，再同步 B-Plan、R1（如影响体验）和规则镜像；不在多个文件分别维护“下一步”。
- `HANDOFF.md` 仅服务当前可恢复工作。提交或移交完成后，必须明确标为已关闭并指向新的恢复入口。
- 历史文档中的路径、行号、状态和“当前”均以其日期为准；需要事实时回查相应提交、测试记录和源码。
- 不用假监控、告警、真实数据源或过期 UI 原型填补文档空白；未实现能力必须写明边界。
