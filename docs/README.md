## 写作约定

文档给做产品和架构判断的人看，不是给审查代理看的。

- 用陈述句写“是什么、做什么、怎么算完成”；否定句只用于真正的安全边界。
- 一条规则一句话。安全边界每条只写一次，不重复免责声明。
- 术语首次出现给中文短名，之后用短名（Capability → 能力包，Run → 一次运行，Trace → 过程视图）。
- 过程细节（谁在第几轮审查、哪个门禁叫什么）写进 workpack 证据，不写进事实源和方向文档。
- 事实、决策、边界、状态照实写；不写“可能、原则上、不排除”这类无法执行的表述。
