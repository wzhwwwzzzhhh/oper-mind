## 读图要点

- 主 Agent A 与 B 各自拥有业务任务和上下文，双方不是长期主管 / 下属关系。
- 通过有标识的请求、响应、输入与结果引用协作；受理请求和完成结果是两个不同事件。
- 发起方负责自己的最终交付；接收方负责承接任务。取消请求不能默认取消对方所有独立工作。

第一版建议在同一后端内验证，不预设外部 A2A 协议或消息中间件。跨业务超时、权限、循环请求上限、结果版本和取消范围待 Design；不会默认交换完整会话或记忆。

## 可编辑的结构源图

```mermaid
sequenceDiagram
    participant A as 主 Agent A / 业务 A
    participant B as 应用协作通道
    participant C as 主 Agent B / 业务 B
    A->>B: 请求候选：目标、输入引用、截止条件
    B->>B: 校验范围、关联请求、处理重复
    B->>C: 投递有明确边界的协作任务
    C-->>B: 已受理 / 拒绝 / 需补充信息
    B-->>A: 受理状态，不等于任务完成
    C->>C: 独立执行，可挂能力或派子 Agent
    C-->>B: 结果候选与引用
    B->>B: 校验、接纳并关联响应
    B-->>A: 交付结果或明确失败
    A->>A: 整合进业务 A 的最终交付
```

Mermaid 与 SVG 展示同一组职责；SVG 简化部分返回线以保持可读性，以明确的边界说明为准。修改结构时需同步源图、SVG 与 PNG 预览。
