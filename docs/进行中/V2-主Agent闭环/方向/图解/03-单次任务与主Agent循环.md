## 读图要点

- 先接纳任务并装配允许能力、资源与本次上下文，再调用模型作语义决策。
- 一次语义决策节点默认一次模型调用；工具结果可能触发下一轮，所以不是整项任务只调用模型一次。
- 模型给出结构化候选，程序校验再执行。工具观察、最终答复、追问和失败有不同处理路径。

失败处理这里做了简化，具体可重试错误、部分完成及追问恢复策略还需 Design。子任务和跨业务调用接入同一候选校验过程，详见图 05 / 06；正则不用于代替生产语义路由。

## 可编辑的结构源图

```mermaid
flowchart TB
    INPUT["消息 → 应用接纳任务"] --> LOAD["装配本次上下文 / 已绑定资源 / 允许能力"]
    LOAD --> LIMIT["程序检查时间 / 调用 / 费用预算"]
    LIMIT -->|允许继续| MODEL["一次模型调用：结构化语义决策"]
    MODEL --> CHECK["程序校验 schema / 注册项 / 执行资格"]
    CHECK -->|答复| FINAL["接纳结果 → 安全展示"]
    CHECK -->|缺信息| ASK["等待用户补充，再装配上下文"]
    CHECK -->|工具 / 能力| EXEC["Workflow 或 Tool → ToolGateway"]
    EXEC --> OBS["结构化观察 / 结果引用"]
    OBS --> LIMIT
    ASK -. 新输入 .-> LOAD
    LIMIT -->|达到上限| STOP["停止并记录明确状态"]
    CHECK -->|无效或不可执行| STOP
    EXEC -->|执行失败| STOP
```

Mermaid 与 SVG 展示同一组职责；SVG 简化部分返回线以保持可读性，以明确的边界说明为准。修改结构时需同步源图、SVG 与 PNG 预览。
