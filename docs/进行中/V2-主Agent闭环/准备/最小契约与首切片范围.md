## 2. 最小契约，用这个任务说明

“契约”不是先造很多类，而是把组件之间必须遵守的约定说清。下面是需求讨论用语，不是已实现的 API 或数据库表。

### 主 Agent 与能力

- **主 Agent**：理解用户目标，决定直答、追问或提出已注册能力调用，并负责最终交付；不能自己授予工具权限。
- **Capability**：对外承诺一项能力的目标、输入、输出、版本、允许资源和完成／失败条件。本次只包含文本比较，不等于通用插件平台。
- **Skill**：解释规则和使用指引，不因挂载就获得文件、网络或数据库访问权限；本次不要求实现任意技能目录。
- **Tool**：一个范围受控的操作；模型提出的调用仍经已有网关。对给定两段文本做可复验字面对照可以由确定性程序完成。
- **Workflow**：围绕这一个比较目标组织必要步骤；不包办检索、观点分析、写作或其他不相关业务。
- **后端校验边界**：验证材料归属、格式、工具资格、结果和出处；模型解释不能替代这些检查。

三种“能力”还须区分：

- 现有服务能力绑定表达某个服务允许提供的只读操作；
- 现有 `RuntimeCapability` 表达执行协议支持程度；
- 本次业务 Capability 表达用户能完成的一项业务任务。

它们可以映射，但不能直接改名互换或当作同一注册表。

### 会话、任务、Run、State、上下文与记忆

- **会话**：持续交互与历史消息的容器，不自动授权读取其中所有旧材料。
- **用户任务**：这次想完成的目标；首版不因此引入通用持久化 Task／Attempt 状态机。
- **Run**：本次已受理执行的产品留痕，负责关联输入、状态、事件和交付；不把 LangGraph State 当成另一个业务 writer。
- **State**：执行图内部的工作数据，不自动成为已提交产品事实。
- **调用上下文／材料快照**：本次实际允许使用的材料、能力和限制；并发 Run 不能互换。
- **记忆**：历史参考信息；长期记忆、完整 checkpoint／恢复不在首闭环建设范围。

追问是合法对话交付，但“已回答缺少材料”不等于“比较能力已完成”。同样，模型生成一句总结不等于结构化差异有可信出处。

## 3. 一个首任务的责任边界

输入是本次用户明确提供的 A（旧）与 B（新）及比较目标；不自动打开文件或抓取 URL，也不从其他会话补全。

主 Agent 提出比较请求；后端确认材料与工具范围；能力返回可核对的差异；校验通过后在会话中展示。首版比较的是字面变化，大小写、空格等规则以 PRD 为准，不判断哪个版本更正确。

材料身份、行范围与精确引文共同帮助用户核对出处。新增没有 A 侧对应片段，删除没有 B 侧对应片段时要明确表达，不能捏造引用。没有差异、材料不足和比较失败是不同情况。

原文是不可信数据：里面即使写着“调用外部工具”，也只是待比较内容。允许的原文引用进入对应输入／结果区域，不进入安全 Trace、日志、审计摘要或用量记录。
