## 1. 本计划是什么

用户已同意先展开 V2 平台初版的第一步，并要求先写开发计划。本文件将第一步拆成三个准备切片，明确交付物、证据要求、实施前置门和下一入口。

这里的“第一步”是**使后续主 Agent + 一个 Capability 闭环具备明确、可验证的实施依据**，不是在本阶段把四种组合全部实现。子 Agent 委派与独立主 Agent 协作是平行维度；本阶段只保留必要接缝，不提前实现两套协作机制。

本文件不取代唯一需求源、正式实施 Design 或 Workpack。当前产品与工程事实仍以[产品定义](../../../事实源/产品定义.md)、[路线图](../../../事实源/路线图.md)、[开发规范](../../../事实源/开发规范.md)为准。

## 3. 目标与排除项

### 只做

- **准备目标 1 · 现状可追溯**：明确正式生产调用链、已有通用资产、业务耦合点与真实缺口，所有现状结论能指到代码或已交付证据。
- **准备目标 2 · 边界可解释**：说明主 Agent、Skill、Tool、Workflow、Capability，以及任务、运行、上下文、结果分别由谁负责。
- **准备目标 3 · 复用有依据**：明确哪些直接沿用、哪些需要适配、哪些仍需验证；优先复用 P10/P11，不再并行创建职责重叠的基础协议。
- **准备目标 4 · 首切片可验收**：确定第一个验证任务的输入、输出、完成／失败条件、资源边界和最小前端范围。
- **准备目标 5 · 后续能开工**：形成对应 PRD／Design 的明确输入和候选组件验证入口，完成必要审查与用户确认后再交正式 Workpack。

准备目标 1–5 是本准备阶段的检查目标，不是假定已确认 PRD 的 AC 编号，也不等同于 Workpack 的 G0–G2 实施门禁。

### 明确不做

- 不修改当前 Coordinator 默认策略、生产 Agent 循环、工具装配或 Run 事实写入。
- 不实现完整 Capability 注册／加载平台、子 Agent 委派或主 Agent 间通信。
- 不新增业务数据库表、迁移、公开 API、OpenAPI／SSE 协议或前端页面。
- 不重做整个前端；只提出首条闭环涉及的页面职责与兼容范围。
- 不升级依赖、不预先采用 LangChain／Deep Agents，不整体迁移框架。
- 不实现长期记忆、RAG、MCP、Recovery、分布式调度或跨进程通信。
- 不接入真实模型、数据库、主机、邮箱、网络搜索等外部资源；不读取用户凭据。
- 不修改或删除 V1 历史证据、基线 fixture、归档 Workpack 或其他任务文件。
- 准备计划本身不授权创建 GitHub Issue／PR。后续完整 PRD 已获用户确认，故按需求流程创建唯一 Issue #133；仍不建 PR、不提交、不推送、不发布。

## 5. 三个准备切片

以下准备范围已由用户确认；切片产物仍需分别审阅，形成文档不自动表示达到全部完成条件。

### 准备-1 · 现状与复用盘点（对应准备目标 1、3）

**要达成的结果**：后续开发者知道现有生产链路在哪里，以及每项资产应沿用、适配、保留为业务实现，还是等待验证。

工作内容：

- 从正式 API、装配、Run、Runtime、ToolGateway、结果组装到前端，追踪一条实际链路。
- 核对会话／消息、模型配置、mock／用量、执行事件、安全投影、状态隔离和结果持久化的复用边界。
- 按“当前事实／证据位置／复用建议／未证实风险／后续验证”记录，不用名称相似代替兼容性判断。
- 将业务耦合与安全保证分开：允许后续替换业务语义，不允许顺带削弱只读、隔离、唯一终态和安全 Trace。

产物：[现状与复用盘点](现状与复用盘点.md)及复用建议已获用户确认；本轮未运行代码验证。

完成条件：

- 正式主链每个主要接缝都有代码依据。
- 上述通用资产和关键耦合点都有处置建议，没有“全通用／全重写”的笼统结论。
- P10/P11 已交付能力、保留 gap 与 V2 待建项明确区分。
- 结论经用户审阅；有争议项保持未决，不写成既定方案。

### 准备-2 · 最小契约与首切片范围收敛（对应准备目标 2、4）

**要达成的结果**：能够用一个小任务说明组件如何协作，并明确第一个正式闭环要交付什么。

工作内容：

- 定义每个角色的职责、输入、输出、失败、完成条件、资源范围及版本责任；先说明语义，不预设类名或数据库表。
- 区分会话、Run、子任务、框架 State、调用上下文和长期记忆，不一次实现全部对象。
- 对照已有端口与 typed contract，写出沿用项、差距和待决策项；无明确 gap 不新造第二套生产执行 port。
- 首任务及完整 PRD 的输入／结果上限、完成与失败等细项均已确认，不顺带引入文件上传或任意磁盘访问。
- 划定首条闭环的前端范围：发起任务、展示安全进度／结果、识别取消／失败／不可用；完整信息架构和所有管理页不作为前置。
- 语义决策使用结构化模型输出；注册项、格式、权限、资源归属、状态与预算仍由程序验证。无效输出、缺少输入与不可用行为必须明确。
- 把待实施需求按仓库规范放入唯一 PRD，而不是把本目录讨论稿复制成第二套滚动需求账本。

产物：[最小契约与首切片范围](最小契约与首切片范围.md)和[主 Agent 与文本比较闭环 PRD](../首闭环/PRD.md)已收敛，PRD 状态为已确认；不是已实施。

完成条件：

- 主 Agent、Capability、Skill、Tool、Workflow 及两种协作可以清楚区分。
- 首任务输入、输出、完成条件、失败情况、资源范围及前端可见反馈经用户确认。
- 需求中区分首切片必须项与后续项；不提前承诺商业业务、通用零改动接入或多 Agent 必然更优。
- 正式 PRD 有可检查 AC 与排除项，经过需求审查和用户确认；本计划不能自动授予该状态。

### 准备-3 · 候选兼容验证与实施交接（对应准备目标 3、5）

**要达成的结果**：依据证据选择首闭环使用的实现接缝，并具备进入正式 Workpack 的条件。

工作内容：

- 围绕现有循环、`create_agent`、Deep Agents 列出最小比较问题；不比较星数、不要求重建完整框架。
- 验证矩阵至少覆盖：现有模型配置与确定性 mock、ToolGateway 不可绕过、结构化事件／结果、安全投影、Run 状态隔离、终态、超时／取消边界和用量记录。
- 对每个候选记录“已由当前证据支持／需适配／不支持／未验证”。没有运行证据时不写“已通过”或作最终采用结论。
- 不要求把所有候选完整实现后再决定；证据不足的候选保留为“未验证”。如果现有循环足以支撑已确认的首任务，可优先复用，避免为比较而扩大范围；适用性仍需有对应证据。
- 本次仅规划验证。需要新增实验代码、安装候选依赖或运行兼容探针时，先确认研究／实施范围及对应门禁，在隔离工作区使用可控输入和确定性替身；不改主仓库环境、不接真实资源。
- 对选中的首切片写正式实施 Design，明确安全边界、端口适配、状态所有权、文件改动面和验证方法；完成独立 Review 和用户确认。
- 正式 Workpack 的建立、1–3 个实施切片、专用 worktree、基线 SHA 和计划确认按 `dev-plan` 另行执行。V2 本阶段编号不借用历史 P10/P11 或迁移文件中的 P14 标记。

产物：[候选兼容验证记录](候选兼容验证记录.md)与[正式 Design](../首闭环/Design.md)已形成，后者已获用户确认；[Workpack 计划](../首闭环/Workpack-计划.md)待确认。运行探针未执行，准备-3 不标完成，实际证明由该计划实施-2 的 G2 出口跟踪。

完成条件：

- 实际采用／适配的组件有验证依据；尚未验证的候选不成为正式装配决策。
- 正式 PRD、Design、Review 和用户确认记录可追溯。
- 后续 Workpack 只覆盖主 Agent + 一个能力闭环，不混入第二业务能力或两种协作的完整实施。
- 当进入 Workpack 时，逐条映射正式 AC，不把准备目标 1–5 当成未经确认的 AC 替身。

- 兼容探针应验证成功／安全失败、跨 Run 隔离、图内合并、同会话并发策略，以及“停止等待”和“底层停止”的差别。示例不应靠长时间 sleep 或真实外部访问证明行为。
- 每项记录基线、命令、确定性输入、实际输出和未覆盖点；未执行只记“未执行”，不能只写 PASS。
