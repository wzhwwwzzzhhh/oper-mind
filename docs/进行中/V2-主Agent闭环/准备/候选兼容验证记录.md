## 1. 问题与证据等级

这里只判断“怎样承载主 Agent + 一项纯文本能力”，不比较流行度，不评判多 Agent 必然优于单 Agent。

- **当前源码支持**：代码中能看到接缝，不表示本轮执行通过。
- **官方文档支持**：官方描述提供机制，不表示与本仓库指定版本兼容。
- **需适配**：存在明确不匹配，必须由正式 Design 和实施验证消除。
- **未验证**：未运行候选探针；不能据此给兼容 PASS。

本轮通过 Context7 检索 LangChain 官方 Python 文档，并只读核对本地源码／依赖清单；未安装依赖、导入运行候选、修改生产代码、执行测试或访问模型／业务服务。

## 2. 共同核查基线

### C1 · 模型、mock 与用量

[LLMClient](../../../../backend/src/core/llm.py)是自有 `chat` 接口；保留 Provider／参数解析、真实 usage 采集。不能因它内部使用 OpenAI SDK，就视为框架的 `BaseChatModel`。

现有 mock 按 DB／Server／Log／Knowledge 工具菜单识别角色，不能直接接文本比较。新能力必须有独立显式决策替身，不放宽 V1 菜单。

还发现一个必须适配的具体点：`LLMClient` 构造 SDK 时没有设置 `max_retries`；本地 `.venv/Lib/site-packages/openai/_constants.py` 的默认值为 2。PRD 要求新链路无自动重试，未来需在 V2 客户端显式设为 0，不能只限制图节点计数。此结论是源码阅读，不是实际重试实验。

### C2 · 工具执行

[ToolGateway](../../../../backend/src/core/tool_gateway.py)已有注册、参数最小校验、等待超时、脱敏与安全调用记录。新 Tool 仍继承 [Tool](../../../../backend/src/core/tool_registry.py)，并补强 typed 入参、材料归属与结果校验；不把现有顶层 schema 子集当完整安全契约。

### C3 · 事件、结果与产品事实

[现有端口](../../../../backend/src/application/contracts.py)只接 `query/service_id`，完成值是诊断摘要；[结果记录](../../../../backend/src/domain/records.py)与 API 结果含严重度／根因。缺少材料快照和非诊断交付，是实际 gap，不是换名即可解决。

Run 应用服务仍应是受理、状态、结果、事件的唯一 writer；LangGraph State 及候选框架 checkpoint 不另建产品事实源。

### C4 · 隔离、终态与控制

[现有执行器](../../../../backend/src/infrastructure/diagnosis/coordinator_executor.py)每 Run 新建内核；[ReAct 图](../../../../backend/src/core/react_graph.py)闭包操作可变 Agent 实例。新实现必须继续每 Run 独立 Agent／模型／Gateway／State，不能只设置 `thread_id` 后共用可变对象。

[P11 保护](../../../../backend/src/application/runtime_safety.py)要求有限流正常结束后才接纳唯一终止；异常、多终止、终止后输出失败关闭。现有取消 CAS、迟到隔离应复用；任何候选都不能自动补上全局 deadline、强制底层停止或崩溃恢复。

## 3. 候选一：现有 LangGraph 图机制与自有 Agent 接缝

- **模型／mock／usage**：当前源码支持已有装配；新决策与无重试策略需适配（C1）。
- **Gateway**：现有工具节点已实际调用 Gateway，是源码支持最强的复用点；新注册菜单／材料约束仍需适配（C2）。
- **结果／事件／安全投影**：需适配（C3），不能返回一段散文后从中提炼差异。
- **隔离／终态／超时／取消**：现有措施可参照（C4），新主 Agent 接入仍未运行验证。
- **依赖**：[requirements](../../../../backend/requirements.txt)已声明 `langgraph==1.2.9`；不需为了此候选新增框架包。本地有 StateGraph 源码，不代表当前环境全量测试已通过。
- **适用性建议**：在既有 LangGraph／BaseAgent／Gateway 上增加范围受限的主 Agent 图，不直接原样套用旧领域 ReAct 的自由文本终态。优先作为正式 Design 的拟议方案，最终激活仍受用户设计确认和实施门约束。

官方依据：[Graph API](https://docs.langchain.com/oss/python/langgraph/graph-api)允许显式状态和自定义节点；节点可接自有模型／工具代码。该文档不是版本锁定兼容证明。

## 4. 候选二：LangChain `create_agent`

- **模型／mock／usage**：官方 Agent 接口存在；自有 LLMClient／显式 mock／usage 接线均未验证，不能写“开箱可用”。
- **Gateway**：官方 `wrap_tool_call` 可包装工具调用；如何确保没有第二条原生 ToolNode 执行旁路，需要适配与负向测试。
- **结构化结果**：官方 `response_format`／Strategy 有机制支持；Provider 对它的支持、本项目出处校验与非诊断持久化仍需适配。
- **隔离／终态／控制／安全投影**：未验证；不替代应用层 CAS、P11 和公开投影。
- **依赖**：本仓库只声明 `langchain-core`／`langchain-openai`，未声明完整 `langchain` 包；不能把传递安装假定为可依赖生产接口。
- **建议**：保留候选。本首任务没有已证实必须通过它解决的缺口，不为比较而安装或迁移；不是认定它不安全或不可用。

官方依据：[Agents](https://docs.langchain.com/oss/python/langchain/agents)、[Tools](https://docs.langchain.com/oss/python/langchain/tools)、[Structured output](https://docs.langchain.com/oss/python/langchain/structured-output)。

## 5. 候选三：Deep Agents

- **能力面**：官方提供规划、文件系统、子 Agent 等现成构件；这些大多超出首闭环。可定制工具，不应误写成“无法关闭文件能力”。
- **模型／mock／usage、Gateway、typed 结果、安全投影、Run 隔离与终态控制**：与本仓库的兼容均未验证。
- **权限**：官方文件权限仅覆盖其内置文件工具，不自动治理自定义／MCP 工具；沙箱执行也不等于我们的审批授权。不能用框架 permissions 替换本项目 Gateway／策略。
- **依赖**：未声明 `deepagents`。文档中某些工具 allowlist 配置有最低版本要求，不适合在未锁版本时照抄。
- **建议**：首闭环不引入；将来委派／大任务确有需求时重新核查，不将这次暂不采用解释为否定后续多 Agent 方向。

官方依据：[概览](https://docs.langchain.com/oss/python/deepagents)、[定制](https://docs.langchain.com/oss/python/deepagents/customization)、[工具](https://docs.langchain.com/oss/python/deepagents/tools)、[权限](https://docs.langchain.com/oss/python/deepagents/permissions)。
