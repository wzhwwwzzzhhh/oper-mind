## 2. 首审：FAIL

结论：P0=0、P1=1、P2=2。以下为设计机制缺口，不是运行故障复现。

1. **P1 · 幂等兼容缺口**：新 fingerprint 没有明确与旧记录的区分，也没有明确 V2 rerun 包含来源 Run。统一重算可能破坏旧键重放，相同材料／不同来源可能误判。
2. **P2 · 模型失败边界不明确**：现有 LLMClient 将异常转为带 error 的字典，设计需明确 typed 调用失败与决策 JSON 失败的不同映射，不能只要求 JSON 校验。
3. **P2 · 迟到事件原子保护缺口**：只说同事务检查状态不够；原序号预留只按 run_id 更新，需原子状态谓词或行锁，避免检查与写入竞争。

Reviewer 核实的源码锚点：[旧指纹](../../../../backend/src/application/services.py:647)、[LLM 失败返回](../../../../backend/src/core/llm.py:101)、[序号预留](../../../../backend/src/infrastructure/persistence/repositories.py:406)。锚点是当前行为依据，不表示已经修过代码。

## 3. 作者修订

- Design §2.6：diagnosis 创建／rerun 保留旧公式及既有作用域，不改历史键；V2 使用版本化前像和既有列可容纳的 64 字符摘要；rerun 包含 source_run_id，kind 不同冲突。§4 补充旧键重放和不同来源验收语义。
- Design §2.5／§3：指定 MainAgentModelAdapter 先识别调用失败，再解析 JSON；typed 成功／失败和固定安全映射，不影响 legacy 行为。
- Design §2.6：普通事件用带 running 谓词的原子 UPDATE 预留序号，与取消 CAS 竞争同一 Run 行；终态事件只在对应 CAS 成功的同事务追加。
- §3 同时澄清共用凭据检测规则的修改接缝；没有放宽 Gateway 出站规则。

这些是文档修订，不是生产修复或测试结果。
