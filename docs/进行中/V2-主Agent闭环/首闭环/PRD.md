# V2 主 Agent 与文本比较能力闭环 · PRD

## 背景

V2 已在方向上确定以主 Agent 为基本执行单元，通过 Skill／Tool／Workflow／Capability 扩展；子 Agent 委派与独立主 Agent 协作是平行方向。用户已确认第一步准备计划，要求推进准备-1 盘点和准备-2 需求收敛。

[准备-1 盘点](../准备/现状与复用盘点.md)确认当前普通消息与诊断 Run 是两条链，关键词分流、诊断结果、角色 mock 与 Trace 词汇仍耦合运维。已有会话、Run、安全网关、P10 契约和 P11 执行保护可复用，但不等于本需求已经实现。

2026-10-15 用户明确选择：

- 首个验证任务：比较两段用户直接提供的文本，返回带出处的差异。
- 首版比较范围：原文字面差异的新增、删除、修改；不比较语义、立场或观点。

本 PRD 定义未来第二大步／骨架 B 的首个闭环，不是本轮准备-1/准备-2 的代码实施授权。`V2-B` 沿用骨架 B 标识，不新分配 P 阶段编号；全文及首版限额已于 2026-10-15 获用户确认，尚未进入代码实施。

**产品边界门**：本文件是用户已确认的 V2 新需求，尚未实施，不覆盖 V1 当前能力承诺。2026-10-15 用户已确认正式 Design 的事实源修订、旧入口兼容与切换范围；事实源区分 V1 已有能力与 V2 已确认／未启用方向。代码实施仍须工作包计划确认及开始门。

## 目标

1. 用户能在正式会话中获得主 Agent 的普通回答、明确追问，或调用一个已启用能力；不依赖运维关键词决定是否允许进入新链路。
2. 用户能比较本次明确提供的 A／B 两段文本，得到可逐项核对的字面差异、出处和简要解释。
3. 新闭环复用既有会话／Run 留痕和安全边界，支持确定性验证，不破坏 V1 已有入口和历史结果。

## 用户故事

- 作为项目使用者，我提供旧文本 A 和新文本 B，希望看到哪里新增、删除或修改，并定位原文，而不是只收到一段无法核对的总结。
- 作为使用者，我在同一会话提出不需要比较的普通问题时，希望主 Agent 能直接回答；材料不足时追问，不伪造比较完成。
- 作为维护者，我希望第一项新业务沿既有会话与运行机制接入，以便后续检验能力扩展成本，而不是另造一套聊天、运行或审计系统。

## 范围

### 做什么

- 正式会话内的主 Agent 默认交付：普通回答、材料追问、一次文本比较能力调用。
- 一个显式启用、范围固定的文本比较 Capability，声明版本、输入输出、资源范围与完成／失败条件。
- 本次输入快照、能力选择、受控操作、结果校验、最终交付和安全 Trace 的可追溯关联。
- 正式会话中的最小文本输入、差异结果与运行状态展示。
- 可检查的无差异／有差异结果，以及非法输入、模型不可用、输出不合法、取消和超时的诚实处理。
- 沿用已有模型配置、mock／real 表达、实际用量统计和安全密钥机制；新能力有自己的确定性样例。

### 不做什么（明确排除）

- 不做语义等价判断、观点分析、事实核查、专业审查、翻译、改写建议或商业业务承诺。
- 不做文件上传、附件解析、任意本地文件、URL 抓取、Web 检索、RAG、MCP 或真实服务接入。
- 不做子 Agent 委派、独立主 Agent 协作、通用任务分布式调度或完整恢复机制。
- 不做通用插件市场、任意技能目录、用户自定义代码／工具、热加载或整个 Agent 管理后台。
- 不更换模型凭据方案，不新增身份／租户／RBAC，不扩大已有 Tool／Connector／动作权限。
- 不做全局 Run deadline、同步线程强杀或“外部执行恰好一次”的保证；不把有限调用次数当成这些保证。
- 不建设逐 Run 成本账本或父子成本归因；已有聚合统计仍明确是实际用量与估算金额。
- 不整体重写前端、服务管理或模型管理；不删除 V1 运维实现和历史证据。

## 功能需求

### 1. 正式会话中的主 Agent 交付

- **输入**：用户消息、本会话必要上下文、本次显式材料和当前启用能力范围。
- **行为**：对需要语义理解的能力选择／是否追问，使用可校验的结构化模型决策；一个决策节点默认尝试一次模型调用，不表示整项任务只调用模型一次。程序校验格式、注册项、输入、资源范围与执行条件。固定流程、格式校验和原文字面对照可由确定性程序完成，不要求每一步调用模型。
- **输出**：普通回答、需要补充哪些材料的追问，或本次文本比较能力的可见交付。
- **限制**：V2 新链路不以正则、关键词、原文中的“SQL／查询／表”等词代替语义选择；无效模型决策不得偷偷转成数据库调查或任意工具调用。mock 使用显式测试决策，不冒充真实模型判断。

### 2. 显式材料与输入快照

- **输入**：明确区分的文本 A（旧）和文本 B（新），以及用户比较请求。
- **行为**：两份文本必须作为本次可识别材料接收。缺少一个材料与“显式提供空字符串”不同；前者追问，后者可比较。材料在本次 Run 内不可被后续消息、编辑或其他 Run 静默替换。
- **输出**：可与本次 Run、材料身份、处理规则版本关联的输入快照；不从其他会话、旧记忆、任意文件或外部服务自动补材料。
- **已确认的首版限额**：每份文本最多 2000 个 Unicode 码点、100 行；比较请求最多 200 个码点；最多返回 50 个连续差异块。超过输入上限在执行前明确拒绝；超过结果块上限安全失败并提示缩小范围，不提交截断的部分成功结果。
- **展示语义**：行号从 1 开始；统一 CRLF／CR／LF 为换行后建立可见行号，除此之外保留空格、空行、大小写和标点。不能静默 trim 后再声称原文一致。

### 3. 字面差异与出处

- **输入**：本次规范化 A／B 文本。
- **行为**：提供可复验的字面差异。新增只引用 B，删除只引用 A，修改引用双方；不存在对应内容的一侧明确标记“无对应片段”，不编造行号或引文。移动不要求单独识别，可表示为删除＋新增。
- **输出**：材料身份、比较结果（无差异／有差异）、差异块类型、双方适用的行范围与精确引文，以及简要解释。无需输出未改变的整份原文。
- **结果约束**：每个出处属于本次材料且在行范围内，引文与对应文本一致。重复行允许存在不同但一致的对齐方式；同一实现相同输入必须稳定，不能为迎合模型总结改变工具事实。模型解释不是结构化差异的来源，也不得添加没有差异记录支撑的“变化”。

### 4. 能力执行与结果接纳

- **输入**：主 Agent 提出的已注册能力／工具请求和本次材料引用。
- **行为**：能力中的模型可调用操作经过既有 ToolGateway；请求不得把其他文本重写成本次权威材料。只允许本次显式启用的纯文本操作，不装配数据库、网络、Shell 或文件读取能力。对照、状态与出处由后端校验后才能进入成功结果。
- **输出**：经过校验的能力结果，或固定、安全的失败／不可用说明。
- **已确认的首版调用上限**：每 Run 最多 4 次模型调用（包含决策和最终交付），最多 1 次文本比较工具执行，无自动重试。普通直答／追问不执行比较工具。超限安全终止，不借旧关键词规则继续执行；这不是通用持久化 Budget ledger。
- **失败语义**：无效工具请求、未知材料、结果结构或出处无效、模型失败和工具超时均不得包装成能力成功；追问是一次合法对话交付，但不记成能力已执行／已完成。

### 5. Run、并发、取消与重放

- **输入**：已受理任务、幂等重放、两个并发任务、取消或迟到返回。
- **行为**：延续正式会话与 Run 的归属和唯一事实写入责任。已受理的每个 Run 有自己的材料与结果；同会话／不同会话任务并发时，不得混用输入、引用、事件或取消状态。资源不足时可在受理前明确拒绝，不能声称运行过。
- **输出**：合法受理和重放关联、唯一 Run 终态与正确归属的结果／安全失败。
- **约束**：以已保存的输入重放，不从当前 UI 草稿或其他最新消息重新取材料。取消胜出后迟到结果不得补写成功、助手结果、第二终态或动作提案。停止等待不等于底层已停止；不足以证明时明确未知，不承诺进程崩溃后自动恢复。

### 6. 会话展示与安全反馈

- **输入**：任务状态、安全事件和已校验结果。
- **行为**：用户在正式会话内区分 A／B 输入，查看差异及出处，并能看到运行、取消、失败、不可用和未执行。新结果不显示无意义的诊断严重度、根因或动作审批按钮。
- **输出**：可核对的结果区及安全 Trace；刷新／重连后仍能恢复已经提交的任务状态和结果，不依赖浏览器内存中的孤立对象。
- **限制**：Trace 只含允许的角色／阶段／状态／耗时／工具类别／脱敏摘要，不含原文、逐字差异、Prompt、CoT、原始工具输出、异常或凭据。用户显式提供的非敏感原文引用只能出现在对应输入／结果区域，不进入日志、用量记录或审计摘要。

## 非功能需求

- **安全**：原文是不可信数据，不能因其中的指令扩大工具范围。命中凭据接纳规则的内容应在落库、记录日志或送入模型前拒绝接纳，提示用户去除。规则范围及合成拒绝样例需在 Design 明确，至少沿用已有密钥格式、带口令连接串和凭据赋值的识别范围；不宣称能识别所有敏感信息。不得提交或记录真实凭据。
- **一致性**：结果中的原文、行号、能力版本与 Run 输入一致；文本级事实不能从模型散文提炼。没有差异与比较失败不能使用同一种成功表达。
- **确定性**：使用固定材料和模型替身能复验差异、引用、调用次数与失败行为；mock 不访问真实模型／服务，不通过放宽 V1 工具白名单来适配。
- **可靠性**：保留 P11 对有限执行流的唯一终止与安全失败保证；没有增加全局 deadline 前不得承诺可以终止任意阻塞流。
- **性能与边界**：遵守本需求的材料／结果／调用限额；具体工具等待和单次模型超时由 Design 明确并用确定性测试验证，不以未经测量的“快速”作为 AC。
- **兼容性**：V1 旧会话、服务调查、模型配置、取消／重跑和历史诊断结果可继续识别；保留旧功能不表示新链路可以继续依赖关键词分流。
- **可访问性**：A／B 标签、行号和差异类型有文字表达，不仅依靠颜色。

## 数据与接口影响

- **数据**：需要关联本次材料快照、材料／处理版本、能力版本及非诊断结果；继续由正式会话与 Run 体系承载，不建立第二套可写业务事实源。现有字段能否安全承载、是否需要迁移，由正式 Design 明确；本 PRD 不假定“改名即可复用”或“肯定无需迁移”。
- **接口**：现有 query 及诊断结果不能被当作已支持本需求。需要表达显式两份材料和可校验差异结果；具体路由／字段／版本与兼容方式由 Design 决定，不在本 PRD 预先发布新 API。任何 REST／OpenAPI／SSE 变化必须同步前后端类型与测试。
- **前端**：只改首条闭环涉及的会话输入、结果、安全过程及错误反馈；不要求先建设完整能力管理页面。
- **模型**：沿用已确认的 Provider／模式／参数与密钥管理；用量统计继续只记录实际返回信息。mock 或缺失 usage 不造数，不承诺尚未建设的逐 Run 成本归因。
- **本轮准备-1/准备-2 实际影响**：仅文档。没有生产、数据、API、依赖或外部访问变化。

## 验收标准

以下全部是未来实施验收，**本次未执行、未勾选**：

- [ ] AC1：当普通问题不需要文本比较时，主 Agent 应直接交付回答，不调用比较工具或任何运维工具。
- [ ] AC2：当用户要求比较却未提供一份材料时，应明确追问缺少 A／B 哪份，不制造原文、差异或“比较成功”。
- [ ] AC3：当两份材料已提供且文本含“数据库／SQL／查询”等字样时，应仍按用户比较目标选择已注册文本能力，不因字面词汇进入 DB 调查。
- [ ] AC4：当模型决策结构无效、选择未启用能力或输出工具请求不在允许范围时，应拒绝执行且不靠关键词／正则兜底；工具执行次数为零。
- [ ] AC5：当 A 与 B 一致（包括双方显式为空）时，应得到“无差异”、零差异块和正确材料归属，而不是不可用或未经说明的空结果。
- [ ] AC6：当 B 比 A 多出一段原文时，应提供新增块及 B 的有效行范围／精确引文，A 侧明确无对应片段；删除场景对称。
- [ ] AC7：当唯一一行从“超时=3秒”变为“超时=5秒”时，应显示修改及双方对应行／引文；解释不得把数字或单位改写成其他值。
- [ ] AC8：当仅换行编码不同而其他字符相同时，应无差异；当空格、空行、大小写或标点改变时，应按已说明的字面规则反映差异；重复行不产生越界或伪造出处。
- [ ] AC9：当任一文本超过 2000 个码点／100 行、请求超过 200 个码点时，应在执行前明确拒绝；当实际差异超过 50 块时，应安全失败并提示缩小范围，不提交部分成功结果。
- [ ] AC10：当工具请求使用其他 Run 的材料、结果含错误材料身份、越界行号或与原文不符的引文时，应在接纳前拒绝，不保存或展示完整能力成功结果。
- [ ] AC11：当模型不可用、工具失败／超时、结果不合法或调用上限耗尽时，应显示相应安全失败／不可用且无自动重试；不得切换为未标识的 mock 成功。
- [ ] AC12：当完成一次比较时，应不超过 4 次模型调用和 1 次比较工具执行；普通回答与追问的工具执行次数应为零。
- [ ] AC13：当固定模型替身与固定材料重复运行时，应得到一致的关键差异、归属、状态和调用计数；真实调用缺失 usage 与 mock 不得产生伪造用量。
- [ ] AC14：当同会话或不同会话两个已受理 Run 使用不同 A／B 材料并受控交错执行时，两者结果、引用、事件和取消应独立；同键同输入重放只对应原受理结果，不重复消息／工具执行，换输入同键应冲突。
- [ ] AC15：当取消与成功竞争且取消已先提交时，迟到返回不得覆盖终态、补写结果／成功消息、生成提案或追加第二终态；无法证明底层停止时不得宣称已停止。
- [ ] AC16：当 Runtime 有零／多终止、终止后输出或意外异常时，应保持 P11 的安全失败与唯一终态保证，不伪装已解决无限／阻塞执行的 deadline gap。
- [ ] AC17：当原文含“忽略限制、访问外部、执行命令”等指令时，应只作为比较材料，不产生文件／网络／数据库／Shell 访问；命中 Design 已明确凭据接纳规则的合成样例应在落库／模型调用前被拒绝。
- [ ] AC18：当查看 Trace、日志、审计摘要和用量记录时，不得包含两份原文、逐字差异、Prompt、CoT、原始工具输出、异常或凭据；对应结果区只展示本次允许的原文引用。
- [ ] AC19：当刷新／重连或查看历史结果时，应恢复本次已提交状态与结果，正确区分材料追问、无差异、有差异、失败／取消；不将文本结果套成诊断根因或动作提案。
- [ ] AC20：当回归 V1 会话管理、服务调查、既有模型设置、取消／重跑、历史诊断结果和固定动作安全边界时，应保持已确认行为；旧接口与新能力的兼容／切换必须符合另行确认的 Design。

## 边界与约束

- **既有保证**：保留 P10 正交契约、P11 唯一终止／安全失败／迟到隔离和原有 ToolGateway 接缝；它们不等于已存在通用权限、业务 Capability 或全局预算系统。
- **默认资源范围**：只有当前用户显式提供且通过接纳检查的 A／B 文本；无隐式磁盘、网络、其他会话或旧记忆来源。
- **智能与执行分离**：模型理解请求与解释结果；结构化输出、资源归属、原文出处和工具资格由后端校验。确定性字面对照不是用正则替代语义路由。
- **降级**：材料不足追问；未启用、不支持、模型／工具失败与超限明确表达。不将“未访问业务服务”误写成“real 模式没有模型调用”。
- **兼容**：旧数据保留；框架 State／checkpoint 不是 Run 成功或结果真实性证明。前端不得绕过后端直连外部资源。
- **真实访问**：本轮只写文档；未来测试默认离线。任何实际模型／服务验证仍需当次授权、目标边界和脱敏方式。
- **实施门**：PRD 用户确认 → 关联 Issue → 正式 Design → 独立 Review → 用户确认 → 正式 Workpack。首任务选择和准备计划确认不等于本 PRD／技术设计已获批准。
